**审核台 · 学习队列与审核标签（机制备忘）**

- **学习队列（稍后采纳）**：律师在审核台完成「通过 / 退回」等动作时，可把本次结论与备注**先入队**（`workspace/learning/suggestions.json`），不立刻改写记忆。之后在桌面或 adopt 流程里**显式采纳**后，才会按策略写回助手档案、Playbook 等。作用是避免模型或单次审核**自动覆盖**长期偏好，把「学」变成**可复核的两步**。
- **审核标签（可选）**：一组固定枚举（见下），用来**结构化**描述草稿问题。带标签的审核会驱动「质量学习」：例如与 Playbook 更新、记忆采纳建议等管道联动（具体以当前引擎/桌面版本为准）。**不选标签也可以审核**；选了则便于统计、检索和以后自动归纳规律。

**当前支持的审核标签**（与 `src/lawmind/review-labels.ts` 中 `ALL_REVIEW_LABELS` 一致；API 仍兼容旧版英文 slug，会规范为下列中文）

| 标签         | 含义（简述）                 |
| ------------ | ---------------------------- |
| 语气过强     | 宜收敛表述                   |
| 语气过弱     | 宜加强立场或结论清晰度       |
| 引用不完整   | 缺页码、条款定位或无法回溯   |
| 引用有误     | 与权威来源不一致             |
| 争点遗漏     | 应讨论的法律/事实要点未覆盖  |
| 争点过度论证 | 次要争点篇幅过多或跑题       |
| 事实顺序不当 | 叙述顺序影响理解或说服力     |
| 事实不准确   | 事实表述有误                 |
| 风险偏高     | 风险渲染过度                 |
| 风险偏低     | 风险警示不足                 |
| 风险未标注   | 应显式标注的风险未标出       |
| 受众定位不当 | 客户稿/内部稿等 framing 混淆 |
| 模板不匹配   | 与期望结构或任务类型不符     |
| 质量范例     | 正向样本，可晋升黄金路径     |
