# Skill · 接案与范围基线

来源方法学：`legalopsconsulting/lpm-skills`（Apache-2.0）的接案→范围→预算→期限→状态报告闭环；本文件为独立重写，不复制其文案。

## 一、接案清单

接案或新事项开始时，先列清八项；缺的写【待补充】，不要用推测填满：

1. **委托人**：名称、联系人、送达方式、谁有权指示。
2. **对方 / 关联方**：名称、关系、是否有利益冲突。
3. **事项**：要解决什么问题；是咨询、审查、起草、诉讼还是交易。
4. **目标**：委托人希望达到的结果；不能承诺结果，只写目标。
5. **交付物**：意见书、合同、起诉状、时间轴、审查表等；格式与份数。
6. **期限**：关键日期、法院/监管期限、委托人期望时间。
7. **预算与计费**：计费方式、预算上限、哪些工作不含在内。
8. **授权**：谁签批、谁可以对外发送、哪些动作必须事先确认。

冲突检索与伦理墙按既有收案闸门走；本 Skill 不替代冲突扫描，也不把未完成的检索写成已通过。

## 二、范围基线

在正式开工前写一段「范围基线」：

- **包含**：本次要做的事，按交付物列。
- **不包含**：明确不做的事（例如不代客户谈判、不处理关联案件、不出庭）。
- **假设**：依赖委托人提供的材料与时间；假设不成立时怎么办。
- **变更规则**：范围变化必须走变更登记，不默认吸收。

范围基线是后面周报与预算对照的基准；没有基线就不要在周报里写「超预算」。

## 三、范围变更四要素

每次变更一行，缺一不可：

1. 变更内容：从什么变成什么。
2. 触发：谁在什么时候提出。
3. 对预算与期限的影响：增加多少工作量、是否影响关键期限；说不清写【待估】。
4. 状态：已确认 / 待客户确认 / 我方内部判断。

范围未变也要写「本期无范围变更」。不要自行调整费率、报价或承诺新的完成时间；这些要律师确认。

## 四、与其它 Skill 的分工

- `matter-status-scope-budget`：周报里的范围变更与预算/工时对照。
- `matter-budget-lite`：预算骨架与计费口径。
- `matter-from-materials`：从材料里抽当事人、案由、日期。
- 本 Skill：接案时的范围基线与变更登记模板；不替代周报，也不替代冲突扫描。

## 交件口径

接案备忘是内部管理件；客户版摘要按交办另出。金额与期限能算则调用 `calculate`，缺台账/流水标缺口，不编数字。下一步必须带日期；缺日期标【待补日期】。
