# Skill · 诉讼时间轴（两阶段）

时间轴是最容易被律师返工的交付物：日期或事实错一条，整张图都要重做。
因此固定两阶段：**先预览确认，后出正式件**。

来源方法学：中国诉讼可视化实践（HoriZon 争议解决簇 / Greater-China-Legal 场景包的
「预览 → 确认 → 正式图」流程），Apache-2.0 方法吸收；本文件为独立重写。

## 阶段一：预览（默认动作）

先把材料里的事实抽成**逐条可改**的草案，而不是直接出图。

每条至少三列：日期、事实、来源。要求：

- **日期**：能核到出处的才写具体日；只有「大约/月底/签约后」的写原话，不折算成具体日。
- **事实**：一句话，用材料里的动作和主体，不写成法律评价（「构成违约」是评价，放意见里）。
- **来源**：材料文件名或出处（`cases/<id>/materials/…` 或当事人陈述）。缺来源标【待补来源】。
- **冲突两说并列**：两份材料日期不一致时并列两行并标【冲突】，不自行择一。

预览按对话正文输出（markdown 表或按日期线性列出），让律师当场增删改。
预览阶段**不**调用 `render_document` 出正式文件。

## 阶段二：确认后才出正式件

只有律师明确确认（或改完确认）后才出正式时间轴。缺日期/来源的行在正式件里保留并标缺口，
不得为了图好看删除或补造。

正式件要求：

- 按时间升序；同日多事按材料顺序，不臆造先后。
- 每条仍保留来源列；来源缺的标【待补来源】。
- 时间轴是事实梳理，不是争点论证；争点放意见/要素部分。

## 与既有能力的关系

- 纯补档案（把传票/谈话写在案）走 `apply_legal_events`，不必出时间轴。
- 交办明确要「时间轴/年表/大事记」时走本 Skill；只说「理一理事实」时可先给预览。
- 缺材料时先出已有部分的预览 + 【待补】清单，不要空转等材料。

## 不做

- 不把推断日期写成确定日期。
- 不在预览阶段出正式 Word（避免律师还没看就产生一个「已出稿」）。
- 不用时间轴替代要件事实勾陈或证据目录。
