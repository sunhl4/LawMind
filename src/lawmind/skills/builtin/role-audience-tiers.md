# Skill · 角色档位与对内对外稿

来源方法学：`vivy-yi/Greater-China-Legal`（Apache-2.0）的角色档位与对内/对外口径；本文件为独立重写，不复制其文案。

## 先定受众

写之前先回答一句：**这份稿给谁看**。受众不同，能写的东西不同：

| 受众            | 可以写                               | 不要写                             |
| --------------- | ------------------------------------ | ---------------------------------- |
| 委托方 / 客户   | 事实、风险、选项、成本、下一步       | 胜诉承诺、内部代号、未经核实的结论 |
| 对方 / 对方律师 | 事实主张、法律依据、保留权利         | 内部评估、底线、策略推演           |
| 法院 / 仲裁机构 | 诉讼请求、事实与理由、证据、法律依据 | 情绪化表达、内部策略、未举证的事实 |
| 内部 / 团队     | 推测、待核实、决策依据、风险分级     | 把内部推测直接搬到对外稿           |
| 监管 / 公开     | 经签发的确定表述、依据               | 未签发结论、内部讨论               |

交办没写受众时，默认按**内部稿**处理，并在文首标「内部稿 · 供审核」。不要默认成对外可签发。

## 对内稿与对外稿的差别

- 对内稿可以有「推测」「待核实」「倾向意见」，但必须标明；不能把推测写成事实。
- 对外稿只写有依据的结论；没有依据的写缺口或【待核实】，不写成确定判断。
- 对外稿不承诺结果（胜诉、审批通过、回款），不写「保证」「一定」。
- 对外稿不使用内部代号、缩写、案卷编号或团队黑话。
- 同一份文书里的当事人称谓要一致；不要一会儿「甲方」一会儿「委托方」。

## 交件前五问

1. 这份稿的受众是谁？文首/称谓是否对得上？
2. 每个结论有没有依据？没有依据的有没有标【待核实】？
3. 有没有承诺结果、保证通过、保证回款？
4. 有没有把内部评估、底线、策略写进对外稿？
5. 需要签批才能外发的，是否仍停在待发信/待拍板？

五问有一项答不上来，就改成内部稿或标缺口，不要直接交对外件。

## 与既有路径的关系

- 函件、诉讼文书、意见书各自有体裁与栏目；本 Skill 只管受众与口径，不替代体裁 Skill。
- 合同审查的受众是委托方/对方纸；审查意见与修订稿分别按上述口径写。
- 邮件短路径与指定 Word 改稿仍按原工具表；本 Skill 不改变工具表，也不新增确认步骤。
