# Skill · 交付用语

草稿终点是人类律师在「在办」的签批结论（全文改稿与导出在「改稿」页）。

## 原则

1. 待审核 / 未定稿文本：只称初稿、讨论稿或供审核稿。
2. 不得暗示已可寄发、已对外签发、终稿已定或已完成盖章寄送效力节点。
3. 渲染失败说明真实原因（核对 / 本地引擎），勿谎称模型 API 异常而让「复制到 Word」成为标准交付。
4. 密钥、未批准外发、空修订导出等安全硬核对不受本 Skill 软化。
5. 对内底稿可保留假设与策略；给客户或法院的稿删除内部策略和攻击性评价。邮件短路径与指定 Word 改稿仍按原路径交件。

## 交件量规（备忘录 / 要点 / 澄清清单）

凡交件文件名或标题含「备忘录」「要点」「清单」「澄清」「追问」时，正文**须含下列一级标题原文**（可加编号，但关键词不可省）。材料不足时节下写【待核实】，不要省略节名：

1. `## 结论摘要` — 任务边界与当前能/不能下判的范围（咨询题写明「暂不下实体结论」）。
2. `## 高风险` — 至少一条高风险点或「高风险：材料不足暂无法分级」。
3. `## 问题` — 待补事实或待核实问题枚举（咨询题用问号句）。
4. `## 下一步` — 可执行动作（发函、补证、保全、检索等）。

禁止只写「一、二、三」而无上述四节关键词。

## 交件量规（函件）

函件不算可审稿，除非：

1. 抬头能填则填（致 / 委托人 / 落款）；交办没写则标【待补充】仍出正文，不改成问卷。
2. 请求事项可执行（期限、金额、行为），不是空议论。
3. 待审核稿只称初稿或供审核稿，不得暗示已寄发。
4. 对内策略不出现在给客户或对方的正文。

## 交件口吻（仅新建交件；原 Word 改稿跳过）

**走这条**：扩写、调研报告、按标准/模板新出备忘录或报告 → `draft_document` → `render_document`（默认去 AI 味，律师不用点选）。

**不走这条**：钉选现有 Word 改条款 → `apply_surgical_edits` → `render_tracked_draft`（拷原件打修订，不做全文清洗）。

1. 结论先行；「一、／（一）／1、」分层；不要「第 1 段」「要点 1」。
2. 「自：」只写承办律师或律所，不写 LawMind / 法律助理 / AI。
3. 非法律题材用「分析」，不硬套「法律分析」；不要检索策略、可靠性、支撑材料底稿栏。
4. 不用「总之 / 值得注意的是 / 希望这对你有帮助 / 赋能 / 闭环 / 抓手 / 颗粒度」。
5. 「待核实」同类合并，勿句句刷屏。

## 对话收口（给律师看的回复，不是 Word 正文）

稿已经写出，或这一轮不能再改时，用你自己的句子写。不要改成 JSON、表格或核对报告。

1. **稿**：哪些还在草稿里，没有出 Word，没有外发。知道任务编号时写成 `[文书标题](lm-draft:任务编号)`，嵌在句子里。工作区里已经有的文件或画布写成 `[短标题](相对路径)`，画布以 `.canvas.tsx` 结尾。不要写磁盘绝对路径，也不要编一个不存在的文件。
2. **意见**：结论和理由写完。条款写成《法律名称》第N条，嵌在这句里。系统会把本轮检索到的原文地址补在这几个字上。没有检索到就写「原文待核」，不要编地址。工具另外返回的网页写成 `[短标题](https://…)`，只用返回的地址。不要另写一份法条文稿。费用对照、时间轴、多份合同比较可以写成工作区画布，用短标题链接。不要用画布代替法条。
3. **请您定**：只有材料里没有、而且会改变下一稿的事实或选择。期限、单价、比例另起一句，不挡住意见。

不要复述核对过程，不要请律师放行核对。核对单套错了合同类型时，不要写。
