# Skill 分析结果再审：开箱、质量、稳态

> 截止：2026-09-08  
> 输入：`docs/LAWMIND-EXTERNAL-LEGAL-CAPABILITY-CATALOG.md`、`docs/LAWMIND-CANONICAL-LEGAL-SKILLS.md`、`docs/LAWMIND-SKILL-LOGIC-REQUIREMENTS.md`  
> 打分尺：只看下面三条。不把确认页、来源栏、审批、审计、律师可见“闸门”当产品价值。  
> 本文件覆盖上一轮 P0 排序。六层结构、功能全集、许可证判断仍然有效；改的是**哪些技巧进主路径、哪些只留在引擎内部、哪些丢掉**。

## 三条尺

1. **上手简单、开箱即用**：律师装上就能干日常活。功能按律师真实工作配齐，而不是先面试、先选档位、先过审核。
2. **交付质量**：在已配齐的功能上把模型能力用满，交件达到能顶一稿律师活的水准——能改、能算、能写、能检索，而不是待填写摘要。
3. **每次都稳**：同样交办几乎总能达到第 2 条的质量。靠同一条流水线、确定性执行、封闭分类和机器自检，而不是靠律师再审一遍。

取长补短：公开 Skill 里，**把模型从聊天推进到成套交付**的部分留下；**把律师按进确认循环才算完成**的部分丢掉或收到引擎内部。

## 0. 上一轮排错了什么

上一轮把厚包里最显眼的“硬阻塞、确认路由、出稿审查、来源边界、利益冲突 STOP”当成了精华。那些技巧服务的是**律所插件的合规外观**，不是这三条。

| 上一轮当 P0                 | 实际作用                      | 按三条尺                    |
| --------------------------- | ----------------------------- | --------------------------- |
| 占位符未填则停止实质工作    | 逼律师先做 15 分钟 cold-start | 违反第 1 条                 |
| 立场/目的/口径三问阻塞      | 没答完不出活                  | 违反第 1 条；有材料时应推断 |
| `confirm_routing`           | 让律师给路由签字              | 违反第 1 条                 |
| 回复里打出闸门名、来源边界  | 让过程看起来可审              | 不提高交件质量              |
| 利益冲突未跑则禁止建档      | 律所风控                      | 个人律师开箱路径用不上      |
| 律师确认后才算正式图/正式稿 | 把完成定义交给审批            | 违反第 1、2 条              |
| 七类成果让用户先分类        | 多一次选择                    | 应由系统按任务自定时        |

应留下、但要改挂靠点的：

- **计划 JSON → 脚本改 Word**：这是质量（真红线）和稳态（同一次计划同一次落改），不是审核。
- **完整读取、法规检索、劳动计算引擎**：这是把活干对，不是信任仪式。
- **封闭 12 类合同、诉讼按阶段**：让模型少漂，是稳态。
- **要素提取、证据链、命题矩阵**：这是替代律师脑力劳动的方法，不是核对清单。

`GOALS.md` 里已有的原则仍然适用：只有空交付、安全、授权、不可逆外写才硬拦。不得用禁止清单冒充质量。

### 抬第 1 条时要丢掉或内化

Cold-start 停工、三问阻塞、路由确认、角色五档（业务部门/对方律师看不见底稿）、飞书/日历写入必须先确认、身份面试、冲突检索作为建档前提。这些可以进**可选设置**，不准挡 Day-1。

### 抬第 2 条（质量，替代律师干活）——取

质量 = 交件本身像律师交的，不是“请律师审核”。

| 技巧                                      | 来源                                | 为什么能替代                                                           |
| ----------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------- |
| 宏观–中观–微观 + 四步                     | copilot / 张海燕结构                | 先交易结构后条款，避免只挑一句违约金。这是审合同的脑力                 |
| 推荐措辞 + 落地方式                       | copilot                             | 律师活是改出来，不是列风险形容词                                       |
| 促进交易                                  | copilot                             | 机械否定不是好律师；要给可谈判改法                                     |
| 要素：生活语言 → 要件事实                 | GCL 原子                            | 客户说“他一直拖着不还”时，律师会写成履行期限届满未履行。这是替代的核心 |
| 证据论证链                                | GCL                                 | 起诉状/证据目录按主张–要件–证据填，缺的标在交件里当工作结果            |
| 规范效力                                  | GCL / 潘睿法宝 / Golden2002         | 引用废止合同法会让交件直接不可用。检索是质量，不是可追溯卖点           |
| 命题矩阵、正反类案、小样本试检            | 元典中间层                          | 检索报告有用，是因为查询不是随机关键词                                 |
| 责任上限四个位置、破局条款                | Anthropic playbook                  | 有档案时质量更高；**无档案时用默认四位置仍要审完**，不要停             |
| N/N+1/2N、加班、期限                      | 潘睿劳动；期限日历                  | 金额必须规则引擎算，模型填槽。口算不能替代律师                         |
| 最短锚定红线                              | LawMind 已有；潘睿/copilot 计划脚本 | 真 Word 修订才是合同审查的交付；25/2049 的 Skill 能做到，这是差异      |
| 线性文书走语义 HTML；要素起诉状走母版克隆 | 潘睿导出                            | 起诉状表格被 pandoc 打烂 = 质量失败                                    |
| 律师版精炼、实务要点                      | Golden2002 律师档                   | 不要普法长文。默认就按主办律师交件写                                   |

缺关键事实时的正确质量行为：仍产出已能做的部分（风险点、改法、已读条款），在交件里写清缺什么、该缺如何影响结论。这是律师备忘的写法。**不要**把“暂停、只问问题、不给风险分级”当成质量。上一轮 3.1 在这一点上排反了。

### 抬第 3 条（每次同质量）——取

稳态靠机器重复同一条路径，不靠人把关。

| 技巧                          | 来源                        | 稳态机制                                                 |
| ----------------------------- | --------------------------- | -------------------------------------------------------- |
| 瘦 SKILL + 按需 `references/` | 潘睿瘦身、code-lawyer       | 上下文小，模型少漂                                       |
| 封闭合同 12 类、诉讼阶段表    | copilot、潘睿民事 S0–S16    | 同类任务走同一路由，不每次发明类型                       |
| 模型只写计划，脚本落盘        | 各厚包 L4                   | 同一次 `find/replace` 几乎总得到同一修订                 |
| 红线 XML 自检失败则收窄重试   | 潘睿 QA + LawMind span gate | 律师看不见“审查未通过”；系统自己再跑                     |
| 计算走引擎                    | 劳动包                      | 同一流水同一公式                                         |
| 自动修正只动格式              | 潘睿出稿                    | 稳态修复排版，不让模型改金额                             |
| 默认 playbook 固定且标明      | Anthropic `[DEFAULT]`       | 没自定义时每次同一套标准；改档案后才换口径，避免静默漂移 |

引擎内部可以保留状态机（读失败、检索失败、命中失败 → 换方法再跑）。**不要**做成律师可见的 PASS/NEEDS_USER_CONFIRMATION 审核台。

## 2. 开箱能力包（第 1 条：配齐）

按 Skill 密度和律师每天是否用，而不是按“有没有审核”。LawMind 现有 6 项只覆盖左上角。

**开箱就要能用（律师打开软件就能交办）**

| 能力         | 为何必须在箱内          | 质量怎么做满                               | 稳态怎么做                         |
| ------------ | ----------------------- | ------------------------------------------ | ---------------------------------- |
| 快问/分析    | 提问型 Skill 最多       | 要素提取 + 要件对应 + 能检索则检索         | 固定输出骨架：结论、依据、缺口     |
| 合同审查     | 重复实现最多            | 三层四步 + 推荐措辞 + 红线+意见成套        | 12 类路由 + 计划脚本 + 最短锚定    |
| 合同起草     | 输出里合同稿 430        | 路由卡 + 条款骨架 + 待补事实写在稿里       | 封闭类型 + 条款库抽取              |
| 检索备忘     | 所有厚包都当核心步骤    | 命题矩阵 + 现行法条 + 正反类案             | 先试检再扩；无库仍给可执行查询方案 |
| 函件         | 已有                    | 要件和请求写全，缺收件人在稿纸标待补仍出稿 | 模板                               |
| 诉讼文书     | 诉讼 Skill 第三多       | 阶段默认“按材料推断”；证据链填进文书       | 母版克隆或语义 HTML                |
| 劳动计算     | 中文 HQ 里劳动最多      | 引擎出金额和公式                           | 同一规则文件                       |
| 时间轴       | 诉讼厚包标配            | 按材料抽日期；立场由甲乙/原被告推断        | 去重规则固定                       |
| 从材料建事项 | `new-case` / LPM 预整理 | 自动分目录、抽当事人案由                   | 预设目录，不空建                   |

**箱内有、但不挡主路径（设置或第二次才需要）**

刑事/破产全阶段、并购数据知产场景包、账单/发票/法院短信、飞书、LPM 预算、自定义 playbook。这些是配齐的后半段，不是开箱面试题。

## 3. 各规范源：长处留下、短处丢掉

### Anthropic 商业法律

- 留：默认可运行的条款政策结构（标准/回退/永不、四位置上限、破局条款）；整组能力一个工作台；快问对照表；从已签合同**学习**口径（提高以后质量）。
- 丢：没配完就拒绝干活；路由要律师确认；privilege/destination 当主流程；集成没探测就不审查合同。
- 补：LawMind 开箱带中国执业默认政策，律师可改。改了只影响之后任务。

### 潘睿总控

- 留：总控自动选子能力（律师无感）；读全文再下笔；法条现查；红线计划脚本；劳动计算；文书导出链路；渐进披露。
- 丢：把飞书、确认记录、闸门词、七类成果分类做成完成定义。LawMind 完成 = 交件能打开、能用、该算的算对、该改的改上。
- 补：内部失败自动换路径（OCR、换检索、收窄 find），不要把失败说明书当作主界面。

### copilot（只借结构）

- 留：三层四步、12 类、计划落 Word、推荐措辞、促进交易、缺事实时在**交件中**写结论待定。
- 丢：开跑前三问；禁止从合同主体推断立场。有甲方/乙方/委托邮件就能推断；推断错了律师改立场再出一版——这比先问三句更符合第 1 条，也更接近真律师拿到卷宗就先看。

### Greater-China 原子

- 留：要素、效力、证据链、解释方法，做成引擎阶段，让模型按律师方式想。
- 丢：五档角色权限、工作底稿保密头、`[verify]` 当界面徽章。

### LPM / new-case

- 留：把邮件堆整理成事项 brief；预设目录。
- 丢：冲突未清不能建档；一切必须先出 docx 才能在对话里看。

### Golden2002 / 元典

- 留：立法法层级、律师版报告、查询矩阵、正反检索。
- 丢：先问普通人/学生/法官。

### LawMind 已有

- 留：最短锚定、Soft Ask、邮件合同短路径、检索后再写备忘。这些本来就更贴近三条尺。
- 补：能力包从 6 项扩到开箱表；计划层接到 surgical edit；劳动引擎；要素阶段；默认政策对象。
- 不要加：律师可见审核台、来源边界主界面、更长的禁止清单。

## 4. 重排后的主路径（合同审查为例）

上一轮：问立场 → 停 → 分类成果 → 确认路由 → 审 → 计划 → 改 → 出稿审查 → 律师确认。

按三条尺：

```
打开软件（已有默认政策）
  → 丢进合同或一句话
  → 系统推断类型和立场（写在交件头，可改）
  → 读全文（内部做；读失败换 OCR/再读，不把“请确认已读”抛给律师）
  → 宏观/中观/微观审完
  → 能检索则核现行法条（核失败在交件里写“此条未查到原文”，仍给其余改法）
  → 计划 JSON → 最短锚定落红线 → 机器自检，失败则收窄重试
  → 一次交出：修订稿 + 意见（含推荐措辞、缺口、公式或依据）
```

律师从打开到拿到交件，中间没有审核页。质量来自分层和脚本；稳态来自同一路由和重试。

快问更短：问题 → 要素 → 能检索则检索 → 直接答。不要“这需要人看”除非模型真的做不了（超出现有能力包）。做不了时应说缺哪项能力，而不是装成审核升级。

## 5. 开发顺序（覆盖上一轮 P0）

### P0 — 开箱就能交件，且交件是真活

1. **默认能力包**：在现有 6 项上加上快问分析、合同起草、劳动计算、时间轴、从材料建事项。开箱可见，不必配置。
2. **默认执业政策**：内置中国律师常用默认（可改）。无自定义也跑完审查/起草/检索。
3. **推断优先**：类型、立场、阶段从材料来；写在交件头。
4. **质量内核接到现有路径**：要素提取 → 现有争点图；合同三层四步 → 现有 surgical edit；检索命题矩阵 → 现有 `research.memo`。
5. **计划脚本 + 机器重试**：命中失败内部收窄，不弹审核。

### P1 — 把质量拉到能替代

6. 推荐措辞和成套红线+意见（文字意见不算合同审查完成）。
7. 劳动/期限规则引擎。
8. 起诉状母版克隆或等价不打表。
9. 正反类案与现行法条进入备忘正文。
10. 可选 playbook：律师改了默认政策，以后任务跟新口径（稳态：改之前旧任务不重算，除非律师点重跑）。

### P2 — 配齐长尾

11. 刑事/破产阶段包、知产目录、发票/短信、LPM 预算。全部仍然是打开就能用的功能，不是新的确认流。

### 不做

- 开箱面试、确认路由、律师可见出稿审批、来源/审计当卖点、预装数千条 SKILL.md、用更长禁止清单代替分层审查和脚本。

## 6. 对前三份分析文档怎么用

- 普查、去重、功能全集、六层、许可证：**继续当事实来源**。
- 逻辑复审里的实现细节（计划字段、12 类、要素九类、查询矩阵）：**当引擎设计**，不要当律师 UI。
- 逻辑复审第六节 P0（执业档案停工、总控闸门词、出稿状态机给用户）：**作废**，以本文第五节为准。
