## 0. 目标与非目标

### 0.1 一句话目标

律师打开 LawMind，默认进入 **对话式 Agent 窗**（能打字、贴材料、处理当前澄清）；**在办**是常驻状态层与可进的总览（并行/卡点时才需要）；**文书台**从「有待审稿」场景进入；**不做 IDE/Agent 模式开关**。

### 0.2 必须达成的四条（修订后）

1. **默认入口 = 对话框 Agent**——符合「对助理交代」的习惯，不是空白控制室
2. **在办 + 待办/澄清 = 强状态层**——红点可操作；整页指挥台给并行与总览，不抢冷启动
3. **审核台保持深工具**——入口场景化为「进入文书台」，不与对话做成对等「第四个家」
4. **双表面用场景切换**——有待审稿才强调文书台；无全局模式设置项

### 0.3 明确非目标

- 不做「IDE 模式 / Agent 模式」设置项或持久化「默认首页」偏好开关
- **不**把冷启动默认改成整页 `agents`（已否决：不符合多数律师习惯）
- 不拆掉审核台三栏与独立预览窗
- 不把产品改成无状态、无处看并行的纯 ChatGPT 空窗
- 不在本计划内重做协作页 IA

### 0.4 成功画面（验收叙事）

1. 冷启动就是对话 Agent：输入框在，能交办、能贴材料。
2. 有待澄清时，对话内可填；顶栏/侧栏「在办」红点也能定位到同一事项。
3. 需要看并行/多 Agent/委派时，进「在办」总览；处理完可回对话。
4. 有待审稿时出现 **「进入文书台」**（对话条 / 在办卡 / 案件卡）；点入三栏审核；完成后回对话或案件。
5. 顶栏不再把「审核」做成与对话对等的日常首页。

### 0.5 为何修订（律师习惯）

| 心智     | 律师日常更像          | 产品对应               |
| -------- | --------------------- | ---------------------- |
| 开工     | 对助理说一句 / 丢材料 | **对话 Agent 默认**    |
| 被追问   | 在同一会话里补几句    | 对话内澄清 + 在办红点  |
| 并行卡住 | 才想起「还有几件事」  | **在办总览 / 状态条**  |
| 出稿验收 | 坐下来改、签          | **文书台（场景进入）** |

Cursor 整页 Agent Window 适合开发者多任务；对 Solo 律师，整页控制室当首页容易空、冷、「不知道在哪打字」。

## 1. 信息架构（目标态）

### 1.1 三层心智（对用户话术）

| 层                     | 用户说法        | 系统表面                                           | 何时出现                             |
| ---------------------- | --------------- | -------------------------------------------------- | ------------------------------------ |
| **交办层（默认首页）** | 对话 / 对助理说 | `mainView = "workspace"` 对话 Agent 窗             | 启动、日常交办与澄清                 |
| **状态层（第二屏）**   | 在办 / 待办     | 对话上的在办摘要条 + 整页 `agents` 总览 + 待我拍板 | 有红点、要看并行、要从总览进文书台时 |
| **交付层（深工具）**   | 文书台          | `review`；CTA「进入文书台」                        | 有待审稿或主动验收时                 |

### 1.2 顶栏改造（建议标签）

| 现状   | 目标                     | 说明                                                         |
| ------ | ------------------------ | ------------------------------------------------------------ |
| 对话   | **对话**（默认选中）     | 冷启动首页；身份是「Agent 交办窗」，不是闲聊产品             |
| 指挥台 | **在办**                 | 总览/舰队；有 badge 时强调；非默认                           |
| 协作   | （已并入「在办」子 Tab） | 不再对等顶栏                                                 |
| 审核   | **移除对等 Tab**         | 改为场景 CTA「进入文书台」；`mainView === "review"` 路由保留 |

### 1.3 对话首页应具备的「Agent 窗」要素

```
对话（默认首页）
├─ 主区：当前会话（交办、澄清、进度气泡）
├─ 输入区：消息 + 材料引用（熟悉、零学习）
├─ 会话内：待澄清条 / 「去填写」→ 滚到表单或聚焦输入
└─ 常驻状态层（必做）：
     ├─ 顶栏或对话上方：在办摘要（N 待处理 · 点开待我拍板或进在办）
     └─ 有待审稿时：主 CTA「进入文书台」
```

### 1.4 在办总览页（整页，非默认）

```
在办（总览 · 按需进入）
├─ 顶区：一句话状态（N 项待你处理 · M 个进行中）
├─ 快捷交办：预设 / 委派 / 工作流（可跳回对话）
├─ 主列：统一卡片（Agent / 委派 / 作业 / 待审稿）
└─ 右列：待办 | 轨迹；待审时主 CTA「进入文书台」
```

**待我拍板**：侧栏/顶栏入口跳转「在办」决策区（非独立模态）；打开后须有可操作项（填表 / 打开对话 / 进文书台），禁止「有徽章却空白」。

### Phase D — 对话 ↔ 在办往返打磨

**产品意图**：总览不是家，但要回得去、回得来。

| #   | 交付项                                                      | 验收       |

| D2  | 对话 → 在办：从摘要/顶栏进总览并尽量选中相关卡              | 定位准确   |
| D3  | 命令面板：`/review` →「进入文书台」；可加「打开在办」       | 快捷键对齐 |

### Phase E — 在办总览完成态（给并行重度用户）

**产品意图**：Firm / 多委派时，「在办」整页够用。

| #   | 交付项                                             | 验收       |
| --- | -------------------------------------------------- | ---------- |

## 3. 场景切换规则（取代「模式开关」）

| 条件                                           | 系统行为                                             |
| ---------------------------------------------- | ---------------------------------------------------- |
| 启动 / 关闭文书台                              | 落在 **对话**（`workspace`）                         |
| `awaiting_clarification` / `awaiting_approval` | 对话内可操作 + 状态层红点；可选进在办总览            |
| 存在待审/需修改草稿                            | 显示 **进入文书台**                                  |
| 点「进入文书台」                               | `setMainView("review")` + focus task                 |
| 审核完成 / 返回                                | 回 **对话**（或案件，若 `reviewLaunchedFromMatter`） |
| 用户主动要看并行                               | 进 **在办** 总览                                     |
| 无待审稿                                       | 不强调文书台主入口                                   |

**禁止**：`localStorage`「默认 IDE / 默认在办 / 默认对话」类模式开关。  
**禁止**：把冷启动默认改成 `agents`（与律师习惯冲突，本修订已否决）。

## 4. 度量与验收（客户友好）

### 4.1 定性走查

1. 新用户不进设置，1 分钟内能否：打开就打字交办 → 处理一次澄清。
2. 有待审稿时，不靠顶栏「审核」Tab，能否进入文书台并签批。
3. 有 2+ 并行卡住时，能否从对话上的红点进在办看清状态。

### 4.2 建议计数

- 冷启动落点应为 `workspace` 主导
- 「进入文书台」来源分布（对话条 / 在办卡 / 案件卡）
- 待我拍板打开后 10s 内是否发生可操作
- 自动整页跳进审核次数（目标趋近 0）

## 5. 风险与缓解

| 风险                       | 缓解                                                  |
| -------------------------- | ----------------------------------------------------- |
| 对话首页被当成闲聊产品     | 空状态/首跑/系统文案强调交办与交付                    |
| 状态层太弱，并行时迷路     | Phase A3 摘要 + Phase B 待办 + Phase E 总览           |
| 老用户找不着「审核」Tab    | 「进入文书台」多入口 + 通知文案                       |
| 在办与对话双源待办打架     | 同一真相源；主操作一处完成即可                        |
| 再度有人提议「默认改在办」 | 本文 §0.5；仅当 Firm 并行数据证明后再议，且应用户确认 |

## 7. 建议实施顺序

```text
A（对话 Agent 默认 + 状态摘要）
  → B（待办/澄清可操作）
  → C（进入文书台场景化）
  → D（对话 ↔ 在办往返）
  → E（在办总览完成态）
```

- **A+B** 优先：默认入口正确，且红点能办事。
- **C** 紧随：审核不再抢日常 IA。
- **D/E** 打磨并行与往返。

## 8. 与愿景的对齐检查清单

- [ ] 默认是「能交办的律师交互台入口」（对话 Agent），不是排版软件，也不是空闲聊（VISION §6.2d）
- [ ] 成功标准仍是任务级交付，不是对话轮次（VISION §6.2b–c）
- [ ] 在办/待办保证「领导看得见、拍板得到」（数字小团队）
- [ ] 审核/文书仍是可验收终点，入口场景化（DFA）
- [ ] 无模式开关；冷启动不强制整页控制室
