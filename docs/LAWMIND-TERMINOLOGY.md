# LawMind 术语表（一动作一词）

> **地位**：现行规范文档。律师可见文案、代码标识符、文档写作的用词以本表为准。  
> **执法**：UI 文案侧由 `pnpm lawmind:ui-copy-lint`（`scripts/lawmind/lawmind-ui-copy-lint.mjs`）机械拦截工程师语言回潮；本表是其禁词清单的口径来源。  
> **背景**：2026-09 评审实测同义词爆炸——renderer 内「在办 ×116、改稿 ×92、签批 ×91、审核 ×86、交办 ×83、复核 ×13」并存，同一工作面 Solo 叫「改稿」、Firm 叫「文书台」。律师不应为同一件事学六个词。

## 一、使用规则

1. **一动作一词**：每个动作/实体/场所在全产品只用一个词；近义词一律视为禁用词。
2. **律师可见面只说律师语言**：文件路径、英文枚举、门禁/机制术语不得出现在律师可见的任何界面、通知、报告与对外文档（见第三节禁词表）。
3. **代码标识符保持英文**：源码内的标识符（`matterId`、`reviewStatus`、`approve` 等）不受中文词表约束，但**不得**把标识符原文透到 UI 文案。
4. **文档写作同此表**：现行文档（见 `docs/LAWMIND-REPO-LAYOUT.md` 现行清单）新增内容必须用表中词；归档文档为历史快照，不回改。

## 二、核心术语表

| 术语           | 定义                                                      | 禁用近义词                                                           | 适用范围             |
| -------------- | --------------------------------------------------------- | -------------------------------------------------------------------- | -------------------- |
| **案件**       | 律师承办的一件委托事项；系统内唯一实体词（代码 `matter`） | 项目、事项、案子、matter（UI 禁英文）                                | UI / 文档 / 代码注释 |
| **交办**       | 律师把一件事交给系统去办的**唯一动词**                    | 派单、下单、提交任务、发起任务                                       | UI / 文档            |
| **在办**       | 正在进行、需要跟进的事项集合；也是工作面名称              | 待办、办理中、进行中（作栏目名时）                                   | UI / 文档            |
| **改稿**       | 对文稿做修订的**唯一动词**；也是改稿工作面的唯一名称      | 修订（作动词）、修改文稿、文书台、批稿                               | UI / 文档            |
| **审核**       | 律师审阅系统产出、决定能否通过的**唯一过程词**            | 复核、审查（指律师看稿时）、审批（指过程时）                         | UI / 文档            |
| **签批**       | 律师对一份产出做出最终批准的**唯一动词**；签批前不得对外  | 批准、通过（作按钮动词）、签发、approve                              | UI / 文档            |
| **待我拍板**   | 所有需要律师决定的事项的**唯一入口**名称                  | 待办中心、审批中心、待处理、action center                            | UI / 文档            |
| **交付**       | 把签批后的成品渲染成可发送 / 送达的形式                   | 出货、产出（作名词指成品时）、导出成品（作栏目名时）                 | UI / 文档            |
| **记忆**       | 系统经律师确认后记住的偏好、习惯与案件事实                | 学习（作名词）、知识库（指个人记忆时）、注入                         | UI / 文档            |
| **助手**       | 系统内干活的角色（代码 `assistant` / `role`）             | Agent、智能体、机器人、AI 员工                                       | UI / 文档            |
| **材料**       | 律师提供给案件使用的文件与证据                            | 语料、语料库（指律师自己的材料时）、上下文文件、context              | UI / 文档            |
| **本机文件夹** | 律师在本机选出、允许助手读取的目录（可多个；可绑案件）    | 项目目录（新文案禁用；存量设置项收敛）、挂载盘、workspace root（UI） | UI / 文档            |
| **本机查找**   | 在已选本机文件夹或系统查找中定位文件；点开后才读正文      | 全盘扫描、Spotlight（UI）、host search                               | UI / 文档            |
| **收进本案**   | 把本机文件复制进当前案件，成为本案材料                    | 导入工作区、ingest、import to workspace                              | UI / 文档            |
| **必核清单**   | 签批前必须逐项确认的核对项                                | 检查点、checkpoint、gate 项                                          | UI / 文档            |

### 用词分场景细则

- **审核 vs 合同审查**：「合同审查」是**业务场景名**（一类交办事项，如「审查这份合同」），保留；律师盯着稿子看的动作一律叫「审核」。
- **复核**：禁用，已进硬拦档。界面说「审核」。稿件意见落盘仍用前缀「复核：」，显示时改写成「审核：」，旧稿不用迁移。
- **文书台**：禁用，已进硬拦档。改稿工作面 Solo / Firm 都叫「改稿」。唯一豁免是历史动作日志里对旧词的识别（`matter-interaction.ts`），不展示给律师。
- **通过**：作签批结果状态可用（如「已通过」）；作按钮动词一律用「签批」。
- **批准**：同上。作状态可用（如「已批准」）；作动词一律用「签批」，「待批准」收敛为「待签批」。
- **语料 / 语料库**：**只禁指律师自己交进来的材料时**。指法源库时保留——「演示语料」「开源语料」「厂商语料」是第 32 章认可的诚实说法（说明这不是完整权威库），不算近义词回潮。
- **修订**：作**我们自己的动作**（「派发助手修订」「按修订确认」）时用「改稿」；`已修订`（改稿状态）、`合同修订稿 / 修订版`（对方来稿）、`修订记录`（`.redline.json` 对律师的说法）保留。

## 三、工程师语言禁词表（律师可见面）

以下类别**不得出现**在律师可见面（UI 文案、系统通知、交付报告、律师向文档）。`lawmind-ui-copy-lint` 对 renderer 文案做机械拦截，清单与本表同步维护；存量合法用例在 `scripts/lawmind/ui-copy-lint-allowlist.json` 登记豁免并注明理由。

| 类别       | 禁词 / 模式                                                                                                                     | 应改为                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 文件路径   | `assistants/…`、`*PROFILE.md`、`MEMORY.md`、`RULES.md`、`CASE.md`、`drafts/…`、`cases/…`、`matters/…`、`workspace/…` 等相对路径 | 「助手档案」「记忆」「本案规则」「案件档案」等业务名  |
| 机制黑话   | 「产出 Agent」「推理图覆盖率」「侧车」（sidecar）                                                                               | 对应律师语言（助手 / 覆盖情况 / 随行进程，或删去）    |
| 提示词机制 | 「已注入 / 未注入 / 始终注入 / 注入记忆」「system prompt」                                                                      | 「已记住 / 已写入」「系统设定」（仅工程文档可用原文） |
| 英文枚举   | UI 直接展示代码枚举原文（如 `pending_review`、`auto_deliver`、`strict`）                                                        | 中文状态词（待审核 / 自动交付 / 严格）                |
| 门禁术语   | gate、bypass、门禁、拦截器、中间件、e2e、token、IPC、API、JSON（对律师面）                                                      | 「核对」「必核」「确认」等业务语言；工程文档不受限    |

> lint 脚本当前机械拦截 **26 条模式**（14 条工程师语言 + 12 条「存量已归零」的近义词，含「文书台」「复核」）见 `scripts/lawmind/lawmind-ui-copy-lint.mjs` 的 `BANNED_PATTERNS`；还有 **4 条仍有存量的近义词**走 `SYNONYM_PATTERNS` 棘轮档，地板冻结在 `scripts/lawmind/ui-copy-lint-synonym-baseline.json`（只许下降）。新增禁词先改本表，再同步脚本，保持「表 → 脚本」单向口径。

## 四、代码标识符约定

- 代码内英文标识符不变：`matter`（案件）、`task`（交办事项）、`draft`（草稿）、`review`（审核）、`approve`（签批）、`deliverable`（交付物）、`memory`（记忆）。
- 标识符与中文术语的对应关系以第二节为准；新增标识符前先查表，避免再造同义词（如不要再引入 `re-review` 对应「复核」）。
- **`review` 一个前缀照两个律师词**：`review`（审阅判断）= 审核；改稿工作面（`apply_surgical_edits` / `render_tracked_draft` / `drafts/`）不能也叫 `review`——术语表里「改稿」的代码列只写改稿侧标识符，别把 `review` 同时挂给两个词。
- 注释面向工程师，可用工程术语，但引用律师可见概念时用本表中文词，减少两套语言漂移。

## 五、现状与收敛

- 本表为**规范**，不声称存量已达标；上表标注的存量计数（2026-09-24 实测）用于跟踪收敛。
- 收敛顺序建议：律师主路径（交办 → 对话 → 审核 → 签批 → 交付）先行，设置页与低频入口随后；每轮收敛后跑 `pnpm lawmind:ui-copy-lint` 防回潮。
- **两档执法**（`scripts/lawmind/lawmind-ui-copy-lint.mjs`）：
  - **硬拦档**（`BANNED_PATTERNS`）：14 条工程师语言 + 12 条「存量已归零」的近义词（出货、派单/下单、检查点、全盘扫描、待办中心、审批中心、批稿、AI 员工/机器人、上下文文件、智能体、文书台、复核）。命中即失败。
  - **棘轮档**（`SYNONYM_PATTERNS` + `ui-copy-lint-synonym-baseline.json`）：待办 21、审批 32、批准（动词）37、修订（自己的动作）26，**合计 116 处存量冻结**。新增即失败；某词收敛到 0 后，把它从棘轮档移进硬拦档。
- 与本表冲突的历史表述见归档文档（`docs/archive/`），归档文档只读封存、不回改。
