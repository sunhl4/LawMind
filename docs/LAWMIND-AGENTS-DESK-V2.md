## 1. 为什么要颠覆现状

现状（即使已降噪文案）仍是**工程师监控台**：

- 三 Tab（进行中 / 交出去的 / 按流程）平权，律师不知先点哪
- 左右等宽：列表 + 详情抢视线，**没有「这一件」的舞台**
- 卡片堆状态/类型/进度，像运维面板，不像「等我签字的文件筐」

律师真实心智只有三句话：

1. **有没有要我拍板的？**
2. **点开这一件，我该做什么？**
3. **做完下一件是什么？**

其余（流程引擎、交办关系、同步、轨迹、过签率）都应沉到底层。

## 2. 对标产品学到什么

| 产品                  | 模式                                                            | 可迁移到 LawMind                                      |
| --------------------- | --------------------------------------------------------------- | ----------------------------------------------------- |
| **Linear Triage**     | 单一「待处理队列」；选中后右侧/主区做 Accept / Snooze；键盘优先 | 「待我拍板」即 Triage；一屏只服务一件决策             |
| **Asana My Tasks**    | 按人视角分段：Today / Upcoming；不是按系统对象类型分            | 用「待我确认 / 办理中 / 已交办」分段，不用工作流/队列 |
| **Superhuman / 邮件** | Master–Detail：**详情区占主导**；列表只是索引                   | 详情舞台 ≥65% 宽；主 CTA 超大、唯一                   |
| **Harvey Workbench**  | 能力再多，入口统一；内容区与导航区清楚分离                      | 新任务永远回对话；在办只负责「跟进与拍板」            |

**反模式（禁止回归）**：等权多 Tab、等权双栏、一屏多个金色主按钮、把 Agent/Job/工具名露给律师。

## 3. 颠覆方案：Decision Inbox（决策收件箱）

### 3.1 一句话定位

> **在办 = 今日需要你过目与拍板的收件箱。**  
> 新任务不在这里创建，回「对话」下达。

### 3.2 信息架构（取代三 Tab）

```
Segment（单选胶囊，非三套页面）
├─ 待我确认   ← 默认着陆（原 awaiting_*）
├─ 办理中     ← 助手正在做、暂不需你
└─ 已交办     ← 原「交出去的」；默认不进主视线
```

「按流程」**不再占一级**：沉入对话模板 / 「更多 → 按流程启动」，或案件室内入口。

### 3.3 布局（Master–Focus，非等宽双栏）

```
┌─ Header ──────────────────────────────────────────────────┐
│ 在办 · 今日有 3 件待你确认          [回对话下达]（唯一 brass）│
│ ○ 待我确认(3)  ○ 办理中(5)  ○ 已交办(2)                      │
├─ Index ~32% ─────┬─ Focus Stage ~68% ─────────────────────┤
│ 分组列表         │  事项标题（大）                           │
│ · 待签批         │  一句话：为什么需要你                     │
│ · 待补充         │                                          │
│ · 待批准         │  ┌────────────────────────────┐         │
│                  │  │  主 CTA（巨大）               │         │
│ （办理中折叠）   │  │  进入文书台签批               │         │
│                  │  └────────────────────────────┘         │
│                  │  次要：稍后处理 · 打开对话 · 停止        │
│                  │  ── 本案要点（折叠）──                    │
│                  │  ── 办理过程（折叠）──                    │
└──────────────────┴──────────────────────────────────────────┘
```

### 3.4 交互原则

1. **默认打开第一件待确认**，律师进来就能动手，不必先点卡片。
2. **每屏一个主 CTA**（签批 / 去对话补充 / 批准），颜色唯一 brass。
3. **列表只答「还有什么」**：标题 + 状态口语 + 一行下一步。
4. **办完自动下一项**（Linear Triage 节奏）。
5. 技术细节一律 `<details>` 或「更多」。
