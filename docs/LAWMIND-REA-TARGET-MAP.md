# LawMind · REA 目标地图（闭源软件 / 网页的规格吸收）

> 日期：2026-10-26（2026-10-27 修订：加载项退出范围）
> 工具：REA 6.8.0（`inspect-desktop-application`、`analyze-javascript-application`、`analyze-web-bundle`、`capture-*-scenario`、`compare-application-versions`、`build-reconstruction-obligation-ledger`）
> 边界：只吸收**可观察行为、交互状态机、文件格式与校验规则**；不搬运代码、提示词、专有文案或数据；不绕许可、不破 DRM、不碰云端后端。
> 关系：`LAWMIND-MEWORK-REA-GAP.md` 是 MeWork 单点补证；本文回答「下一个该拆谁、为什么、拆到什么程度」。`GOALS.md` 铁律 #4（先复用后自研）与 #5（合法吸收）仍适用。

## 0. 一句话结论

**REA 的高产出区是「价值落在客户端」的专业工具，不是云端法律 AI。**

- 值得拆：文档比对、PDF 证据处理、批量阅卷、文书装配、立案包、律所运营界面。这些的边缘案例、状态机、文件格式都在客户端。
- 不值得拆：Harvey / Legora / CoCounsel / 北大法宝 / 威科的「大脑」。模型、检索、数据授权在服务端，REA 只能看到壳。

所以排序不按品牌知名度，按三个乘积：

> **客户端逻辑密度 × 采信价值 × 中国法域适配**

### 0.1 产品边界：所有工作在 LawMind 内完成（2026-10-27）

这一条优先于本文后面的所有目标排序：

- **不再做 Word / WPS 加载项**：不做任务窗格、不做侧载清单、不做端口登记、不把「在 Word/WPS 里审」当产品路线。
- **不把「用 WPS 打开」当工作流步骤**：`open-with-wps`、`用本机应用打开` 只保留为异常格式的逃生口，不是默认路径，也不进验收。
- **审阅、比对、标注、改稿、签批都在 LawMind 内完成**：文件工作台、修订视图、PDF 阅读/标注、表格审阅、交付包清单是主工作面。
- **导出 docx / pdf / zip 是交付格式，不是编辑回路**：导出后不要求律师再打开 Word/WPS 改一轮；需要改就在 LawMind 内改，再导出。
- **既有加载项代码只保留维护态**：不删、不扩展、不新增验收；手册里对加载项的描述是现状，不是路线。
- **REA 只吸收行为规格**：Word/WPS/Acrobat 的「比较文档」「修订接受/拒绝」「页锚」等行为可以作为规格参考，但不以集成或嵌入为目标。
- **外部工程不改变本条边界**：投标自动化工程（平级目录 `../TenderOS`，规格见 `docs/LAWMIND-LEGAL-TENDER-AUTOMATION.md`）与面向他司的 WPS 套件移植规格（`docs/WPS-SUITE-PORTING.md`）都是独立交付物；它们的 WPS 集成或投标桌面目标不回灌到 LawMind。

一个由此产生的硬门槛：任何新能力如果必须跳出 LawMind 才能完成，**默认降级或不做**；确实需要外部程序时，只允许作为导出/应急出口，并在产品文案里明确标注。

## 1. REA 能看见什么、看不见什么

| 层                   | 可见                                                  | 典型产出             | 对 LawMind 的用途              |
| -------------------- | ----------------------------------------------------- | -------------------- | ------------------------------ |
| Electron / JS 桌面   | 主进程与渲染层模块图、IPC、校验器、工具契约、文件读写 | 应用图 + Evidence    | 规格、状态机、边界条件         |
| Web 客户端           | bundle、路由、API 调用形状、组件树、i18n              | 页面 / 网络 Evidence | IA、数据模型、导出格式         |
| 原生 macOS / Windows | AX 树、截图、窗口与菜单、可访问性动作                 | UI Evidence          | 行为 capture，不做二进制反编译 |
| 云端后端             | **不可见**                                            | —                    | 不投入                         |

> Word / WPS 加载项已退出目标范围（2026-10-27）。它们的行为只作为「比较文档 / 修订接受拒绝 / 页锚」的规格参考，不作为集成、嵌入或验收对象。

三条限制要先说清：

1. **代码可见 ≠ 逻辑可见**：压缩、混淆、服务端渲染、feature flag 会把关键路径藏起来。
2. **Web SaaS 的 bundle 是壳**：模型、检索、计费、权限都在服务端；REA 拿不到，也不该拿。
3. **原生二进制反编译成本高、法律风险高**：优先 AX 行为 capture + 公开文档 + 开源组件。

### 1.1 什么时候不该跑 REA

- **文档能说清的**：公开帮助中心、定价页、API 文档、法院文书样式。直接读，别拆包。
- **公开 API 能接的**：飞书/企微机器人、电子签、工商数据。走官方接口，别逆向。
- **价值在服务端的**：Harvey / Legora / CoCounsel / 法宝 / 威科。拆到的只是壳。
- **只有「必须点进去才看得到、且客户端才算得出来」的交互**，才值得跑 REA。
- **必须跳出 LawMind 才能用的加载项/外部编辑器**：不跑、不拆、不排期；产品内没有这个工作面就不做。

一个本机实测（2026-10-26，仅用于判断交付形态）：

```bash
npx rea-agents@latest inspect-desktop-application "/Applications/wpsoffice.app" \
  --detail summary --evidence_output tmp/rea/wps-inspect.json
```

结果：6421 个文件，0 个 JS/Electron 候选，0 个组件标记——WPS 是原生应用。REA 对它只能做 AX 行为 capture，不能拆 bundle。这次实测的结论不是「改做 WPS 加载项」，而是：**加载项路线既不是我们的产品方向，也不是 REA 的高产出区，直接退出范围。**

## 2. 合法吸收的硬规则

这一节不是道德表态，是防止把公司拖进版权/商业秘密纠纷、也防止把维护绑死在别人实现上的工程规则。

1. **不搬代码、提示词、专有文案**。只写行为规格；实现由我们自己写。
2. **净室分离**。写规格的人可以看 Evidence；写代码的人只看规格与公开资料。至少做到实现者不复制粘贴。
3. **Evidence 不入库**。放 `tmp/rea/<product>/<date>/`（已 gitignore）或仓库外；不提交解包源码、chunk、含客户数据的截图。
4. **只用公开面 / 自有账号**。公开页面、公开试用、自己买的 license；不绕登录、不破 DRM、不批量抓数据。
5. **许可证与 ToS 先核**。网页抓取、API 调用、导出格式使用都要看条款；有疑问就不做。
6. **专利 / 商业秘密红线**。某个交互疑似专利或明确商业秘密，先让法务看；不把「能拆」当「能抄」。

**能吸收的是规格，代码要自己写。** 直接搬对方代码进商业产品，省下的两周会在许可证、升级、维护和法律风险上加倍还回去。

## 3. 选择标尺

| 维度            | 权重 | 问题                                                                |
| --------------- | ---- | ------------------------------------------------------------------- |
| 采信杠杆        | 30   | 是否让交付更可验证、更敢用，而不是只更快？                          |
| 中国法域适配    | 20   | 是否对应中国法院、文书、法宝、企微？                                |
| 本地闭环        | 15   | 能否在律师一台机器上、在 LawMind 内跑完，不引入云依赖和外部编辑器？ |
| 客户端可见度    | 15   | REA 是否真的看得到行为与规格？                                      |
| 首切片成本      | 10   | 4 周内能否出一个可用切片？                                          |
| 法律 / ToS 风险 | 10   | 是否公开面 / 自有账号、无绕过？                                     |

**准入线**：加权 ≥ 3.8 / 5，且「采信杠杆」单项 ≥ 4；**「本地闭环」低于 3 的目标直接不排期**。

## 5. 第一轮三个试点

### Pilot A · 文档比对（全程在 LawMind 内）

- 目标：把「两份 docx 比对 → LawMind 内修订视图 → 导出保留修订的 docx」的交互与边界写成规格，不抄代码。
- 参考：Word / WPS / Acrobat 的「比较文档」只作为行为参考；**不侧载、不嵌入、不要求律师打开它们**。
- 观察：粒度选项、格式忽略、表格/编号/页眉页脚/脚注、移动检测、批注、输出为修订还是新文档、失败与只读文件的行为。
- 验收：两份含表格、编号、页眉页脚的 docx，在 LawMind 文件工作台里能看差异、接受/拒绝、导出保留修订的 docx；正文无丢失；不依赖 Word/WPS。

### Pilot B · 法院立案包（公开网页）

- 目标：把「一个案件从材料到可提交包」的清单与格式抄成规格。
- 命令：
  - `npx rea-agents@latest analyze-web-bundle`（本地 CDP endpoint + target id）
  - `npx rea-agents@latest capture-browser-scenario`（公开页面；不登录、不绕验证码）
- 观察：材料清单、份数、文件命名、PDF 合并顺序、页数/大小限制、送达地址确认书、授权委托书、证据目录、案件要素表。
- 验收：3 个法院 / 3 类案件生成 checklist；缺件明确说缺；不假装「已符合全部要求」。

### Pilot C · MeWork 剩余项（已有包）

- 目标：把 `LAWMIND-MEWORK-REA-GAP.md` 里「规格弱/强」的项补到可开工。
- 命令：`npx rea-agents@latest capture-electron-scenario`（分析表、时间线、音频入口）。
- 观察：分析表 schema、依据列导出、时间线/思维导图再生纪律、音频入口的实际状态。
- 验收：只更新规格摘要；不把解包源码或专有 chunk 提交进仓库。

## 7. 每个目标的作业流程

1. **卡**：产品 / 版本 / 平台 / 入口 / 证据命令 / 可见面 / 不可见面 / 预计产出 / **是否全程在 LawMind 内完成**。
2. **Capture**：REA Evidence + 截图 + AX 树；存 `tmp/rea/`，不进 git。加载项、外部编辑器不跑。
3. **Spec**：行为 ID（`COMPARE-01`…）、状态机、文件格式、边界条件、错误语义（不抄原文）。
4. **Build**：实现者只读 spec + 公开/开源资料；不读 Evidence；实现必须落在 LawMind 自己的渲染层/文件工作台。
5. **Verify**：行为测试，不用竞品 golden；逐条对照 spec；记录「有意不做」；不以「能在 Word/WPS 里用」验收。
6. **Ledger**：`build-reconstruction-obligation-ledger` 生成重建义务清单；摘要进本文附录或独立 ledger。
7. **Watch**：季度 `compare-application-versions` 看对方新能力，只更新竞品情报，不自动跟进。

**验收口径**：不以「对方有，我们也有」验收；以「律师少改一稿、少一次返工、少一次被退回，而且没有跳出 LawMind」验收。新能力必须进 `LawMind-Bench` 或真稿对照，否则只能算「功能完成」，不能算「能力可用」。
