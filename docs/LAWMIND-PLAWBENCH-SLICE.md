# PLawBench 切片：中国法实务 × LawMind 真循环

工程复测手册。不是官方榜。语料缓存在 `tmp/official-benchmarks/plawbench/cache/`（gitignore），不进 git。

数据源：<https://github.com/SKYLENAGE-AI/PLawBench>（ACL 2026 / arXiv:2601.16669）。官方裁判协议见仓库 `prompt_zh.py`。本切片用 **deepseek-flash 单裁判** 按官方 rubric 打分，百分比不可直接对论文表。

Harvey 英文对照与交件/账本改动见 [docs/LAWMIND-HARVEY-LAB-SLICE.md](./LAWMIND-HARVEY-LAB-SLICE.md)。  
中国法律 Agent 公开集与自建 **LawMind Bench**（独立平级仓库）：[docs/LAWMIND-CHINESE-LEGAL-AGENT-BENCHMARKS.md](./LAWMIND-CHINESE-LEGAL-AGENT-BENCHMARKS.md) · 本机常见 `../LawMind-Bench/`。

## 1. 为什么用这套，而不是继续 Harvey

|        | Harvey LAB（本仓库两题）            | PLawBench                                       |
| ------ | ----------------------------------- | ----------------------------------------------- |
| 法域   | 美国雇佣合同英文                    | **中国法**实务场景                              |
| 权威库 | 不应为凑分去搜北大法宝              | `search_statute` / `search_case_law` 与产品同向 |
| 形态   | 多文件摘录 + 问题备忘录 + 命名 docx | 咨询追问 / 四段案例分析 / 起诉状·答辩状         |
| 评分   | 二元 match_criteria                 | 专家 rubric 加权分                              |

LawBench / LexEval 是考卷零样本，不是交件回合；LegalAgentBench 依赖远程工具 API，默认不进本切片。

## 3. 怎么跑

```bash
pnpm exec tsx tmp/official-benchmarks/plawbench/run_slice.ts
# 只跑已选子集中的某类：
KINDS=case,complaint pnpm exec tsx tmp/official-benchmarks/plawbench/run_slice.ts
# 全部 280 题（250 案例分析 + 6 起诉状 + 6 答辩状 + 18 咨询）。中断后重跑同一命令会跳过已成功的题。
SLICE=full pnpm exec tsx tmp/official-benchmarks/plawbench/run_slice.ts
# 只评分已有工作区产物：
RESCORE_EXISTING=1 pnpm exec tsx tmp/official-benchmarks/plawbench/run_slice.ts
# 只重跑全量基线里 acc&lt;0.5 的题，并读桌面 `.env.lawmind` 的北大法宝。不改写 slice-report-full.json。
ONLY_FAILED=1 pnpm exec tsx tmp/official-benchmarks/plawbench/run_slice.ts
```

首次会读 `cache/`；缺文件时从 GitHub raw 拉取。9 题报告：`tmp/official-benchmarks/plawbench/slice-report.json`。全量报告：`slice-report-full.json`。全量默认不跑直调，要对照时加 `DIRECT=1`。

### 4.2 首跑结论（给后续改动用）

1. **劳动案例分析**：LawMind 与直调接近（略低或持平）；`search_statute` 已走产品路径，不必为追平直调而关工具。
2. **起诉状**：至少一题（complaint-4）显示 harness 价值巨大；complaint-6 说明检索≠rubric 覆盖。
3. **答辩状**：LawMind 显著落后直调 → 下一刀优先看答辩状技能/交件结构，而不是再改 Harvey 英文账本。
4. **咨询追问**：指令「只追问不给意见」有效时满分；consult-5 需看清单是否偏题。
5. 单裁判 flash 有噪声；改引擎前后应用同一 harness 复测，并在本表追加行。

### 5.4 失败形态归类（给改引擎用）

1. **金标极性相反**（刑事占有类）：检索空 + 通说坚定 → 整题崩。要并列对立口径，或接中文类案库后再收口。
2. **律师对冲压过考卷结论**（医美/惩罚性赔偿）：「不宜承诺」吃掉结论分。考卷形态应交办时先写明确结论句。
3. **权威检索空转**：刑法/澳门法/专门规章常落到演示语料；模型标【待核实】后法条栏失分。北大法宝实连与刑法条文召回要单独验。
4. **步骤顺序**：rubric「顺序不可调换」；自由展开会丢分析过程分，即使实体方向对。
5. **裁判噪声**：同一模型单裁判仍会晃；分题涨跌要对照稿面，不要只看均分。

## 8. 低分题门控与法宝对照

全量基线（`slice-report-full.json`，无北大法宝，均分约 0.786）里，案例分析多数已经很高，起诉状/答辩状和一部分追问很低。门控只认任务句，不认空行后的案情：

- 起诉状/答辩状：文件落地后本回合不再广告检索。缺诉讼请求或答辩请求、事实、理由、证据时，隐藏提示重写一次。
- 追问：任务句写明不要完整法律意见时，不广告 `search_statute` / `search_case_law`。编号不足 8 条时重写一次。

`ONLY_FAILED=1` 只重跑基线 acc \< 0.5 的题，读桌面 `.env.lawmind` 的法宝变量，结果写入 `slice-report-pkulaw-failed.json`。每题日志要有 `providers=pkulaw` 且 `livePkulaw` 大于 0，否则这次仍没测到法宝。不重跑已经 ≥0.5 的题。
