# 记忆长期使用：双门复审与调研（大白话）

> 日期：2026-09-27  
> 范围：`src/lawmind/memory/`、`src/lawmind/learning/`、`src/lawmind/stance/`、提示词注入、桌面「记忆库 / 审核台」  
> 目的：律师用几个月之后，这套记忆会在哪里帮倒忙；外面同类产品与论文怎么解；我们该先改什么。  
> 不是：立刻换掉 Markdown 真相源，也不是接一套云端记忆服务。

交叉引用：[手册第 6 章](./lawmind/manual/06-memory-and-learning.md)、[第 37 章](./lawmind/manual/37-memory-modules-reference.md)、[未来问题总册](./LAWMIND-FUTURE-ISSUES.md)。

## 0. 先说结论（双门复审后仍站住的）

方向没错：**Markdown 人能打开改**、**风格偏好尽量先确认再落盘**、**提示词只塞短指纹**、**立场库已经会查冲突**。这些不要推翻。

律师长时间用起来，真正会痛的是另外五件事：

1. **写进去容易，想收回难**——界面和注释说能「撤回」，实际只能忽略还没确认的建议；已经写进档案的句子还在。
2. **别的案子会悄悄出现在本轮对话里**——工作区搜索有跨案开关，相似案摘录没有；也不看当事人是否对立。
3. **一单上的让步，容易变成「你平时就这么写」**——个案识别太窄；审核标签默认就能写进律师档案。
4. **找不准时，仍塞最近文件**——相关记忆分数全是 0 时，还会塞最近几份进提示词。
5. **设置页写「点确认才会写入习惯」**——审核标签那条路可以绕开这句话。

外面 2025–2026 的主流解法，不是「再加一个向量库」，而是：**每条记忆有生效/失效、按键更新、检索时绝不返回已作废的内容、写法与案件事实分槽、跨人跨案要过权限门**。Harvey 的个人记忆也明确：**第一期只记个人写法，不记客户和案件事实**。

下面先写双门复审表，再写大白话说明，最后写建议改法与外链。

## 2. 现在这套记忆到底在干什么（大白话）

可以想成律所自己的小柜子，不是云端黑盒：

- **柜子里的纸**：`LAWYER_PROFILE.md`、`CASE.md`、客户档案、playbook、日记等，人用编辑器也能打开。
- **待你签字的条子**：记忆库里的「待确认」。风格类建议默认要你点确认（或批量预览后再确认）。
- **已经写进卷宗的流水**：案件争点、风险、进展等，工具一记就进 `CASE.md`（队列里标成自动采纳）。理由说得通：记错了打开卷宗能看见；偏好记错了很难发现。
- **模型每轮真正「盯着看」的**：很短一截——律师指纹大约八百字、本案索引更短一点。整本档案不整段塞进脑子。

设计意图写在手册第 6 章：**未确认尽量零写入**；装不下要告诉模型「完整内容去某文件读」，不许悄悄切掉。

## 3. 律师用久了会怎样疼

### 3.1 改了主意，旧话还在指挥模型

你去年喜欢「付款 30 日」，今年确认改成「45 日」。两边句子都可能还在档案里。指纹窗按本轮问句里的双字重叠挑条，「付款」「期限」两边都能对上，模型就可能左右互搏。

界面上「忽略」只对**还没确认**的条子有效。已经写进文件的，没有「这一条从今天起作废、以后别再塞进提示词」的按钮。代码注释和旧季报里的「一键撤回」，律师在记忆库里找不到对应动作。

### 3.2 别家案子的字，跑进这家对话

你在办甲客户。系统用双字相似度翻别的 `CASE.md`，把看起来像的几段塞进提示词。合同都有「甲方」「违约」「付款」，很容易像。摘录又常从前部列表行来，当事人、金额、案号往往就在那儿。

工作区搜索要开跨案开关才扫别案；这段「相似案进提示词」**不看那个开关**，也**不看**当事人是否对调。本机文件夹倒是有利益冲突隔离——两边标准不一致。

### 3.3 这一单的让步，变成你的人设

对方死磕，你这单把付款期限放宽。系统若当成「你的习惯」，下一单没谈拢的客户也会拿到同样口径。

现在的「个案」识别太粗：看得见年份、金额、有限公司；看不见案号、法院、英文主体、银行账户，也看不见「可谈判条款」。审核时你只是想标「语气过强」，系统却可能把整句备注写进律师档案——设置页还写着要先确认。

### 3.4 找不准就硬塞最近的

相关记忆对不上问句时，仍塞最近几份文件。模型看起来「很有记忆」，其实是噪音。任何叫 `CASE.md` 的路径还额外加分，别案卷宗也可能被抬上来。

### 3.5 用得越久，真正稳的习惯越看不见

热档案超过约 120 条，最早的挪进归档。归档不参与本轮挑选。问句对不上时，窗口只留最近几条。一年前确认过、至今仍对的写法，可能某一天静默离开模型视野——文件还在，提示词里没了。

### 3.6 立场库是亮点，但别指望它罩住全部

条款立场已经会：被取代的不进、预置未确认的不进、太旧的打折、证据最好跨两个不同案件、客户/对方对调则跳过。这是全库最接近「专业记忆」的一层。缺口是：证据若含本案可豁免跨案门槛；冲突只比精确名字；同一条款仍可能并排进两条。

## 4. 外面最新在怎么做（调研，大白话）

### 4.1 法律产品：Harvey

Harvey II 的 Memory（约 2026）：

- 记**个人怎么写**（结构、引用习惯、风险胃口、红线风格），**第一期不记客户/案件细节**。
- **不偷偷记**：有确认卡；设置里可查、改、删，可整关。
- 设计伙伴强调：**可审计**是硬条件。
- 事项级 / 组织级记忆往后做，并要伦理墙（含 Intapp 一类集成）。

对我们的启示：个人偏好与案件事实分槽；确认与可删是标配；跨事项记忆不能比个人偏好更松。

产品说明：[harvey.ai/blog/memory-is-here-harvey-personalized](https://www.harvey.ai/blog/memory-is-here-harvey-personalized)、[平台页](https://www.harvey.ai/platform/memory)；访谈：[Point Blank](https://www.pointblank.law/p/inside-harvey-ii-legal-ai-that-remembers-how-you-work)。

### 4.2 开源与工程：三类架构，三种用途

| 名字                   | GitHub / 形态                                               | 适合什么                                                   | 不适合我们直接整仓替换的原因                    |
| ---------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------- |
| **Mem0**               | [mem0ai/mem0](https://github.com/mem0ai/mem0)               | 对话里抽事实、`add/update/delete/search`                   | 后台自动抽取，和「未确认零写入」拧着            |

| **Graphiti / Zep**     | [getzep/graphiti](https://github.com/getzep/graphiti)       | 事实有时间窗，矛盾时旧边失效，检索可问「现在为真的是什么」 | 要图数据库；可学机制，不宜当本机真相源          |

## 5. 我们该怎么改（建议顺序，仍用大白话）

**原则：柜子还是 Markdown；学的是「失效、按键、分槽、读取过滤」，不是换云端大脑。**

### P0（信任与串味）

1. **真撤回 / 真失效**  
   每条已采纳习惯有：范围（个人 / 客户 / 本案）、键（如「付款期限」）、生效与失效时间、来源案件。律师点「这条作废」→ 热区去掉、归档保留、**组提示词时绝不注入失效条**。注释和季报里的「一键撤回」要么做成，要么删掉表述。

2. **跨案摘录过同一道门**  
   与利益冲突 / 跨案搜索同口径：未允许跨案、或当事人对调 → 不把别案 `CASE.md` 塞进提示词。摘录只用命中的争点/风险句，不从前部随便切当事人行。

3. **改设置文案或改审核写入**  
   二选一（建议改写入）：审核标签继续可打；**写成永久偏好必须进待确认**；备注里的本案事实只进本案进展。设置页那句「点确认才会写入习惯」必须和真实行为一致。

### P1（长期好用）

4. **新习惯默认问范围**  
   通用写法 / 只属于这个客户 / 只属于本案。可谈判条款（期限、管辖、违约金等）默认本案或客户，不进批量「低风险风格」。

5. **待确认队列别进「已生效」提示通道**  
   留在记忆库红点；不要和指纹偏好同一段系统提示。

6. **零分召回不注入**  
   对不上就空着，不要塞最近三份。`CASE.md` 加分只给本案。

7. **律师档案两块**
   - 短核心：身份 + 仍有效的十几条写法，人可编辑，始终占指纹预算。
   - §八 / 归档：按键检索，问句也能打到归档里的有效条。

### P2（加固）

8. 把立场库的冲突与衰减经验，推广到偏好条目（同条款冲突、客户串味）。
9. 给 `validUntil` / 失效真正赋值，并在召回路径过滤。
10. 用现有 cassette 加两条验收：**偏好反转后旧句不进请求体**；**对立当事人旧案不进请求体**。不必先上通用长记忆榜。

**明确不做（除非产品另开题）**

- 打开团队记忆云同步。
- 整仓换成 Mem0 / Letta / Graphiti 当真相源。
- 让模型自己改核心人设而不经律师确认。

## 8. 重构第一刀（2026-09-27 已落地）

上面第 5 节的渐进补丁不再作为实施顺序。已经按重构版做了第一刀，没有换成云端记忆服务：

- 真相源是工作区 `lawmind/memory-kernel.sqlite`。类型、范围、确认态、失效态在 `src/lawmind/memory/kernel/contract.ts`。写法槽对齐 Harvey（语气、结构、引用、改稿、风险、格式）；条款键沿用现有立场名。表里没有的键可以写，不靠词表拒绝。
- 进提示词的只有已确认、当前有效、范围匹配、且与本案当事人不冲突的记录。未确认不进。其他案件不自动混入；点名旧案才走 `formatExplicitPrecedentRecall`。
- 同一写法槽再次确认会把旧句标成被取代。撤回后不再进入提示词。
- 审核时打标签只产生待确认。律师在记忆库点确认之后才写入档案。
- 记忆库界面是「我的习惯 / 本案认知 / 已作废」，有效记录上有撤回。
- 两条 cassette：偏好反转后旧句不进下一次请求；对立旧案不进下一次请求。

还没做的增强没有了。Markdown 档案仍在，给人看，也作为导入来源。语义召回、习惯巩固和关系都在本机记忆库里，见 §11。

## 9. 第二刀（2026-09-27）

计划只做内核稳住之前、会让长期使用失真的两件事。语义召回和关系留到第四刀。

| 项                 | 做法                                                                                | 为什么现在做                                                             |
| ------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 导入跟文件走       | 每个来源文件记修改时间。变了才再导。已有 id 不覆盖，撤回不会被导入复活              | 第一刀用进程缓存，律师改完档案要重启才进下一轮                           |
| 确认时选槽位和范围 | 默认仍是一键确认，不进对话。可选「语气 / 结构 / …」替换同一种旧写法，或「只限本案」 | 审核标签原先都堆在「就这一条」上，不会替换旧口径，也分不出这单和通用写法 |

对话里不新增确认框。本案事实仍然直接记下。跨案仍然不自动注入。

## 10. 第三刀（2026-09-27）

## 11. 第四刀（2026-09-27）

原先留下的三块增强，都做在本机记忆库里，没有接图数据库，也没有用哈希冒充语义模型。

| 项       | 做法                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 召回     | 本案事实按槽位中文名和正文一起找。问「风险」能召回没写这两个字、但记在风险槽里的句子。其他案件仍然不进   |
| 习惯巩固 | 同一种写法、同一句话，至少两个案件确认过，才生成一条待确认的通用习惯。口径不同的不合并。确认前不进提示词 |
| 关系     | 新口径取代旧口径、以及「这条归纳自哪些案件」，记在记忆库的关系表里。撤回和待确认的规则不变               |

## 12. 读取门（2026-09-27）

记忆库可用时，提示词里的习惯只来自当前有效的记录。已撤回或被取代的句子会从律师档案、案件档案和客户档案的热区删掉，仍可在记忆库「已作废」里看到，也可以从那里恢复，或把同一句再写进档案。已撤回、已取代的句子也会从提示词的案件窗口和可执行偏好里去掉。档案里已经不见的旧句，导入时标成被取代。立场文件再次保存，不会把已经作废的句子写回当前。写法槽在 2400 字预算里先入选。

点名对照旧案时，没有客户编号也会看档案里的姓名。委托人、我方、对方能对上就用；只有甲方和乙方时，诉讼地位单独写明甲方或乙方才定我方。甲乙双方、甲方或乙方这种两边都出现的写法不定我方。对调才排除。诉讼地位没写、姓名也对不上时，不把旧案当成对立。

## 7. 一句话收束

记忆要让人能看见，确认后才成习惯，提示词不灌爆。  
律师用久了会疼的地方是旧话撤不干净、别案会串味、一单让步变成人设。  
这些收在本机记忆库里：失效在读取时执行，档案和案件窗口跟着记忆库走，其他案件不自动混入。
