# LawMind 本机能力方案（对齐 Cursor / Codex）

> **状态**：P0–P3 已落地（2026-09-12）。书签在非沙箱桌面以路径持久化；MAS 沙箱下的 security-scoped bookmark 仍待原生层。工作区外查找命中只回 `hit_id` + 文件名/父目录；律师在待拍板选择允许一次 / 本会话 / 始终后才读正文。
> **律师可见名**：本机能力。  
> **工程名**：Host Access Plane。  
> **用途**：让助手在本机找到材料、读材料、收进本案、跑受控本地命令，能力上对齐 Cursor / Codex，合规上按案件、按目的、只读优先、可撤销。  
> **不是**：关掉沙箱、给助手 root、或把全盘写权交给模型。  
> **交叉引用**：[LAWMIND-ARCHITECTURE.md](../LAWMIND-ARCHITECTURE.md) · [SECURITY.md](../../SECURITY.md) · [GOALS.md](../../GOALS.md) §二铁律 · [LAWMIND-FUTURE-ISSUES.md](../LAWMIND-FUTURE-ISSUES.md) §7

---

## 0. 一句话目标

律师交办时，助手应能像 Cursor 一样在**这台电脑**上定位文件、打开文件、整理进本案、调用本机办公/分析命令；默认仍按**本案材料**干活。越出已选文件夹时必须**看得见、可点选、可撤销**。写入永远不以「全盘」为默认。

对标句：**索引层可全盘只读 → 读取层逐次授权 → 写入层死守工作区。**

---

## 1. 先对齐事实：Cursor / Codex 并没有「全盘魔法」

律师体感「Cursor / Codex 能看见并操作整个电脑」，来自三件事叠在一起，而不是一个「全盘 API」：

| 他们实际有的                                 | 律师体感                            | LawMind 今天                                                                                 |
| -------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------- |
| 用户身份下的 **Shell**（沙箱可关）           | 任意 `find` / `cat` / `rg` / `open` | 无面向助手的本机命令工具；`safeCommand` 只给引擎内部子进程，且 `cwd` 必须落在 `allowedRoots` |
| 工作区多根 + 文件工具（Read / Grep / Write） | 打开的文件夹都能改                  | 仅 **工作区 + 一个项目目录**（`getAllowedRoots`）                                            |
| 高工具预算 + 自动批准                        | 能连翻几十个文件                    | 检索/浏览合计 **4 次/轮**（`DISCOVERY_LOOP_TOTAL_CAP`），多数发现类工具 **1 次**             |
| 代码库索引                                   | 「我记得大概内容」也能搜到          | 工作区 FTS 已有；本机文件名/正文索引没有                                                     |
| 可选 MCP / 本机 helper                       | 权限收在守护进程                    | MCP 只读工具仍走工作区路径栅栏                                                               |

因此「足以跟 Cursor 媲美」的验收不是「模型拿到 POSIX 全盘句柄」，而是律师日常这四句都能办成：

1. 「桌面/下载/论文文件夹里那份 PdZn 材料，找出来并读。」
2. 「把这份文件收进本案。」
3. 「用本机 Word / officecli 打开或处理它。」
4. 「不要去碰别的客户材料，也不要读密钥。」

Cursor 在第 4 句上几乎不做。LawMind 必须做，而且必须做在**网关层**，不能靠提示词。

## 3. 产品形态（律师看见什么）

设置里增加一节 **本机能力**（不要出现 FDA、TCC、bookmark、IPC 等词）。律师只做三件事：

1. **选择本机文件夹**（可多个）：桌面、下载、论文目录、客户材料盘……每个文件夹用系统文件框选出，可撤销。
2. **本机查找**：只记得文件名或一句正文时，先出候选列表，点开才读内容。
3. **越界确认**：助手要读尚未允许的位置时，弹出「允许一次 / 本会话允许 / 始终允许 / 拒绝」。

一级对话不必先学配置。Day-1 默认仍是工作区 +（若已选）本机文件夹。律师说「去我电脑上找」时，助手走本机查找，而不是报「超出工作区」。

现有「项目目录」升级为「本机文件夹」的第一项，兼容旧配置：内部仍可把旧 `projectDir` 当作 `mounts[0]`。

### 3.1 四种本机模式（对律师一句话，对引擎一个枚举）

| 律师说法       | 工程 `hostAccess.mode` | 助手能做什么                                                                                     |
| -------------- | ---------------------- | ------------------------------------------------------------------------------------------------ |
| **仅本案**     | `matter`               | 只碰本案目录 + 工作区公共记忆。默认。                                                            |
| **已选文件夹** | `mounts`               | 再加律师挂上的本机文件夹。日常 90%。                                                             |
| **本机查找**   | `locate`               | 可用系统查找（Spotlight / Windows Search）按**文件名与系统元数据**出候选；**打开正文仍要授权**。 |
| **受控命令**   | `command`              | 在已授权根内跑白名单本机命令（officecli、git、python 分析等）。写仍默认只进工作区。              |

`readonly` / `research` 权限模式禁止本机写入与本机命令；`locate` 仍可用。

## 4. 目标架构：本机能力面

不把「全盘句柄」交给助手。助手只调用工具；所有本机 I/O 经过 **授权网关（Access Broker）**。

```text
律师交办
   │
   ▼
助手工具（search_host / read_host_file / import_host_file / run_host_command）
   │
   ▼
授权网关  ←── 案件围栏 · 硬黑名单 · 书签/系统权限 · 一次/会话/始终
   │
   ├── 查找面    Spotlight / Windows Search / 自建 FTS（只读，可排除）
   ├── 读取面    已选文件夹 + 逐次授权；完全磁盘访问仅可选增强
   └── 写/跑面  默认只写工作区；命令走 safeCommand；全盘写永不默认
```

可选 **本机助手进程**（扩展现有 `lawmindd`，或独立 `lawmind-hostd`）：只暴露 `list / search / read / import`，不把文件系统句柄回传给模型。与「完全磁盘访问」组合时，钥匙在守护进程，不在对话循环。

### 4.1 授权网关是唯一写/读入口

所有路径解析从「单根工作区」升级为「根集合 + 授权」：

| 根类型       | 来源                           | 默认读                              | 默认写                            |
| ------------ | ------------------------------ | ----------------------------------- | --------------------------------- |
| `workspace`  | 工作区                         | 是                                  | 是（仍受写保护清单）              |
| `mount`      | 本机文件夹书签                 | 是                                  | **否**（收进本案 = 复制进工作区） |
| `grant`      | 本轮/本会话/持久授权的单个路径 | 是                                  | 仅当授权写明 `write`              |
| `locate-hit` | 本机查找命中、尚未授权         | **否**（只回文件名/目录/大小/日期） | 否                                |

`resolveWorkspaceRelativePath` 保持给工作区相对路径。新增 `resolveHostPath`（`src/lawmind/host-access/access-broker.ts`）供本机工具使用。`fs-bridge`、`show-item-in-folder`、`open-with-system` 必须走同一套根集合，禁止再写一份 `workspace \|\| project` 判断。

### 4.2 案件围栏（物理拒绝，不是提示词）

会话带 `matterId` 时：

- 工作区侧：继续默认不扫其他 `cases/<otherMatter>/`（现有 `search_workspace` 行为）。
- 本机侧：每个本机文件夹可 **绑到案件**。未绑定 = 仅当前会话可用，且不得写入其他案件目录。
- 跨案绑定必须律师在设置里显式打开「允许对照旧案材料」，且命中后只回**文件名与案件标签**，不回正文；与旧案对照产品原则一致（事实不写入本案）。
- 本机查找命中若落在「已绑定其他案件」的文件夹，网关直接 `cross_matter_denied`，同时可建议走 `check_conflict_of_interest`。

伦理墙最低要求已落地：对立客户的本机文件夹不能同时出现在同一会话的有效根里（读 CASE.md 当事人）。律所级完整墙仍见 FUTURE-ISSUES。

### 4.3 硬黑名单（网关层，不依赖模型）

默认拒绝（路径匹配 + 文件名模式，跟随符号链接解析后的 realpath）：

- `~/.ssh`、`~/.gnupg`、`~/Library/Keychains`、`~/Library/Cookies`
- `**/.env`、`**/.env.*`、`**/id_rsa`、`**/id_ed25519`、`**/*.pem`、`**/*.p12`、`**/*.key`
- 工作区写保护镜像：`lawmind.policy.json`、`audit/`、`sessions/`、钥匙串与 `mail-secrets.json`
- 其他客户案件目录（见 4.2）
- 策略可加：`hostAccess.denyPathPatterns`

黑名单不可被「始终允许」覆盖。律师要读某份误落在黑名单里的材料，只能先把文件复制到本机文件夹或本案目录——这是有意的摩擦力。

### 4.4 本机命令（「操作电脑」的真实含义）

Cursor 的「操作电脑」= 用户身份 Shell。LawMind 对齐的是**律师办公操作**，不是通用系统代理。

| 档          | 命令面                                                                                                    | 何时可用                 |
| ----------- | --------------------------------------------------------------------------------------------------------- | ------------------------ |
| L0 默认     | 无本机命令；`run_analysis` 仍按现策略                                                                     | 所有人                   |
| L1 办公     | 白名单：随包 `officecli`、系统打开（已有 `open-with-system`）、`mdfind`/`mdls`（macOS）、Windows 等价查找 | 已选文件夹或已授权路径   |
| L2 工作副本 | 再加 `git`（只在已选文件夹 / 工作区）、受控 `python`（复用 `allowAnalysisScripts`）                       | 设置打开「允许本机命令」 |
| L3 会话命令 | 律师对本会话点「本机命令：本会话允许」后，可跑额外二进制；仍禁止 shell 元命令、仍过黑名单与 `safeCommand` | 明确确认；Firm 默关      |

硬禁（与 `safeCommand` 已禁项对齐并扩展）：`sh` / `bash` / `zsh` / `cmd` / `powershell`、`sudo`、`osascript` 默认、任意 `curl|wget` 向非 allowlist 出口。参数必须数组化，禁止拼接命令行。

**全盘写、装软件、改系统设置、控制其他 App 窗口：不做。** 那不是 Cursor 律师场景的核心，也不是 LawMind 的交付。

## 5. 工具契约（助手侧）

现有 `read_project_file` / `search_workspace` / `analyze_document` 保留，内部改为走授权网关的根集合。新增四个工具，避免把「本机」语义偷偷塞进旧工具：

| 工具               | 作用                                                                                             | 批准                                                |
| ------------------ | ------------------------------------------------------------------------------------------------ | --------------------------------------------------- |
| `search_host`      | 在有效根 +（可选）系统查找中搜文件名/正文；默认只回 `hit_id`、文件名、父目录、大小、日期、短摘要 | `locate` 出工作区外命中时，不回绝对路径，正文须授权 |
| `read_host_file`   | 读单个已授权文件（大小上限沿用 `MAX_TEXT_READ_BYTES` / 图像上限）                                | 根外用 `hit_id` → 待我拍板（一次/会话/始终）        |
| `import_host_file` | 复制进 `cases/<matterId>/…`，成为本案材料                                                        | 默认允许（写的是工作区）；目标不得逃出本案          |
| `run_host_command` | L1–L3 本机命令                                                                                   | L1 可按策略预批准；L2/L3 走 `dangerous_tool_gate`   |

只读权限模式下：`search_host` / `read_host_file` 可用，后两个禁用。

### 5.1 文件密集交办的配额

今日 4 次发现上限是为了打断「已有钉选路径还在空翻」的死循环，不是本机能力的产品上限。

拆成两本账：

| 账本                             | 默认                           | 本机查找/多文件交办                                                                               |
| -------------------------------- | ------------------------------ | ------------------------------------------------------------------------------------------------- |
| 旧发现工具合计                   | 仍 4（钉选路径已知时保持刹车） | 会话声明 `host_file_task` 后不计入本机工具                                                        |
| `search_host` + `read_host_file` | 每轮 12 / 单工具 8             | 软预算；触顶问「是否继续」，硬顶防 runaway（建议 32，低于 `agentMaxToolCallsPerTurn` 的 50 封顶） |

已知钉选/附件路径时，继续用现有 `discoveryStopHint`，不要鼓励再扫盘。

## 6. 桌面与系统权限

### 6.1 macOS：书签是默认，完全磁盘访问是增强

1. **本机文件夹**用 `NSOpenPanel`（Electron `dialog.showOpenDialog`）选出，主进程保存 **security-scoped bookmark**，启动时 `startAccessingSecurityScopedResource`。沙箱下这是唯一合规的持久读权。
2. **完全磁盘访问**只作为 Doctor / 本机能力里的可选开关：系统设置深链 + 「已开启 / 未开启」状态。默认关。开启后仍过授权网关与黑名单，**不**等于助手可遍历全盘正文。
3. 未开完全磁盘访问时，本机查找仍可用 Spotlight（`mdfind`）做**元数据**命中；读 Desktop/Downloads 等受保护目录必须先有书签或当次授权。

### 6.2 Windows / 后续

书签等价物：用户选出的目录 ACL + 应用保存的根列表。查找先接 Windows Search（`Windows.Storage.Search` 或 `es.exe` 仅在已授权时）。完全磁盘访问无直接对应；「以用户身份读用户配置文件」即可，仍过网关。

### 6.3 本机索引（第二步，不是第一步）

| 阶段 | 引擎                                           | 存什么                                          | 不存什么                            |
| ---- | ---------------------------------------------- | ----------------------------------------------- | ----------------------------------- |
| B0   | `mdfind` / Windows Search                      | 不落库，当次查询                                | 正文                                |
| B1   | 自建 FTS（复用 `indexing/fts-ingest.ts` 模式） | 文件名、扩展名、mtime、可选正文（律师勾选的根） | 黑名单、密钥、未绑定的其他案件根    |
| B2   | 增量 + 大文件抽取（PDF/DOCX 走现有解析）       | 分段正文                                        | 默认不抽图/音视频；单文件上限策略化 |

索引文件放在 **应用支持目录**（按书签 id 分库），不要写进客户工作区，避免把全机目录清单提交进案件包。排除规则与历史扫描的 `SKIP_DIR` 对齐，并加上 4.3。

目的限定：索引只为「定位本案材料」。Firm 不得把本机索引做成跨所检索。

## 7. 落地顺序（按 ROI）

### P0 — 日常 90%（先做，对齐「挂上文件夹就能读 PdZn」）

1. 多根：`getAllowedRoots` / `fs-bridge` / `lawyer-local-file` / `show-item-in-folder` 改为 N 个 `mounts`；旧 `projectDir` 迁移为第一项。
2. 设置 UI：本机文件夹（添加 / 撤销 / 可选绑定案件）。macOS 持久化 security-scoped bookmark。
3. 本机查找 B0：`search_host` 调 `mdfind`（无则退回在 mounts 内按文件名走）；命中在 mounts 内可直接 `read_host_file`。
4. 文件密集配额：本机工具单独账本（§5.1）。
5. 律师文案：项目目录 → 本机文件夹。

**P0 完成即**：律师挂上论文所在文件夹后，下一轮能直接读。这是 Cursor「打开那个文件夹」的等价物。

### P1 — 「我只记得大概内容」

1. 授权弹层：一次 / 本会话 / 始终（读）；写默认不可选。
2. 本机查找可出 mounts 外的 Spotlight 候选（仅元数据）。
3. `import_host_file` + 对话里「收进本案」。
4. 硬黑名单单测 + 符号链接逃逸单测。
5. `check_conflict_of_interest` 对「本机文件夹绑定的案件」做提示（仍律师终判）。

### P2 — 「也能操作这台电脑」（办公级，不是 root）

1. `run_host_command` L1/L2 + 设置「允许本机命令」。
2. 可选完全磁盘访问（Doctor），只增强查找/读，不改写默认。
3. 本机 FTS（B1），增量更新，排除规则。
4. 本机助手进程：只读 API；引擎不再自己扫受保护目录。
5. Windows 查找适配。

### P3 — 律所

1. 伦理墙：对立客户本机文件夹不能同会话生效。
2. 本机访问日志（供撤销与安全调查，**不**写成「可信证明」；见 GOALS §二「关于可审计」）。
3. 管理策略：Firm 可关 L3、可强制 `matter` 模式、可下发 deny 列表。

历史扫描的 3 根上限与本机文件夹是不同产品：前者是「导入旧习惯」，后者是「日常本机能力」。不要把 `MAX_SCAN_ROOTS = 3` 直接当成 mounts 上限；建议 mounts **16**，扫描仍保持 3，除非单独改历史扫描产品。

## 9. 配置项（`lawmind.policy.json` → `hostAccess`）

```json
{
  "hostAccess": {
    "mode": "mounts",
    "maxMounts": 16,
    "spotlightEnabled": true,
    "fullDiskAccessOptIn": false,
    "allowHostCommands": false,
    "hostCommandLevel": "office",
    "fileTaskReadBudget": 12,

    "denyPathPatterns": [],
    "allowCrossMatterMounts": false,

  }

```

| 键                       | 默认     | 说明                                           |
| ------------------------ | -------- | ---------------------------------------------- |
| `mode`                   | `mounts` | 见 §3.1；未选任何本机文件夹时实际等同 `matter` |
| `maxMounts`              | `16`     | 持久书签上限                                   |
| `spotlightEnabled`       | `true`   | 本机查找 B0                                    |
| `fullDiskAccessOptIn`    | `false`  | 只表示律师可在 Doctor 打开；不是已授权         |
| `allowHostCommands`      | `false`  | L1+ 总开关                                     |
| `hostCommandLevel`       | `office` | `office` \| `workspace` \| `session`           |
| `fileTaskReadBudget`     | `12`     | 本机读/找软预算                                |
| `fileTaskReadHardCap`    | `32`     | 防 runaway                                     |
| `allowCrossMatterMounts` | `false`  | 同会话绑多个案件根                             |
| `indexBodyInAppSupport`  | `true`   | 正文索引不进工作区                             |

环境变量只作开发覆盖：`LAWMIND_HOST_ACCESS_MODE`、`LAWMIND_HOST_COMMANDS=1`。打包版忽略「跳过网关」类开关（对齐 `LAWMIND_SKIP_API_AUTH` 已被打包忽略）。

## 11. 律师场景三条风险（比技术更硬）

1. **利益冲突 / 保密**：全盘查找可能碰到其他客户材料。同一会话不得读取「已绑定其他案件」的根；对立客户根不能同时生效。这是物理拒绝。`check_conflict_of_interest` 只是提示，不能代替围栏。
2. **个人信息最小必要**（《个人信息保护法》）：本机索引按目的限定为「定位本案材料」。排除规则先于入库。不能「先全存再过滤」。
3. **密钥与凭证**：§4.3 硬黑名单。始终允许也不能打开。误放在桌面的 `.env` 同样拦；律师应先复制到本案再作为材料。

能力上可以让助手看见很大一块本机磁盘；合规上必须让它**按案件、按目的、只读、可撤销**地看见。否则赔的是一整个所的信誉，不是一次工具报错。

## 12. 明确不做（否决清单）

- 建议律师关掉 App Sandbox、给助手 root、或长期全盘写权。
- 用提示词代替案件围栏或密钥黑名单。
- 把本机索引或全盘路径写进可外发的案件包。
- 把「可审计」当成「本机能力很安全」的广告（GOALS §二）。
- 像素级操控其他图形界面（那是另一类产品，不是 Cursor 律师工作的核心）。
- 为了对齐 Cursor 而拆掉 `safeCommand` 的禁 shell 与出口代理。

## 14. 和「四条路线」的关系

前序讨论里的 A/B/C/D 都保留，只是收成一条产品，而不是四套并行权限：

| 路线                      | 本方案中的位置                             |
| ------------------------- | ------------------------------------------ |
| A 多根关联 + 书签         | **P0 主干**                                |
| B 本地索引 / Spotlight    | P0 用 B0；P2 上 B1                         |
| C 完全磁盘访问 + 授权网关 | 网关是全程主干；完全磁盘访问是 P2 可选增强 |
| D 本机助手进程            | P2，与 C 组合；钥匙不进对话循环            |

一句话：**先做成 Cursor 的「多文件夹 + 能找能读」；再做成 Cursor 的「能跑本机命令」；永远不做成「无围栏的用户 Shell」。**
