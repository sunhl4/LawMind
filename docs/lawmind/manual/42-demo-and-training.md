# 第 42 章 试用、演示与培训准备

这一章给要给别人演示 LawMind、或者给团队做培训的人看。

## 42.1 演示前必须做的三件事

### 第一件：准备演示用的工作区

**不要用真实案卷演示。** 准备一个独立工作区：

```bash
LAWMIND_WORKSPACE_DIR=/tmp/lawmind-demo pnpm lawmind:seed:desk
```

它会灌三个示例案件：

| 案件 id             | 类型         | 用途                             |
| ------------------- | ------------ | -------------------------------- |
| `xinghui-sale-876`  | 诉讼卷宗     | 演示案件工作台、期限、开庭倒计时 |
| `xinghui-nda-2026`  | 轻量合同案件 | 演示合同审查                     |
| `lianhua-sale-2022` | 已结案       | 演示相似案件召回                 |

**幂等**，重复跑会跳过已有行。

### 第二件：验证模型连通

```bash
pnpm lawmind:env:check --strict
```

**演示最尴尬的失败是模型连不通。** 提前验一次。

### 第三件：想清演示哪三条

演示不能贪多。建议固定三条：

| 演示什么           | 为什么选它                     |
| ------------------ | ------------------------------ |
| 一句话交办出草稿   | 最能体现「不用选办件」         |
| 丢一份合同出修订轨 | 最能体现「最短改动」这个差异化 |
| 外发停在待我拍板   | 最能体现「只有真授权才打断」   |

**三条足够**。其余的作为问答时的补充。

## 42.2 演示脚本（约 15 分钟）

### 开场（1 分钟）

一句话说清定位：**本机运行的律师工作台，交办之后一路办到可交付的东西。**

关键强调：**数据不出本机**（除非你配了法源、模型 API 这些必要的外部连接）。

### 第一段：一句话交办（4 分钟）

```text
操作：在对话里说「查一下民法典关于违约金过高的规定，写个备忘」
```

**看什么**：

- 状态条显示「本轮按检索研究处理」（**不用你选**）。
- 「在办」里能看到它在跑。
- 产出结构化备忘：**规格要求的最少六节**是事项、命题矩阵、现行法条、正向类案、反向类案、结论；生成器实际会多出**效力层级、来源边界、缺口**三节（共九节）——演示时看到九节不用奇怪。

**要讲的点**：

- 它不会中途问「要不要继续」。
- 引用的栏目即使没查到也会保留，并标【待核实】。

### 第二段：改稿（6 分钟）

```text
操作：拖入一份合同 → 说「审一下违约责任，能改的直接改」→ 打开改稿面
```

**看什么**：

- 审查意见（风险指向具体条款，建议给推荐措辞）。
- 红线面板里每处改动是**最短锚点**（比如只改「30 日」→「45 日」）。
- 导出带修订轨的 Word。

**要讲的点**：

- 原文件一个字节都不动。
- 整句改写会先收成最短锚点再落稿。收不成、查找串仍超过 60 字的，Word 插件不计这一处，回桌面改稿看。空修订不许导出。
- 空修订不许导出。

**如果时间紧**：只演示「红线面板里改动是最小化的」这一件事，冲击力最大。

### 第三段：只有真授权才打断（4 分钟）

```text
操作：说「把这封信发给对方律师」
```

**看什么**：停在「待我拍板」，显示「先核对收件人再发」「系统不会自动发送」。

**要讲的点**：

- 整场演示里，这是**唯一**一次它停下来问你。
- 审批卡片上的风险等级是「高」。
- 如果配了伦理墙，还会做冲突检查。

## 42.3 演示时容易被问的三个问题

### 「它会不会胡说八道？」

回答要点：

1. 引用必须能回溯到检索结果或材料（对不上会被拦）。
2. 查不到就标【待核实】，不编条号。
3. 每格要么有出处要么明说「无法判断」。
4. 独立审稿在另一个会话跑，写手看不到审稿意见。

**可以现场演示**：看某条引用的预览（含「支撑了哪些结论、被哪些章节引用」）。

### 「它会不会自己发出去？」

回答：**不会**。只要有外发，就停下来等你点。

**可以现场演示**第三段。

### 「它能替代律师吗？」

回答要点（也是产品立场）：

- 它顶的是「一稿」，不是「终稿」。
- 必核清单和签批是两道律师门。
- 高风险交付物要过独立审稿。
- 界面上明确写着「通过核对 ≠ 法律正确」。

## 42.4 培训课的结构建议

给团队做培训，建议压到 60 分钟，四段：

| 段  | 时长    | 讲什么                                                                                 |
| --- | ------- | -------------------------------------------------------------------------------------- |
| 一  | 10 分钟 | 顶栏两个：对话、工作台；拍板点「待我拍板」。改稿从手头的事进去。只有外发和改原稿会打断 |
| 二  | 20 分钟 | 现场走一遍「交办 → 审核 → 签批 → 导出」                                                |
| 三  | 15 分钟 | 记忆要确认才写入；口径怎么配                                                           |
| 四  | 15 分钟 | 答疑 + 让他们自己试一条                                                                |

**第二段一定要让他们自己动手。** 看别人操作和自己操作的差别很大。

## 42.5 培训必须讲清的五件事

这五件是「不讲清就会反复问」的：

| 讲什么                                    | 为什么必须讲                           |
| ----------------------------------------- | -------------------------------------- |
| 外发和改原稿才会打断                      | 不讲清会被认为「它怎么不问就做了」     |
| 记忆要确认才写入                          | 不讲清会被认为「它怎么知道我偏好这个」 |
| 必核清单和签批是两道门                    | 不讲清会觉得「为什么要我点两次」       |
| 待我拍板在侧栏                            | 不讲清会找不到待决策的事               |
| 顶栏两个入口 +「待我拍板」怎么进改稿/签批 | 不讲清会在界面里迷路                   |

## 42.6 一份「试用第一周」的安排

如果对方要试用一周，可以这样安排：

| 时间      | 做什么                                     |
| --------- | ------------------------------------------ |
| 第 1 天   | 装、连模型、走首跑、跑两个练习（第 25 章） |
| 第 2 天   | 建一个真实案件，灌一份真实材料（脱敏后）   |
| 第 3 天   | 走一次完整的「审 → 改 → 签 → 导」          |
| 第 4 天   | 配一条自动化                               |
| 第 5 天   | 回顾：看一次记忆库，确认几条建议           |
| 第 6–7 天 | 自由使用；记下问题                         |

**第 5 天那一步很重要**：它让「越用越贴」这件事被感知到。

## 42.7 演示用的五个「不要」

| 不要                     | 因为                                                  |
| ------------------------ | ----------------------------------------------------- |
| 不要在连不通的模型上演示 | 最尴尬的失败                                          |
| 不要用真实案卷           | 隐私 + 万一出错无法解释                               |
| 不要一次演示十个功能     | 记不住，重点被稀释                                    |
| 不要演示没配好的功能     | 比如没接法源却演示「查真法条」                        |
| 不要绕过门禁演示         | 绕过验收/空修订这些演示一次，就毁了「它可信」这个印象 |

## 42.8 如果对方问「和竞品比怎么样」

有用的回答框架（**不要只讲功能数量**）：

| 维度 | LawMind 的立场                                 |
| ---- | ---------------------------------------------- |
| 部署 | 本机优先；不把案卷上传                         |
| 交件 | 修订轨、最短改动、引用要能核到                 |
| 边界 | 只有外发和改原稿打断                           |
| 诚实 | 查不到就说查不到；不发明分数                   |
| 学习 | 未确认零写入                                   |
| 合规 | 内容端到端加密，密钥不出本机；审计只按义务留存 |

**避免的**：吹功能数量、吹「可审计」当卖点（产品自己都不这么做，第 1 章）。

## 42.9 培训之后留什么

建议留四份东西：

| 留什么             | 内容                                            |
| ------------------ | ----------------------------------------------- |
| 一页速查           | 顶栏对话/工作台 +「待我拍板」+ 三条常用交办话术 |
| 常见问题           | 从第 38 章挑十条最相关的                        |
| 联系人             | 出问题找谁                                      |
| 一份「试试看」清单 | 五个具体练习（第 25 章那些）                    |

**一页速查最有用。** 内容建议就这么几行：

```text
交办：直接说事，或者拖材料进来
看结果：在「改稿」
需要我决定：侧栏「待我拍板」
它什么时候会问我：发给外面，或要改原稿
它记住什么：我在「记忆库」确认过的
```

## 42.10 已知坑（本章相关）

- **演示前一定验模型连通。**
- **别用真实案卷演示。** 用演示数据。
- **别演示没配好的功能。**
- **别绕过门禁演示。** 那会毁掉信任。
- **「可审计」不是卖点。** 产品自己都明确不这么宣传。
- **不要只讲功能数量。** 讲交付、边界、诚实这三件事。
- **培训要让他们动手。**
- **一页速查比长文档有用。**
