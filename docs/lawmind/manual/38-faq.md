本章收录使用与开发中反复出现的问题。按主题分组，每条两三句话。

## 38.1 上手与安装

**Q1：一定要装桌面应用吗？能不能用浏览器？**

一定要桌面应用。产品只有这一种形态。`http://127.0.0.1:5174` 只是 Electron 渲染进程的来源，不是网页版工作台。

**Q2：Node 版本要求？**

22.16 以上（`.nvmrc` 写的是 `22`）。pnpm 用 10.23.0。

**Q3：`pnpm install` 之后 Electron 起不来怎么办？**

pnpm v10 可能跳过了 Electron 的 postinstall。跑 `pnpm approve-builds`（允许 `electron`）再 `pnpm install` 一次。

**Q4：数据放在哪？**

应用数据在用户数据目录下的 `LawMind/`（macOS 是 `~/Library/Application Support/LawMind`），工作区默认在其下的 `workspace/`。

**Q5：能换工作区位置吗？**

能。设置 → 工作区，或者首跑向导里选。但**别放同步盘**（尤其开案件副本时会有两套同步叠加）。

**Q6：打包版和开发态有什么区别？**

开发态渲染层来自 Vite（5174），本地服务用 `tsx` 跑 TS；打包态渲染层是 `file://` 下的 `dist/`，本地服务是打包过的 CJS，而且**sandbox 打开、`LAWMIND_SKIP_API_AUTH` 被忽略**。

**Q7：macOS 提示「无法验证开发者」？**

未公证的包需要右键 → 打开。正式包应该是 Developer ID 签名 + 公证过的。

## 38.2 模型与配置

**Q8：API Key 存哪？**

系统密钥链（服务名 `ai.lawmind.desktop`）。存完之后会从 `.env.lawmind` 里抹掉明文。

**Q9：为什么保存 Key 失败？**

系统加密存储不可用（`safeStorage.isEncryptionAvailable()` 返回假）。要么启用密钥链，要么手工写环境文件。**不要**改成明文保存。

**Q10：换了 Key 好像没生效？**

环境变量文件的优先级**高于**密钥链。检查 `.env.lawmind` 里那 8 个明文键还在不在。

**Q11：支持哪些模型？**

任何 OpenAI 兼容接口。内置了通义千问、DeepSeek、GLM、Moonshot、硅基流动的预设。法律垂类模型（ChatLaw / LawGPT / LexEdge）可以配成专用通道。

**Q12：模型报 502 / 连不通？**

依次查：Base URL 和模型名、网络白名单、代理环境变量（只支持 http 代理）、企业自签 CA、密钥是否失效。命令行可以用 `pnpm lawmind:env:check --strict`。

**Q13：`lawmind.policy.json` 配了不生效？**

最常见的原因是**缺 `schemaVersion: 1`**（整份文件会被忽略）。其次确认文件在工作区**根**，不在 `lawmind/` 里。然后看体检页的 `policy.applied`。

**Q14：策略文件和工作区里的 `lawmind/` 目录什么关系？**

没关系。`lawmind.policy.json` 在工作区根；`lawmind/` 是引擎的状态目录。

## 38.3 对话与回合

**Q15：为什么它不问我要不要继续？**

设计如此。只有外发、改原稿这类真授权才打断。中间步骤（列目录、检索、分析）不问。

**Q16：想让它先给方案怎么办？**

指令里明说「先给我看方案，我确认后再写」。

**Q17：对话变长了它好像忘事？**

触发了上下文压缩（compact）。对话里会有压缩提示。想避免就用「承前分叉」另起一段。

**Q18：怎么知道上下文用了多少？**

输入框工具栏的上下文用量表。它按桶显示（律师/助手/工具结果/摘要/钉选等）。

**Q19：为什么有时候很快就被压缩？**

通常是「钉选」或「工具结果」桶太大。看用量表确认。

**Q20：能中途改指令吗？**

能。回合进行中继续输入会作为「律师中途指示」排队，在下一次模型采样前生效。

**Q21：点了停止会怎样？**

有进度 → 暂停（可以接着跑）；没进度 → 报「已停止生成」并丢弃那条用户消息。

**Q22：会话能跨对话检索吗？**

能。`search_conversations` / `read_conversation`，或者 `⌘⇧O` 搜侧栏。

## 38.4 意图与能力

**Q23：怎么知道它把这句当成什么任务了？**

对话顶部的状态条会显示「本轮按××处理」。排查时看 `intent` 事件的 `source` 字段。

**Q24：能强制指定能力吗？**

能。写 `$skill contract.review`，或者「【办件】能力：contract.review」。

**Q25：一句话里有两件事怎么办？**

编译器会输出 `chain` 并预填两步清单。它不是工作流，只是顺序提示。

**Q26：为什么把起诉状当合同审了？**

理论上不该发生（诉状头会压过正文里的「合同」二字）。如果遇到，这是致命误绑，值得报告——金标集里有专门的用例守这条。

**Q27：怎么看有哪些能力？**

对话里说「有哪些能力」，或者让模型调 `list_more_tools`。也可以读第 22 章。

## 38.5 工具与审批

**Q28：为什么绝大多数动作都不问我？**

因为只有 `send_email` 会机械暂停。其他写工具只是被审计。治理里的 `lawyer_approved_write` 是**分类**，不是弹窗开关。

**Q29：批准的审批能复用吗？**

按工具名匹配（同一会话同一案件）。但 `apply_surgical_edits` 和 `prepare_outbound_mail` 是**参数绑定**的：改了参数就要重批。

**Q30：审批有有效期吗？**

显示上有 24 小时。不会自动批掉。

**Q31：审批缓存会被模型伪造吗？**

不会。`__approved` 是服务端专用标记，模型传来的会被剥掉。

**Q32：为什么某个工具说「需要绑定案件」？**

它在 `MATTER_SCOPE_REQUIRED` 里（15 个）。先在工作台选案件，或者在对话里指定案件。

**Q33：工具调用次数有限制吗？**

有三层：本轮总预算、检索/列表类的单工具限额 + 总量上限（8–32，按上下文伸缩）、本机文件类的限额（12–48）。

**Q34：`list_more_tools` 是干什么的？**

渐进披露的入口：返回可启用的能力清单（含中文说明），启用后进入本会话的已披露集合。

## 38.6 改稿与导出

**Q35：它会改我的原稿吗？**

不会。改稿路径是「拷副本 + 在副本上落修订轨」，原文件一个字节都不动。

**Q36：最短改动是怎么保证的？**

一处改动里夹了 ≥6 个连续未改文字就算未最小化，引擎会**重算**（不是拒绝）。算法是反复摘最长公共片段。

**Q37：导出的 Word 里为什么有整句删+整句增？**

说明某处没被最小化。可能来自历史遗留的 section 级 hunk，或者落盘时歧义跳过。看 `redline-plan.json` 的 `skipped`。

**Q38：提示「尚无待叠加修订」？**

空修订门在起作用（至少要有 1 处改动）。先真的落改，再导出。不要绕过。

**Q39：改了正文之后红线乱了？**

hunk 的 `before` 是相对**基线**的。用「重置基线」按钮。

**Q40：导出到哪里？**

顺序是：点名的三个文件夹（桌面/下载/文稿）→ 显式路径 → 源文件旁边 → 案件 `artifacts/` → 项目目录 → 工作区 `artifacts/`。第一个匹配的赢。

**Q41：文件名为什么带日期？**

规则是「标题_YYYYMMDD_01」，冲突递增。不用任务哈希（对人没意义）。

**Q42：引擎会自动打开 Word 吗？**

不会。`openWord: false` 是刻意的。

## 38.7 Word 插件

**Q43：窗格报「无法加载该加载项」？**

先确认用的是 `localhost` 而不是 `127.0.0.1`（IPv6 问题），再看体检页的端口漂移提示。修法是用「重新侧载 Word 清单」，然后**完全退出 Word 再打开**。

**Q44：窗格报 `unauthorized`？**

窗格持有旧凭据。重开窗格让它重新取（从同源 `config.js`）。

**Q45：点了「审这份」一直转圈？**

看 `reviews.json` 里那条的状态。最常见真因是**模型调用失败**（比如 key 失效）。`running` 超过 30 分钟会被自动标成 `failed`。

**Q46：插件说「回桌面端看」？**

这次有整节重写（锚点超过 60 字），插件不处理。去改稿工作面处理。

**Q47：文件在点击后被改过？**

会转 `stale`，提示重新点一次。这是为了防止用旧基线出稿。

**Q48：能在 Word 里发送邮件吗？**

不能。插件的预批准名单刻意不含 `prepare_outbound_mail`，而且 Word 回合内 `render_document` 被工具自身拒绝。

## 38.8 检索与法源

**Q49：为什么查不到法条？**

看体检页的法源状态。`sample-ready` 表示只有演示语料。要更多得配语料或接端点。

**Q50：结果里说「演示语料」是什么意思？**

不是正式完整法库，只是演示检索管线用的样本。**未标注来源的外部语料一律按演示处理**（保守默认）。

**Q51：为什么查不到类案？**

本机没接类案库。系统只探测本机（不主动捅公网），而且**不会编案号**。

**Q52：跨案先例库怎么开？**

`LAWMIND_ALLOW_CROSS_MATTER_SEARCH=1`，然后**重建索引**。默认关是伦理墙姿态。

**Q53：搜不到工作区里的东西？**

索引陈旧。看 `doctor.searchIndex.staleReason`。重建需要 `LAWMIND_ALLOW_INDEX_REBUILD=1`。

**Q54：材料检索的页码准吗？**

来自抽取时的定位。扫描件走 OCR 的条目页码可能不准——这是 OCR 的固有不确定性。

**Q55：为什么要求先检索再写引用？**

因为模型记忆里的法条经常是错的。协议要求写条号前先试检，没检到就标【待核实】。

## 38.9 记忆与学习

**Q56：它会自动记住我的偏好吗？**

不会。所有学习都以「待确认建议」形式排队，你确认才落盘。

**Q57：为什么有「批量采纳」？**

因为逐条点确认在实践中没人坚持。批量只包含低风险的风格类。

**Q58：某条建议采纳了但好像没生效？**

看它的 state 是不是 `recorded_noop`——那表示没有对应的落盘面。系统不会假装写过。

**Q59：档案里的空模板会注入吗？**

不会。空模板（没填身份字段、也没有真积累）不注入。

**Q60：§八 轮转会让我丢东西吗？**

不会。最早的条目挪到 `lawyer-profile-archive.md`，不删除。而且轮转不影响模型行为（模型只看 800 字指纹）。

**Q61：技能好像没生效？**

看 `GET /api/skills` 里那条的 `enabled` 和 `signatureOk`。签名失败是**静默的**。

**Q62：改了技能文件但行为没变？**

你改的可能是工作区里那份（播种产物）。要改仓库里的 `src/lawmind/skills/builtin/`。

**Q63：立场库里的东西为什么不生效？**

三个门槛：置信度衰减后 ≥0.4、证据跨至少 2 个不同案件、冲突检查通过。

**Q64：历史扫描的习惯为什么没出现？**

习惯要出现 **≥5 次** 才入队。

## 38.10 案件与工作台

**Q65：新案件为什么是「收案」不是「进行中」？**

只有勾了「利益冲突检查完成」和「委托确认」两项，状态才进 `active`。

**Q66：对话里说的事为什么工作台看不到？**

可能是「写了等于没写」——检查 `intake-brief.json` 和 `matter.json` 是否一致，确认 `apply_intake_brief` 真的跑了写穿。

**Q67：CASE.md 和 matter.json 不一致怎么办？**

`pnpm lawmind:ops matter-consistency` 查，`pnpm lawmind:ops matter-repair-projection` 修。注意叙事小节不回写 JSON，不算漂移。

**Q68：当事人填不全，第 9 个人不见了？**

历史上限是 8，现在改成 32 了。升级即可。

**Q69：期限不提醒？**

检查三点：是不是未释放（有前置没完成）、`remindBeforeHours` 是不是太大、守护进程在不在跑。**开庭期限永远提醒**。

**Q70：传票抽出来的日期不对？**

抽取是启发式，写进工作台前要确认。不要改阈值让它「别猜」——它本来就不写。

**Q71：能撤销刚才的档案写入吗？**

能。说「撤销刚才那次写入」，依赖 `desk-writes.jsonl`。

**Q72：材料列表为什么不算哈希？**

为了打开快。只有案件副本发布时才算。

## 38.11 审查表与队列

**Q73：「无法判断（证据不足）」是什么意思？**

抽不动时的**显式弃答**。这是诚实交付，不算缺陷（验收口径里明确区分了「弃答」和「缺出处」）。

**Q74：为什么有格子是空的？**

两条路：弃答（写了固定文本）或者材料里确实没有。

**Q75：锁定行会被重抽覆盖吗？**

不会。这是有意的。

**Q76：两次跑出来的表一样吗？**

一样。行序按**路径升序**排（不是按 mtime），所以可复现。

**Q77：审查表和案件审查矩阵有什么区别？**

审查表是**某个任务的交付物**（有出处、可导出）；案件矩阵是**案件层面**从现有文本摘录的对照（只能在界面上批注）。

**Q78：矩阵里为什么有些格是空的？**

因为关键词没命中，故意留空——「不要往每列都塞文档开头那段」。

**Q79：专案组的安全分能看吗？**

界面上不展示。那是内部排序信号，不是质量证明。界面显示的是真实的运行时统计。

**Q80：专案组是真调模型吗？**

打包的串行执行器是**启发式**的，不调模型（为了可复现）。并行那条路是给律所版留的。

## 38.12 自动办件与邮件

**Q81：为什么建自动化要填六项确认？**

因为自动化最容易出「你以为它会干 A，实际它在干 B」的问题。期望结果和审批边界会进任务书。

**Q82：通知策略选了「从不通知」还会收到吗？**

会。**失败和待拍板永不静默**，这条不受通知策略影响。

**Q83：缺资料时会怎样？**

默认「出部分结果并报告」。另有「当失败报」和「安静跳过」两档。

**Q84：同一个附件被反复处理？**

历史上出现过（门禁停住但律师看不到，于是重派）。现在有派发台账 + 待处置项。

**Q85：邮箱能用哪个？**

内置了 Gmail / Outlook / Microsoft 365 / QQ / 163 / 自定义 IMAP 六种预设。

**Q86：邮箱密码怎么存？**

AES-256-GCM 加密存 `mail-secrets.json`（0600）。v1 明文会自动迁移。

**Q87：为什么非标准端口的 IMAP/SMTP 被拒？**

安全默认（对齐 MCP 的 `allowInsecureHttp` 先例）。要放行得显式开并有警告。

**Q88：换邮箱密钥要注意什么？**

**先导出邮箱配置**。因为换密钥后旧密文解不开，而系统拒绝覆盖解不开的密文。

## 38.13 协作

**Q89：邀请同事后他看不到案件？**

查四件事：中继配置一致吗、邀请码过期没（14 天）、对方接受了吗、版本是不是 firm 且开了 `matterReplicaCollab`。

**Q90：为什么出现「（冲突）」文件？**

两个人改了同一个文件。后写胜出，输的那份改名保留——**两份字节都在磁盘上等人来合**。

**Q91：为什么不做自动合并？**

因为两份法律文件不该机器裁决。代码注释写明「Not a CRDT」。

**Q92：同步报「完整性拒绝」？**

接收端重算哈希和清单不符。让对端重新发布。**不要**去掉哈希校验。

**Q93：中继能看到内容吗？**

看不到。端到端加密，密钥永不出本机。但**中继能丢包和重放操作**（op 还没有签名）。

**Q94：移除成员后会怎样？**

做密钥轮换，把被移除的人挡在后续内容之外。

**Q95：会议室和普通对话有什么不同？**

同一套回合，只是多跑几轮、共享一条时间线，并且记录注明「非对外法律意见」。

## 38.14 排障与运维

**Q96：某个报错看不懂？**

把报错原文在仓库里搜——文案通常就在代码里，附近有解释。

**Q97：怎么收集诊断信息？**

体检页截图（或 `pnpm lawmind:doctor --json`）+ 诊断包（脱敏 zip）+ 相关审计导出。

**Q98：会话历史损坏怎么办？**

`pnpm lawmind:doctor --fix`（修工具调用配对）。

**Q99：升级后一堆 404？**

`pnpm lawmind:bundle:desktop-server` 然后重启。

**Q100：怎么备份？**

`LAWMIND_WORKSPACE_DIR=<工作区> bash scripts/lawmind/lawmind-backup.sh <路径>`。默认不含环境文件（防密钥泄漏）。**它不是 `pnpm` 脚本**（`package.json` 里没有这个入口）。

**Q101：换机器要注意什么？**

密钥链是**本机**的，所以模型 Key、技能签名密钥、审计链密钥、邮箱密钥都要重配。工作区备份恢复后重建索引即可。

**Q102：能多人用同一台机器吗？**

不建议。工作区是「同一时刻一个写者」的设计。多人走案件副本那条路。

**Q103：审计能删吗？**

不要删**中间**某天——哈希链是按顺序连的，删了会断。

**Q104：审计里为什么看不到查询内容？**

**刻意不记** query 和 body（查询词本身就是敏感信息）。

**Q105：法源调用太多会不会有问题？**

NPC 有节流（1.5 秒间隔 + 5 分钟缓存）。用量可以在体检页看（`doctor.authorityUsage`，只记次数不记内容）。

## 38.15 开发相关

**Q106：改提示词能调效果吗？**

不建议。这个系统里调效果的正确做法是配偏好、配 playbook、确认记忆、用明确的话术。

**Q107：改编排器要做什么？**

必须加 cassette（`turn-orchestrator-cassettes.test.ts`）。断言下一次请求体，不要断言提示词里的中文句子。

**Q108：加一个工具要动几处？**

八处（实现、注册、名字集合、披露清单、保留名、沙箱、测试、cassette）。见第 18.5 节。

**Q109：加一份技能要动几处？**

五件事（正文、注册进种子清单、能力映射、契约测试、消化记录）。见第 18.5 节。

**Q110：为什么全量 `pnpm test` 那么慢？**

几千个测试。日常改动用单目录：`pnpm exec vitest run <目录>`。

**Q111：锁顺序的测试红了怎么办？**

先想清是「约束过时了」还是「你的改动碰到了约束」。这类测试（spec 顺序、判定表 150 项、CORS 结构、棘轮）通常不是测试的问题。

**Q112：覆盖率有硬要求吗？**

是棘轮：**不能降**。降了要在 diff 里显式抬基线。

**Q113：能改 `src/lawmind/skills/builtin/*.md` 吗？**

能，但要知道**这些 md 是运行时说明书**，改了会改变下一轮模型行为。改完跑契约测试。

**Q114：`matter-ops/storage.ts` 能用吗？**

能用，但它是**唯一绕过写协议**的模块（裸 fs、无锁、无原子写、无 zod）。别模仿它。

**Q115：两份常量清单在哪？**

`runtime/protected-workspace-rels.ts` 与 `electron/fs-bridge.mjs`。改一处必须改另一处——**有测试替你抓漏**：`electron/fs-bridge.test.ts` 逐项比对两侧文案与白名单。

**Q116：为什么技能有 37 份但种子清单只有 35 个 id？**

`client-talk-intake` 和 `legal-event-extract` 写了但没注册，所以不会种进工作区。这是一个真实的漂移。

**Q117：`integration/` 和 `integrations/` 有什么区别？**

单数那个**只有测试**（跨模块验收）；复数那个才是连接器。

**Q118：`run_analysis` 为什么默认不可用？**

需要策略开启（`allowAnalysisScripts`）。

**Q119：`facts_grounded` 为什么永远是 warning？**

因为实测它恒为 0（136 份推理快照里 `facts > 0` 的是 0 份）。设成 blocker 会挡掉每一次高风险交付。升级条件写在注释里。

**Q120：`shouldCheckpointToolBudget` 为什么恒为 false？**

工具预算不再触发检查点。`skipToolBudgetCheckpoint` 只为兼容旧会话保留。

## 38.16 三条最常被问到的

如果只看三条，看这三个：

1. **「为什么它不问我？」** —— 设计如此。只有外发和真授权才打断。
2. **「怎么让它更懂我？」** —— 用一两周，去记忆库确认建议；把口径写进 playbook。不要改提示词。
3. **「出问题怎么查？」** —— 体检页 → 诊断包 → 审计，三步走；报错原文在仓库里搜得到。
