# 第 26 章 交办话术与提示模板

这一章是实用向的：**同样的活，怎么说效果更好。**

原理在第 4 章：系统靠**确定性信号**（动词 × 文件形态 × 案件语境）判断你要干什么。所以话术的作用不是「念咒语」，而是**把信号给足**。

## 26.1 三条基本原则

### 原则一：说清「要什么」，不用说「怎么干」

好：「审一下这份合同的违约责任，风险点标出来，能改的直接改。」

不好：「先读合同，然后找违约责任那一条，然后比对民法典关于违约金的规定，然后……」

原因：过程是系统安排的，你说得越细越可能限制它。**你给的是目标，不是步骤。**

### 原则二：材料比话重要

同一句话，附了合同和不附合同，结果完全不同。文件形态（合同 / 诉状 / 函件 / 发票 / 传票）是判定的核心信号。

所以**能拖就拖，别用文字描述材料**。

### 原则三：边界要明说

「不要改原稿」「只出意见书」「别发邮件」这类约束必须写出来。系统默认什么都可能做，你不说它不知道。

有专门的机制处理这类约束（第 4 章讲的交付意图）：它会**去掉和你的指令相反的默认完成条件**。

## 26.2 合同类话术

| 你想干什么     | 这么说                                                         | 为什么这么有效                                        |
| -------------- | -------------------------------------------------------------- | ----------------------------------------------------- |
| 审合同         | 「审一下这份合同的违约责任/付款条件/解除条款」                 | 「审」是动词信号，附的合同是形态信号                  |
| 审一批合同     | 「把这几份合同的付款条件和责任上限整理成一张表，每条要有出处」 | 「整理成表」触发审查表能力；「要有出处」正对验收口径  |
| 从零起草       | 「起草一份采购合同的框架，我方是买方」                         | 「起草」+ 合同形态 → 起草路由；「我方是买方」定了立场 |
| 改一份合同     | 「改一下这份合同，把付款期限从 30 天改成 45 天，出修订稿」     | 「改」+「修订稿」是改稿信号；具体改动给了锚点         |
| 只要意见不改稿 | 「只出审查意见，不要改原稿」                                   | 去掉「必须红线才算完成」的默认                        |
| 统一称谓       | 「这几份文书里的『甲方』都改成『买方』，当事人名字也统一」     | 触发跨文书一致改                                      |

**注意最后一条**：如果是多处命中需要统一替换，系统会先问你一次（或者让模型显式声明 `occurrences: "all"`）。这是防线，不是麻烦。

## 26.3 诉讼类话术

| 你想干什么 | 这么说                                               |
| ---------- | ---------------------------------------------------- |
| 写起诉状   | 「按这份材料写一份起诉状，我方是原告」               |
| 上诉       | 「写一份上诉状，针对一审判决的第三项」               |
| 刑事       | 「这个案子在审查起诉阶段，写一份辩护意见」           |
| 家事       | 「离婚案，写一份起诉状，有两个孩子的抚养问题」       |
| 知产       | 「专利侵权，整理一下权利基础和诉讼路径」             |
| 证据整理   | 「把这些材料整理成证据目录，每条写清证明目的」       |
| 时间轴     | 「从这些材料里做一个时间轴，先给我看草案」           |
| 答辩       | 「对方起诉了，写一份答辩状，重点反驳第三项诉讼请求」 |

**关键技巧**：把**阶段**说出来（一审 / 二审 / 审查起诉 / 执行）。阶段信号决定用哪套文书格式，不说的话系统要猜。

「先给我看草案」对应时间轴的两阶段模式（预览 → 确认 → 成图）。

## 26.4 检索与研究类话术

| 你想干什么 | 这么说                                                 |
| ---------- | ------------------------------------------------------ |
| 查法条     | 「查一下民法典关于违约金过高的规定」                   |
| 查类案     | 「找一下类似的买卖合同违约判例」                       |
| 出备忘     | 「研究一下数据出境的合规要求，写个备忘」               |
| 快问       | 「公司能不能单方面调岗？」                             |
| 读网页     | 「看看这个链接里说什么：（贴 URL）」                   |
| 深度研究   | 「这个问题比较复杂，做一次深入检索，广度和深度都拉满」 |

**几个要点**：

- 「查一下」会走检索研究；如果你只想一句话答案，说「能不能……」「这样违法吗」这类句式会落到快问。
- 贴 URL 时明确说「看看这个链接」，会触发 URL 档案。
- 想要正反两面都查，可以说「支持的和反对的观点都要」——这正对命题矩阵的设计。

## 26.5 材料与档案类话术

| 你想干什么   | 这么说                                                         |
| ------------ | -------------------------------------------------------------- |
| 整理案卷     | 「把这份文件夹里的材料归位，抽出当事人和案由」                 |
| 谈话入档     | 「这是昨天和客户的谈话记录，整理一下，把当事人和案由记进案子」 |
| 收材料进案   | 「把这些文件收进本案」                                         |
| 材料整理     | 「本案材料有点乱，提个整理方案给我看看」                       |
| 修材料放错案 | 「这几份材料放到错案子里了，挪到 XX 案」                       |
| 记期限       | 「记一下：下个月 15 号之前提交证据」                           |
| 传票         | （拖着传票照片）「记一下」                                     |
| 建案件       | 「新建一个案子，叫 XX 公司买卖合同纠纷」                       |

**「提个整理方案给我看看」**这个说法对应三步式的第一步（提计划 → 确认 → 执行）。

## 26.6 计算类话术

| 你想干什么 | 这么说                                                          |
| ---------- | --------------------------------------------------------------- |
| 劳动补偿   | 「他工作了 3 年 7 个月，月薪 1 万，被违法解除，算一下能拿多少」 |
| 加班费     | 「算一下这两年的加班费，平时加班 120 小时，周末加班 60 小时」   |
| 期限       | 「一审判决 3 月 10 日送达，上诉期什么时候届满」                 |
| 诉讼费     | 「标的额 200 万，一审受理费多少」                               |
| 表格核算   | 「把这份 Excel 里的金额汇总一下，出个对照表」                   |

**关键**：把**要素给全**（工作年限、月薪、解除性质、日期）。缺了要素系统会标缺口，不会瞎算——这是设计（第 21 章那两条「不得口算」的验收标准）。

## 26.7 交付与导出类话术

| 你想干什么 | 这么说                                    |
| ---------- | ----------------------------------------- |
| 出 Word    | 「出一份 Word」                           |
| 出修订稿   | 「出一个带修订痕迹的 Word，放我桌面」     |
| 出 PPT     | 「做成培训课件，12 页左右」               |
| 写文件     | 「把这份意见书写成一个 md 文件放工作区」  |
| 导出表格   | 「导出成 xlsx」                           |
| 指定位置   | 「放到下载文件夹」/「放到这个案件目录里」 |

**「放我桌面 / 下载 / 文稿」**这三个是白名单位置（第 8 章）。指名之后系统会写到你点名的位置。

## 26.8 自动化类话术

| 你想干什么       | 这么说                               |
| ---------------- | ------------------------------------ |
| 从一件活变自动化 | 「以后每周一都这样来一次」           |
| 建自动化         | 「每周五下午给我一份本案进展小结」   |
| 邮件处理         | 「每天早上把需要我回的邮件整理出来」 |
| 续展监控         | 「提前 30 天提醒我这些合同的续展」   |

**注意**：自动化要填六项确认（第 17 章）。话术只能建起架子，那六项还得你自己定。

## 26.9 协作类话术

| 你想干什么       | 这么说                                   |
| ---------------- | ---------------------------------------- |
| 派活             | 「让合同助手先审一遍，把结论给我。」     |
| 找特定岗位       | 「找一个做合规的助手看一下这段」         |
| 问同事（同步等） | 「问问研究助手法条里怎么规定，等它回复」 |
| 请人审           | 「让另一位助手审一下这份稿的准确性」     |
| 开个会           | 「开个会讨论一下这个案子的和解方案」     |

**关键**：被派的助手看不到你的对话，所以**任务要说全**（要什么、不要什么、有什么材料）。系统里那几个参数（`goal` / `not_goal` / `materials`）就是干这个的。

## 26.10 记忆与口径类话术

| 你想干什么 | 这么说                                    |
| ---------- | ----------------------------------------- |
| 记偏好     | 「以后所有合同的违约金都按不超过 30% 写」 |
| 记口径     | 「我们所在管辖条款上一律写单一机构」      |
| 撤销写入   | 「撤销刚才那次写入」                      |
| 查记忆     | 「你都记住了我哪些偏好？」                |

**注意**：说「记住」不会直接写。它会变成一条**待确认建议**，你在记忆库确认才落盘（第 6 章）。

## 26.11 逆向：哪些话会把事情带偏

| 不好说法                       | 问题                                     | 改说                             |
| ------------------------------ | ---------------------------------------- | -------------------------------- |
| 「你先看看这份合同」（附合同） | 「看看」不是审查信号，可能只得到一个摘要 | 「审一下这份合同的××」           |
| 「帮我处理一下这个」           | 目标和材料都不明                         | 说清要产出什么                   |
| 「随便写一份」                 | 交付物类型无法绑定                       | 说清类型（意见书 / 备忘 / 函件） |
| 「按我说的步骤来」             | 限制系统安排                             | 只说目标                         |
| 「这个不用检索，你直接说」     | 高风险情况下会被证据门拦                 | 让它检索，或者接受标【待核实】   |
| 「尽快」                       | 没有信息量                               | 给具体时间约束                   |

## 26.12 「不要」清单怎么写

系统支持从自然语言里抽边界。几种常见的：

| 边界     | 怎么说                                            |
| -------- | ------------------------------------------------- |
| 不改原稿 | 「不要改原稿」「只出意见书」                      |
| 不发邮件 | 「先不要发，给我看」                              |
| 不改事实 | 「事实部分照抄材料，不要改写」                    |
| 不加结论 | 「只整理材料，先不下结论」                        |
| 限定范围 | 「只看违约责任那一章」                            |
| 限定风格 | 「按对方纸的立场审」（对应己方纸/对方纸那个机制） |

## 26.13 一个完整的好交办长什么样

```text
审一下这份采购合同的违约责任和解除条款。我方是买方。
风险点要标出条款位置，能给改法就给改法。
只出审查意见，先不要改原稿。
```

拆解一下：

| 句子                     | 起什么作用                         |
| ------------------------ | ---------------------------------- |
| 「审一下这份采购合同」   | 动词（审）+ 形态（合同）→ 合同审查 |
| 「违约责任和解除条款」   | 缩小范围，模型不用面面俱到         |
| 「我方是买方」           | 定立场（影响风险判断方向）         |
| 「标出条款位置」         | 正对 `clause_anchor` 检查          |
| 「能给改法就给改法」     | 正对 `recommended_wording` 检查    |
| 「只出意见，不要改原稿」 | 交付意图边界                       |

四句话覆盖了意图、立场、验收、边界。这比写一大段「请仔细阅读……并注意……」有用得多。

## 26.14 已知坑（本章相关）

- **话术不是咒语。** 它只是把信号给足。系统的判定是确定性的，不是靠关键词匹配打分。
- **材料形态常常比话更重要。** 附了诉状的「看看这个」和附了合同的「看看这个」会走不同路。
- **「不要」必须明说。** 系统不会替你想边界。
- **说「记住」不等于会记住。** 要走确认。
- **阶段、立场、金额要素给全。** 缺了会被标缺口而不是猜。
- **别描述步骤。** 那是给系统留的判断空间。
