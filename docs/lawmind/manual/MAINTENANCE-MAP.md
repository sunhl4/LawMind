# 手册改动定位表

这份文件只回答一个问题：**代码改了，我该动手册里的哪一章？**

## 这份文件与另外三个入口的分工

| 文件                 | 回答的问题                   | 什么时候用        |
| -------------------- | ---------------------------- | ----------------- |
| `README.md`          | 手册有哪些章、怎么按角色读   | 第一次进来        |
| `INDEX.md`           | 「我想知道 X」→ 去第几章     | 找答案            |
| **本文件**           | **「我改了 X」→ 要改第几章** | **提交代码前后**  |
| `check-crossrefs.py` | 小节引用有没有指错           | 改完章号 / 小节号 |

用法：拿你这次的 diff，在下面第一张表里找对应行，然后照「主章 + 连带章」逐个改。

---

## 三、新增功能时，通常要同时动这几处

按经验，一个新功能最少要碰四类文档：

1. **机制章**（功能面）——律师怎么用、边界在哪。
2. **实现章**（43–71）——哪个文件、哪个函数。
3. **参考章**（20–23）——如果它新增了技能 / 规格 / 能力 / 工具。
4. **清单附录**（A/B/C）——如果它新增了环境变量、端点、审计事件或文件。

再加两处容易漏的：

- **第 18 章的加动清单**——告诉后来者「下次加这东西要改哪」。
- **第 39 章的版本表**——如果引入了新的持久化结构。

## 四、改完必须跑的两件事

```bash
# 在仓库根
npx markdownlint-cli2 "docs/lawmind/manual/*.md"

# 在 docs/lawmind/manual/ 下
python3 check-crossrefs.py
```

`check-crossrefs.py` 的硬指标只有一个：**① 悬空必须为 0**。② 跨章与 ③ 熵差只是提示。

**还有一条脚本查不出来的**：改了小节号之后，去抽查一批引用了该章的地方——**小节号仍然存在、但指的是另一件事**这种错，脚本报不出来。改完章号或小节号，至少抽 10 条看看。

## 五、章节联动：改一章时顺手看哪几章

这些是「同一件事写了两遍」的地方，改一处必须改另一处：

| 技能     | 11（机制） / 20（清单） / 70.10–70.15（实现） | 实现           |
