# 第 27 章 交付实施与团队部署

这一章给交付实施方和律所 IT：怎么把 LawMind 交到律师手上，怎么判断「能用」，怎么扩到一个团队。命令细节在第 31 章；策略字段在第 30 章。

五条铁律在这里的取舍：

| 铁律           | 这一章怎么落                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 上手简单       | 个人律师的路径是安装包、模型向导、一件真案子。策略文件、签名、中继、培训课都不进这条路径。                                                                         |
| 交付质量       | 验收看脱敏真稿能不能直接用：条款是否指得上、修订是否落在最短锚点、引用是否还有效。体检变绿和审计包导出都不算交件。                                                 |
| 稳定           | 同一道金标交办重复跑，看结果飘不飘、会不会中途多问一句。判断分级默认停在 `shadow`，误报率出来之前不改成硬拦。                                                      |
| 先复用，后自研 | 安装走所里已有的软件分发；模型走已有的 OpenAI 兼容网关；小团队同步走已有共享目录。名册和多租户不够用时才上案件云。                                                 |
| 发挥模型能力   | 对话与改稿用最强的通用模型；法律检索可以另接一条垂类通道（`dual`）。`agentMandatoryRules` 只写短原则。禁止清单、字数配额、为了「走对流程」冻结工具，都不写进策略。 |

可审计不是验收标准。哈希链、外锚、合规导出只在排障、恢复、安全调查或买方写明的法规义务里使用。

## 27.1 两口钟，不是三套安装仪式

部署成功只认两个时间：

| 钟     | 问什么                                               | 商业上算做成                                   |
| ------ | ---------------------------------------------------- | ---------------------------------------------- |
| 第一口 | 一位律师从打开窗口到交出一份能改、能签批的稿，要多久 | 当天，用他自己的一件脱敏案子，不先上课         |
| 第二口 | 一个小组从试用到「默认就用它办这类活」，要多久       | 两周试点后，金标集上多数稿只需轻改，外发零漏批 |

三种运行形态仍然存在，但它们是第二口钟的档位，不是第一口钟的前置作业。

| 形态      | 什么时候选                                 | 数据在哪                                                       |
| --------- | ------------------------------------------ | -------------------------------------------------------------- |
| 单机 solo | 默认。独立律师，以及所内还在试点的人       | 本机工作区 + 应用数据目录                                      |
| 单机 firm | 试点结束，所里要伦理墙、强制互审、副本协作 | 仍在本机；多的是门禁默认值                                     |
| 多人协作  | 两人以上同时办同一案件                     | 名册与操作经中继同步，内容端到端加密，密钥不出本机（第 16 章） |

`private_deploy` 不是「更安全的 solo」。它是买方安全评审已经点名要白名单、合规导出和真技能签名时才升的档。

## 27.2 第一口钟：单机当天能交件

### 装

1. 对上系统和架构：macOS 分 arm64 / x64，Windows x64，Linux x64。
2. 用已签名的安装包。所里已有 Jamf、Intune 或同等软件分发时，推这个安装包，不要另做安装服务器。
3. 源码路径只留给开发：`pnpm lawmind:desktop`。不要用浏览器打开 `http://127.0.0.1:5174`。

律师打开的是桌面窗口。端口、环境变量和打包命令不进培训。

### 模型：一条主通道，检索可选第二条

走设置里的向导（模型与连接）。密钥进系统密钥链，并从环境文件里抹掉明文。

对话、选工具、改稿用**当前最强、所里已经采购的通用模型**。不要为了「先跑通」故意降到小模型，也不要第一天就换成法律垂类模型当大脑。垂类模型（ChatLaw、LawGPT，或所里已有的检索专用端点）只接检索通道：

- 向导或设置里的检索通道选 `dual`（环境变量 `LAWMIND_RETRIEVAL_MODE=dual`）。
- 未配检索专用模型时，系统回退到同一条通用模型，不另造一条空通道。

所里已经有 OpenAI 兼容网关（统一 Key、统一账单、统一域名）时，`LAWMIND_AGENT_BASE_URL` 指到那条网关。不要为 LawMind 再搭一套推理集群。

批量写入环境文件只在无法走界面时使用：

```text
LAWMIND_AGENT_BASE_URL=...
LAWMIND_AGENT_MODEL=...
LAWMIND_AGENT_API_KEY=...
```

环境文件里的密钥是明文，而且优先级高于密钥链。能走界面就走界面。开发仓库里的 `pnpm lawmind:setup:team` 是把团队示例环境合并进 `.env.lawmind`，不是给律师机器做的分发工具。

### 当天只验一件真活

用律师自己的一份脱敏合同或备忘，不要用仓库示例凑数。

1. 拖进对话，说「审一下」或「按我标的点改」。
2. 中途不该出现「要不要继续」。只有外发、改原稿这类真授权才停在「待我拍板」。
3. 审查意见要指到具体条款。改稿导出的是带修订轨的 Word，改动落在最短锚点（第 8 章）。
4. 顶栏只有对话、工作台、在办。改稿从在办或对话进去，不单独占一级入口。培训不要讲六个工作面，也不要说「文书台」。

策略文件、技能签名、审计外锚，第一天都可以没有。

## 27.3 策略：先影子，再抬门

个人律师不需要 `lawmind.policy.json`。要写，文件必须有 `schemaVersion: 1`，否则整份被忽略。未知键同样被忽略。`auditIntegrityExport`、`strictDangerousToolApproval`、`acceptanceGateStrict`、`citationGateStrict` 是版本功能键，不是策略键；写进文件不会生效。策略键以 `src/lawmind/policy/workspace-policy.ts` 为准（第 30 章）。

firm 试点的最小文件只做两件事：标明版本，并放行模型域名和法源域名。

```json
{
  "schemaVersion": 1,
  "edition": "firm",
  "egressMode": "allowlisted",
  "networkAllowlist": ["api.deepseek.com", "flk.npc.gov.cn"],
  "networkAllowlistEnforced": true
}
```

域名换成你们真实的网关和法源。空名单再加强制，等于断网。推荐名单可以并入（第 15 章 `RECOMMENDED_LEGAL_NETWORK_ALLOWLIST`），不要手抄一半。

配完看 `GET /api/health` 的 `policy.applied`，以它列出的项为准。

### 判断分级停在影子

`judgmentTiering` 的默认是 `shadow`：系统记下「如果打开会怎样」，不改律师看到的结论。这是上线方式，不是未完成。

试点两周内保持 `shadow`。只统计两件事：

- 若改成 `on`，有多少份其实能用的稿会被拦住（误报）。
- 有多少份后来被律师改掉的问题，影子记录里根本没出现（漏报）。

误报还高时，不要把 `judgmentTiering` 改成 `on`，也不要靠加长 `agentMandatoryRules` 去补。`agentMandatoryRules` / `agentMandatoryRulesPath` 只放短原则（例如「对外稿必须经律师签批」）。禁止词表、字数上限、关键词拒稿会把模型判断掐死，违反铁律 5。

firm 版默认还会打开强制互审、伦理墙、案件副本、修订稿独立审稿硬墙、危险工具严格审批。这些是授权和利益冲突边界，不是文稿质量开关。试点里如果律师的主抱怨是「还没写完就被拦住」，先看是不是这些默认门在空转，用 `policy.features.<key>` 把还没准备好的那一档暂时关上（第 15.8 节）。`wordAddinAutoRun` 在 firm 默认关，要保留「桌面端有一次显式动作」；要开必须在策略里写明。

`toolSandbox` 可以开：它把高风险工具放进子进程，不改变模型能用哪些工具。

### 自定义技能才签名

用到工作区自有技能时：

```bash
export LAWMIND_SKILL_SIGNING_SECRET='<足够长的随机串>'
pnpm lawmind:skills:sign --workspace <工作区>
pnpm lawmind:skills:sign --workspace <工作区> --check
```

必须是真密钥。派生兜底（`derived`）不算签名；没有 `--allow-derived` 时 CLI 会拒绝。内置技能不靠这把密钥。

## 27.4 第二口钟：小组试点，而不是先培训

在单机已经能交件之后，再扩团队。顺序是：选人、定金标、影子跑、再开协作。

### 试点怎么切

一个实务组，三到八位已经会用对话交办的律师，两周，十件他们知道「好稿长什么样」的旧案（脱敏）。不要全所首日切换，也不要先做一天集中培训。

开场只讲四句：

1. 顶栏是对话、工作台、在办；改稿从手头这件事进去。
2. 只有外发和改原稿会打断。
3. 记忆要律师确认才写入。
4. 必核清单和签批是两道门，过了才能对外。

### 中继：先用已有目录

| 形态                       | 什么时候用                                        |
| -------------------------- | ------------------------------------------------- |
| 共享文件夹（NAS / 同步盘） | 默认。小组已有内部共享，人少                      |
| HTTP 中继（自建）          | 共享目录的权限和冲突已经不够                      |
| 案件云                     | 要名册、多租户（第 16 章；默认 `127.0.0.1:8788`） |

同步盘会自己同步文件，和案件副本的同步叠在一起会双写。给 LawMind 一个独立目录，不要指到整个所共享盘。

同一台机器、同一个工作区，同一时刻只允许一个写者（第 7 章的锁）。两人要同时办一案，走案件副本，不要轮流登录同一台电脑。

材料先留在所里原来的文件夹里，用「本机文件夹」只读引用；要进案件再「收进本案」。不要为了上线把卷宗整体搬进工作区。

## 27.5 验收：金标与重复，不看审计包

### 律师当场能看懂的七项

| 验什么   | 怎么验                                                  | 通过                                                |
| -------- | ------------------------------------------------------- | --------------------------------------------------- |
| 模型通   | 设置 → 模型与连接「验证模型」，或 `pnpm lawmind:doctor` | 已配置且连通；`dual` 时检索通道单独显示已配或已回退 |
| 交办通   | 「查一下民法典违约责任」                                | 出备忘；中途不问「要不要继续」                      |
| 材料通   | 拖一份脱敏合同说「审一下」                              | 风险指向具体条款，不是空泛摘要                      |
| 改稿通   | 改稿 → 签批 → 导出                                      | 带修订轨的 Word；改动是最短锚点                     |
| 记忆通   | 记忆库确认一条                                          | 档案里出现对应改动；未确认的不出现                  |
| 外发闸门 | 让它发一封邮件                                          | 停在「待我拍板」，不会直接发出                      |
| 重复稳定 | 同一条交办再跑一次                                      | 结论结构同类；不会突然多一轮确认                    |

「出了一份备忘」只说明链路通。质量认材料通、改稿通，以及下面的金标。

### 金标（有夹具才算数）

```bash
pnpm lawmind:gate --all --strict
pnpm lawmind:true-manuscript
pnpm lawmind:human-baseline
pnpm lawmind:ops matter-consistency
pnpm lawmind:doctor --json
```

`lawmind:gate` 退出码：0 是全部就绪或没有草稿；1 是 `--strict` 下有未就绪；2 是参数或 IO 错误。

三道门没有夹具时 SKIP，这是正常结果：

| 门                                   | 什么时候才有意义                                                                                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 真稿（`lawmind:true-manuscript`）    | 律师脱敏的 `.docx` / `.doc` / `.pdf` 放在 `fixtures/lawmind-true-manuscript/`。`--write-baseline` 只起草侧车，不覆盖律师已确认的基线 |
| 人类基准（`lawmind:human-baseline`） | 同题双稿至少 10 件。`--write-blind` 出匿名包；确定性分数不能代替律师盲评                                                             |
| 类案就绪                             | 本机有可用的类案索引                                                                                                                 |

不要把 SKIP 写成失败，也不要用仓库示例去填夹具。人不够 10 件时，基准报 INSUFFICIENT，同样不是通过。发版场景另跑 `pnpm lawmind:release-readiness`。

试点结束时用这四个数做商业判断，不看功能清单：

1. 十件里有几件律师愿意在轻改后发出（可用率）。
2. 律师后改掉的问题里，系统事先标出了几件（缺陷召回）。
3. 同一条交办重跑，结论和打断次数飘了没有。
4. 律师从打开窗口到可签批稿的分钟数，以及这十分钟的模型花费。比的是可用页的成本，不是 token 单价。

### 安全抽查（边界，不是质量分）

| 项                | 怎么验                                          |
| ----------------- | ----------------------------------------------- |
| 本机 API 只对回环 | 另一台机器访问本机端口，连不上                  |
| 分包鉴权          | `word-addin` 客户端调 `/api/matters/*` 得到 403 |
| 治理路径          | 经文件接口改 `lawmind.policy.json` 被拒         |
| 本机文件夹只读    | 改其中的文件被拒，并提示收进本案                |
| 外发要审批        | 上表已验                                        |

审计链、`rootHash`、外锚不放进这张表。需要做安全调查或合同写了留存义务时，再按 27.6 导出。

## 27.6 长期维护

### 备份

| 要备   | 位置                                                                                      |
| ------ | ----------------------------------------------------------------------------------------- |
| 工作区 | `<工作区>/`（`matters/`、`cases/`、`drafts/`、`sessions/`、`tasks/`、`*.md`、`lawmind/`） |
| 应用根 | `<用户数据目录>/LawMind/`                                                                 |
| 密钥   | 系统密钥链 + `~/.lawmind/keys/`                                                           |
| 许可   | `~/.lawmind/license.json`                                                                 |

```bash
LAWMIND_WORKSPACE_DIR=<工作区> pnpm lawmind:backup -- <输出.tar.gz>
```

默认不含 `.env.lawmind`；要含才设 `LAWMIND_BACKUP_INCLUDE_ENV=1`。索引（`lawmind/search-index.sqlite`）和质量快照是派生的，不备份，坏了从真相源重建。

### 升级

1. 先备份。
2. 装新版本（仍走原来的软件分发）。
3. 打开后看体检：跑 `pnpm lawmind:doctor` 或看 `GET /api/health`——策略是否仍是 `policy.applied` 里的那些项，索引要不要重建。
4. 源码开发态若大量 404，重建本地服务 bundle：`pnpm lawmind:bundle:desktop-server`。安装包用户不用跑这条。
5. Word 或 WPS 连不上：设置 → 外观 →「重新连接」，然后完全退出对应软件再打开。加载项尚未验收为成品，见 [LAWMIND-WORD-ADDIN.md](../LAWMIND-WORD-ADDIN.md) 的「现状：半成品」。

### 巡检看漂移，不看审计厚度

能开界面就看设置 → 模型与连接与工作区两页（验证模型、查找重建都在那里）；更全的体检跑 `pnpm lawmind:doctor`。不能开时每周一条：

```bash
pnpm lawmind:doctor
```

它同时看会话配对、投影、索引，以及签名未通过的自定义技能。投影对不上或技能因此停用时退出码为 1。会话配对下一轮会自动补；文件改过的索引下一次检索会补。步骤在第 31 章。

`pnpm lawmind:ops doctor` 打同一份三行。`--deep` 只额外跑开发用的 smoke，不要放进每周巡检。

### 审计只为义务和调查

没有写明的留存义务时，不要把审计导出列进月度验收。

需要归档时：

```text
GET /api/audit/export?since=<起始>&until=<结束>&compliance=1
GET /api/audit/export?integrity=1
GET /api/audit/export-summary?format=text
```

外锚（`LAWMIND_AUDIT_EXTERNAL_ANCHOR_URL`，`file://` 或 HTTP PUT）约每 24 小时推一次摘要，用来发现链被改过。审计不记 query 和 body（第 15 章），不能用来还原「查了什么」。文件在 `<工作区>/audit/`，按天切，不自动删。不要删中间某一天，哈希链会断。

`pnpm lawmind:ops acceptance-pack` 打的是工作区治理打包，给实施存档，不证明稿子能用。

### 密钥轮换

| 密钥                           | 怎么换                 | 影响                         |
| ------------------------------ | ---------------------- | ---------------------------- |
| 模型 API Key                   | 设置里重存             | 无                           |
| `LAWMIND_AUDIT_CHAIN_KEY`      | 换之后新事件用新密钥   | 旧链仍可用本机匹配过的密钥验 |
| `LAWMIND_SKILL_SIGNING_SECRET` | 换后重签全部自定义技能 | 不重签的技能静默失效         |
| `LAWMIND_MAIL_SECRETS_KEY`     | 先导出邮箱配置再换     | 旧密文解不开，且系统拒绝覆盖 |
| 本机 API 安装密钥              | 自动生成并注入         | 客户端凭据是派生的           |

### 换机器

1. 备份工作区并在新机器恢复。
2. 重配密钥。密钥链不跟着目录走：模型 Key、技能签名、审计链、邮箱。
3. 打开应用，让索引重建。
4. Word 插件按第 31 章重新连接。

## 27.7 私有化档的额外预检

`private_deploy` 的自检数据在 `GET /api/health` 的 `doctor.privateDeployChecklist`（第 15.14 节；体检页 UI 已撤，用 `pnpm lawmind:doctor` 或直接读端点），六项：策略文件在、版本是 private、白名单已配、危险工具严格审批开着、合规审计导出可用、技能签名用的是真密钥。

这六项是预检，不是安全证明。过了只说明包装项齐了。交件质量仍看 27.5 的金标。

这一档额外默认打开的是 `complianceAuditExport` 和 `securitySbomPanel`。SBOM 面板给买方安全评审开会用，不放进律师主路径。许可是软门槛：到期或未激活只提醒，不阻断交办（第 15.7 节）。当前仓库里的许可公钥是开发公钥，对外发版前要换成发行方生产公钥。

## 27.8 实施时不要走的捷径

**不要调系统提示词来「适应我们律所」。** 效果来自首跑偏好、工作区 `playbooks/CLAUSE_PLAYBOOK.md`、律师确认过的记忆，以及第 26 章的交办话术。改系统提示词会打到所有任务。

**不要用审计保存期限代替质量复盘。** 留存多久看所里的合规意见。技术上链不能中间断开；外锚摘要很轻，可以比正文留得更久。

**不要为了 firm 的功能表把 solo 试点直接改成 firm。** 先让第一口钟成立。伦理墙和强制互审解决的是多人利益冲突，不提高单份合同的写法。

**不要把模型费用优化做成降智。** 检索走 `dual` 已经把垂类调用限在检索车道。对话和改稿继续用最强通用模型。省下来的钱用「每份可签批稿的花费」验收，不用平均 token 价验收。

## 27.9 装完打勾

个人律师只打前六项。后面各项是团队或私有化才有的。

```text
[ ] 安装包与系统架构匹配，窗口能打开
[ ] 模型经向导配置且连通（密钥在密钥链，不在明文环境文件）
[ ] 一件脱敏真活能审或能改，中途没有「要不要继续」
[ ] 导出是带修订轨的 Word，外发停在「待我拍板」
[ ] 顶栏路径是对话 / 工作台 / 在办，律师没被要求先上课
[ ] `pnpm lawmind:doctor` 没有红色项（诚实 SKIP 除外）
[ ] （团队）lawmind.policy.json 含 schemaVersion=1，policy.applied 与预期一致
[ ] （团队）白名单放行的是真实模型域名和法源域名
[ ] （团队）judgmentTiering 仍为 shadow，误报尚未压过可用率
[ ] （团队）金标十件已脱敏；SKIP / INSUFFICIENT 没有被记成通过
[ ] （团队）中继目录独立，不与全所同步盘叠在同一棵树上
[ ] （按需）自定义技能已用真密钥签名并通过 --check
[ ] （按需）备份脚本能解开并含 BACKUP-MANIFEST.txt
[ ] （按需）Word 插件能侧载并取件
```

## 27.10 已知坑

- 策略文件缺 `schemaVersion: 1` 会被整份忽略。以 `policy.applied` 为准。
- 版本功能键写进策略文件会被忽略。
- 环境文件里的密钥是明文，且压过密钥链。
- `wordAddinAutoRun` 在 firm 默认关。
- 真稿、人类基准、类案三道门的 SKIP 不是失败。示例文件填进去会使门失效。人类基准不足 10 件是 INSUFFICIENT。
- 换技能签名密钥必须重签全部自定义技能，否则静默失效。
- 换邮箱密钥前先导出配置。解不开的旧密文会被拒绝覆盖。
- 不要删除中间某一天的审计文件。
- 同一工作区不要两人同时写。换机器必须重配密钥。
- 索引和质量快照不用备份。
- `pnpm lawmind:doctor --deep` 不会多查。`--deep` 只属于 `pnpm lawmind:ops doctor`，而且只跑开发 smoke。
- 验收包和审计导出不证明交件质量。
