# 第 25 章 从零上手实操

这一章按时间走一遍：装上、连上模型、发出第一句。对照 Cursor、Codex 和 Harvey，第一天的形状是**进到能干活的界面，点一句或自己说一句**，不是先填问卷。

连上模型之后系统建好「演示案件」，输入框留空（选过身份时放进一句默认交办）。空对话上有三句可点的示例，点了只填进输入框，改完再发。审合同和记传票要先把文件拖进来。身份可从**设置 → 账号 → 开始时的偏好 → 重新填写**补；文风与风险口径不进首跑，做完几件事后到记忆库确认再收。

## 25.1 第一天上午：装上、跑通

### 第一步：装

下载对应系统的安装包（`LawMind-<版本>-<系统>-<架构>.<扩展名>`），或者从源码跑：

```bash
git clone https://github.com/sunhl4/LawMind.git
cd LawMind
corepack enable
corepack prepare pnpm@10.23.0 --activate
pnpm install
pnpm lawmind:desktop
```

**判断成功的标准**：桌面窗口打开，能看到侧栏和顶栏。**不要**去浏览器打开 5174（第 2 章）。

### 第二步：连模型

首跑会弹连接向导。三件事：

1. 选一个推荐栈（DeepSeek Flash / 通义千问 / OpenAI 兼容），或者自己填 Base URL 和模型名。
2. 填 API Key。
3. 选工作区（默认在用户数据目录下）。

**如果模型能填完但保存不了**，说明系统密钥链不可用（第 2 章那段文案）。要么启用密钥链，要么手工写 `.env.lawmind`。

### 第三步：进对话

模型保存并验证通过后，**不会**再弹身份问卷。系统会建「演示案件」，并把权限设成可以执行。输入框是空的。已经有案件时，引导不会自动再弹。

空对话上有三句可点的示例（见下一步）。身份可以之后从设置里重开新手引导再选；重开窗口与第一次一样：选完身份即建演示案件开工，文书类型由对话判断。写作习惯不在首跑问卷里收集，可在记忆库里从改稿与对话确认后沉淀。

工作区是空的、又还没标记关闭时，引导仍会自己打开。这时主按钮是**直接开始**，和上面同一条路。已经选了身份或文书之后，这个按钮改成「不记这些，直接开始」，避免和主按钮抢，也不会悄悄丢掉刚选的项。

### 第四步：发第一句

空对话标题是「开始对话」。下面三句：

| 按钮       | 填进输入框的话                               |
| ---------- | -------------------------------------------- |
| 写一份备忘 | 查一下民法典关于违约金过高的规定，写个备忘。 |
| 审违约责任 | 审一下这份合同的违约责任。                   |
| 记下传票   | 记一下这份传票里的开庭时间和案号。           |

审合同和记传票要先把文件拖进输入框，再发。备忘可以空着手发。

**判断成功的标准**：状态条有一行「本轮按「××」处理」，随后出现「正在办理…」的进行中指示（侧栏会话行也会显示进行中）。中间步骤不会问要不要继续。

### 第五步：看一遍体检

体检没有单独的设置页了：模型连通在设置 → 模型与连接里点「验证模型」，其余跑 `pnpm lawmind:doctor`（或看 `GET /api/health`）。重点看三行：

| 看什么 | 期望                                   |
| ------ | -------------------------------------- |
| 模型   | 已配置、已连通                         |
| 索引   | 就绪（可能显示「陈旧」，重启后会重建） |
| 法源   | 演示语料就绪（非正式权威库）           |

界面写的是「演示语料就绪」，这是正常的。要查真法条得配语料或接端点（第 10 章）。

## 25.2 第一天下午：第一次交办

### 练习一：一句话

在对话里点「写一份备忘」，或自己说：「查一下民法典关于违约金过高的规定，写个备忘。」

**应该看到**：

- 状态条显示「本轮按「检索研究」处理」。
- 对话里出现「正在办理…」；要细看这一步在跑什么，命令面板 `/tasks` 打开任务抽屉。
- 最后产出一份备忘，落在工作区。

**如果它问你要不要继续**，那是 bug——中间步骤不该问。

### 练习二：丢一份材料

拖一份合同进输入框，说：「审一下违约责任。」

**应该看到**：

- 输入框上方出现钉选条。
- 产出审查意见（有审查结论、主要风险、修改建议三节）。
- 每条风险都指向具体条款，每条建议都有推荐措辞。

好的审查意见会把风险指到具体条款，并把建议写成可替换的句子。对不上时只提醒，不挡导出。不要为了过检查去凑「第×条」。

### 练习三：改稿

如果有原合同：

1. 点对话里的草稿链接（或命令面板 `/review`）。顶栏一级只有对话、工作台；改稿不占导航——**中栏换成草稿台**（`LawmindMiddleDraftDesk`），对话留在右侧。
2. 草稿台左侧是红线面板，逐处决定接受或拒绝；右侧看正文。
3. 展开「高级 · 签批」：先勾齐律师必核清单，再签批。
4. 用交付条导出 Word，看是不是带修订轨。想回到文件本身，点草稿台上的「回到文件」，`.docx` 会进文件工作台的 Word 修订面。

**检查点**：导出的修订轨里，改动应该是**最短锚点**——比如只把「30 日」改成「45 日」，而不是整句删除加整句新增。

### 练习四：看一次「要拍板」

**理解一件事**：绝大多数动作不会停下来等你。只有外发、真授权、以及需要你判断的事项才停。真停下来时，它在三处之一：

- **对话里**：最后一条助手消息下面的待办卡——批准、改参数再批准、拒绝，或回答澄清。
- **工作台案卷**：本案「现在」里出现「待拍板 → 去拍板」。
- **操作确认浮层**：高 / 中 / 低风险的操作确认，邮件类会摘要收件人，确认或驳回。

想看办理全貌：顶栏「工作台」（中栏案卷），或命令面板 `/agents` 把律师工作台铺满主区。顶栏没有「在办」一级 tab。

## 25.3 第二天：把工作台用起来

### 建一个真实案件

工作台案件列表的「新建案件」（或命令面板 `/new`）。**轻量建案只填案件名**——它会创建同名文件夹。

其余信息之后补：打开工作台本案卷宗，展开「档案」：

- 当事人
- 案号与案情：门类、案由、案号、法院、审级、诉讼地位（诉讼案件）、开庭日、标的金额（受理费随标的即时估算），填完「保存卷宗」
- 也可以把接案谈话贴进「谈话记录」，抽出接案笔录后确认写入

### 灌一份传票

把你手边的传票照片拖进对话，说「记一下」；或打开本案「档案 → 全部期限」，把传票 PDF / 图片拖进去。

**应该看到**：

- 抽出的开庭时间、案号出现在工作台今日。
- 有一条「确认这次抽取」的待办——抽出的期限**确认后才写入**（手工入口仍要确认）。

**检查点**：抽出不等于写入；系统也不猜期限之间的依赖（比如「举证期限自动挂在开庭后面」），前置关系只在你明确设定后按序浮现。

### 配一个每日计划

工作台里手写几条今天的计划。明天打开时，没做完的会**带过来**（往回看 14 天，最多带 8 条）。

### 看一次记忆

设置 → 记忆库。三个 Tab：**我的习惯 / 案件认知 / 已作废**。待确认的记录带着「待确认」标。

**记住这条规则**：没有你的确认，系统不会往你的偏好档案里写东西——未确认的不进对话。觉得某条对就确认（从本案审核来的，默认只留本案；要以后都用，先把「用于」改成「以后的稿子都用」），觉得不对就忽略或驳回。

## 25.4 第三天：把重复劳动交出去

### 配一个自动办件

设置 → 自动办件。建一条，比如「每周一起草给客户的进展」。它准备草稿，不会自己把信发出去。

主表单三项：**选案件、做什么（预设）、多久一次 / 几点**。下面「规矩已经写好」折叠里有四项默认规矩，要改再打开：

| 项               | 怎么填                                         |
| ---------------- | ---------------------------------------------- |
| 办完是什么样     | 「一页进展说明，包含本周完成事项和下周计划」   |
| 哪些事必须先问我 | 「涉及金额的结论必须我先确认」                 |
| 资料不全时       | 三选一，建议「先交能做到的部分，并列出缺什么」 |
| 什么时候告诉我   | 三选一，建议「只在出问题时通知我」             |

**为什么认真填**：清空「办完是什么样」或「哪些事必须先问我」就不能创建——这几项会进任务书，直接影响模型怎么做。而且它防的是「你以为它会干 A，实际它在干 B」。没办成、或停下来等你拍板时，一定会通知你。

### 看一眼跑出来的东西

自动办件跑出来的草稿进工作台该案的「现在」（要外发的信也在这里等批准）；对话里同样有记录。想按任务看，命令面板 `/tasks` 打开任务抽屉：job、工具批准、进行中的委派都在里面。

### 试一次委派

委派是 **Firm 多助手**的功能：设置 → 协作 里交办出去的活、按流程办；对话命令面板 `/delegate` 也可以发起（Solo 默认一位父助手，没有这项）。

如果你所里建了合同助手，可以试试「让合同助手先审一遍，你把结论汇总给我」。

**注意**：被派的助手看不到你和它的对话，所以要写清要做什么、不要做什么。

## 25.5 第一周：把口径固定下来

### 校准你的偏好档案

用了一周之后，设置 → 记忆库 里应该攒了一些待确认的记录。这时候逐条过一遍：

- 从本案审核来的写法，确认后默认只留在本案；要变成以后都用的写法，先把「用于」改成「以后的稿子都用」。
- 同一写法在多个案件里都出现过（「多个案件里同一写法」标），确认后才通用。
- 觉得不对就驳回；确认错了可以去「已作废」里恢复。

**涉及案件事实的一条条来**，不要闭眼全点。

### 配执业口径

设置 → 工作区，两个折叠块：

- **执业口径**：默认立场、争议解决、原则上不接受（一行一条）、备注。改完只影响之后的办件，不会回改历史文件，已生成草稿不会重算。
- **审查标准**：按合同类型或客户自动套用的核对项（一行一条，可用触发词）。学习来的红线默认关闭，点「确认启用」才生效。

工作区里的 `playbooks/CLAUSE_PLAYBOOK.md` 是同一份口径的文件，不必为了改一句去找路径。

### 校准风险表述

如果你发现系统总是写得太保守或者太激进，改两个地方：

1. 设置 → 工作区 → **执业口径**（默认立场与「原则上不接受」）。
2. 设置 → 记忆库：把认可的风险表述确认进去，不认可的驳回。

注意：**风险口径不在新手引导里**——重开首跑只能再选一次身份，改不了风险。

### 试一次历史扫描（可选）

设置 → 工作区 →「整理电脑上的资料」：指定范围（某个文件夹，或桌面、文稿和下载）→ 查看分类 → 勾选确认，确认后才复制。判断只看文件夹名和文件名，原文件留在原地，文件内容不发给模型。

它还会从你的**修订记录**里抽办案习惯：同一条款的同一改法被接受满 **5 次**才入队，入队后同样**要你确认**才生效（第 6 章）。

## 25.6 常见的第一周困惑

### 「为什么它不问我？」

这是设计。只有外发这类真授权才打断（改已有 Word 走修订轨，不另问一次），中间步骤不问。

**如果你确实想让它停下来**，可以在指令里明确写「先给我看方案，我确认后再写」。

### 「为什么它改了原稿？」

它不会改原稿。**改稿路径是「拷副本 + 在副本上落修订轨」**，原文件一个字节都不动。

如果你看到原文件变了，那说明走的不是修订轨那条路（比如用了 `render_document`）。

### 「为什么导出要我签批两次？」

两个不同的门：

- **必核清单**：逐项确认（第 12 章）。
- **签批**：最终批准。

必核清单没勾完，不能签批。这是你自己的确认，不是稿子被关键词挡住。

### 「为什么引用它说『待核实』？」

说明这条没检索到来源。系统**不编条号**，查不到就标待核实（第 10 章）。

配了法源之后会好很多。

### 「为什么有些技能不生效？」

技能要么被主推（进提示词正文），要么只在索引里（要 `read_skill` 才读）。第 20 章列了哪些技能不在主推行列。

### 「为什么同一个问题两次答案不一样？」

如果两次都过了验收门，那差别通常在表述而不在事实。想要更稳，可以：

- 把口径写进 `playbooks/CLAUSE_PLAYBOOK.md`。
- 把看过的偏好确认进记忆，让同样交办不飘。法律判断仍交给模型。
- 用「按××口径办」点明立场。

稳定性靠已确认的口径，不靠把模型关进一份禁写清单。

## 25.7 一个效率窍门合集

| 想干什么           | 怎么做                                                     |
| ------------------ | ---------------------------------------------------------- |
| 钉一份文件         | 拖进输入框，或者 `@` 文件名                                |
| 从空对话起一句     | 点「写一份备忘」「审违约责任」或「记下传票」               |
| 粘贴截图           | 直接在输入框粘贴（会钉选）                                 |
| 换会话但带上前文   | 承前分叉：「这场对话」→「另起新对话（带上文）」（第 3 章） |
| 不选办件           | 直接说事；系统自己判断                                     |
| 强制指定能力       | 写 `$skill contract.review` 或「【办件】能力：…」          |
| 搜历史对话         | `⌘⇧O` 或 `/chats`                                          |
| 对话变长了         | 输入栏会出现「这场对话」，可整理或另开一段                 |
| 让某份技能被看到   | 在指令里点名要用它                                         |
| 撤销刚才的档案写入 | 对话里说「撤销刚才那次写入」                               |
| 一次跑一件长活     | 用工作流（「先让 A 做…再让 B 做…」）                       |
| 复现同一张表       | 审查表的行序按路径排，两次跑结果一致                       |

## 25.9 一句话总结

上手只要三件事：**连上模型、第一次交办、看一次体检**。剩下的都是慢慢把口径磨准——而口径主要靠记忆库和工作区里的 playbook，不靠背提示词。
