# 第 25 章 从零上手实操

这一章按时间走一遍：装上、连上模型、发出第一句。对照 Cursor、Codex 和 Harvey，第一天的形状是**进到能干活的界面，点一句或自己说一句**，不是先填问卷。

连上模型之后系统建好「演示案件」，输入框留空。空对话上有三句可点的示例，点了只填进输入框，改完再发。审合同和记传票要先把文件拖进来。身份、文风、风险口径从设置里重开新手引导再记，做完几件事后再到记忆库里收。

## 25.1 第一天上午：装上、跑通

### 第一步：装

下载对应系统的安装包（`LawMind-<版本>-<系统>-<架构>.<扩展名>`），或者从源码跑：

```bash
git clone https://github.com/sunhl4/LawMind.git
cd LawMind
corepack enable
corepack prepare pnpm@10.23.0 --activate
pnpm install
pnpm lawmind:desktop
```

**判断成功的标准**：桌面窗口打开，能看到侧栏和顶栏。**不要**去浏览器打开 5174（第 2 章）。

### 第二步：连模型

首跑会弹连接向导。三件事：

1. 选一个推荐栈（DeepSeek Flash / 通义千问 / OpenAI 兼容），或者自己填 Base URL 和模型名。
2. 填 API Key。
3. 选工作区（默认在用户数据目录下）。

**如果模型能填完但保存不了**，说明系统密钥链不可用（第 2 章那段文案）。要么启用密钥链，要么手工写 `.env.lawmind`。

### 第三步：进对话

模型保存并验证通过后，**不会**再弹身份问卷。系统会建「演示案件」，并把权限设成可以执行。输入框是空的。已经有案件时，引导不会自动再弹。

空对话上有三句可点的示例（见下一步）。身份和文书类型可以之后从设置里重开新手引导再选；按所选文书放进第一句交办。写作习惯不在首跑问卷里收集，可在记忆库里从改稿与对话确认后沉淀。

工作区是空的、又还没标记关闭时，引导仍会自己打开。这时主按钮是**直接开始**，和上面同一条路。已经选了身份或文书之后，这个按钮改成「不记这些，直接开始」，避免和主按钮抢，也不会悄悄丢掉刚选的项。

### 第四步：发第一句

空对话标题是「开始对话」。下面三句：

| 按钮       | 填进输入框的话                               |
| ---------- | -------------------------------------------- |
| 写一份备忘 | 查一下民法典关于违约金过高的规定，写个备忘。 |
| 审违约责任 | 审一下这份合同的违约责任。                   |
| 记下传票   | 记一下这份传票里的开庭时间和案号。           |

审合同和记传票要先把文件拖进输入框，再发。备忘可以空着手发。

**判断成功的标准**：状态条有一行「本轮按「××」处理」，「在办」里能看到这件事。中间步骤不会问要不要继续。

### 第五步：看一遍体检

体检没有单独的设置页了：模型连通在设置 → 模型与连接里点「验证模型」，其余跑 `pnpm lawmind:doctor`（或看 `GET /api/health`）。重点看三行：

| 看什么 | 期望                                   |
| ------ | -------------------------------------- |
| 模型   | 已配置、已连通                         |
| 索引   | 就绪（可能显示「陈旧」，重启后会重建） |
| 法源   | 演示语料就绪（非正式权威库）           |

界面写的是「演示语料就绪」，这是正常的。要查真法条得配语料或接端点（第 10 章）。

## 25.2 第一天下午：第一次交办

### 练习一：一句话

在对话里点「写一份备忘」，或自己说：「查一下民法典关于违约金过高的规定，写个备忘。」

**应该看到**：

- 状态条显示「本轮按「检索研究」处理」。
- 在「在办」里能看到这件事在跑。
- 最后产出一份备忘，落在工作区。

**如果它问你要不要继续**，那是 bug——中间步骤不该问。

### 练习二：丢一份材料

拖一份合同进输入框，说：「审一下违约责任。」

**应该看到**：

- 输入框上方出现钉选条。
- 产出审查意见（有审查结论、主要风险、修改建议三节）。
- 每条风险都指向具体条款，每条建议都有推荐措辞。

好的审查意见会把风险指到具体条款，并把建议写成可替换的句子。对不上时只提醒，不挡导出。不要为了过检查去凑「第×条」。

### 练习三：改稿

如果有原合同：

1. 从这份稿进入改稿。顶栏一级只有对话、工作台、在办；改稿是进去之后才出现的次级页。
2. 看红线面板，逐处决定接受或拒绝。
3. 接受之后签批。
4. 导出 Word，看是不是带修订轨。

**检查点**：导出的修订轨里，改动应该是**最短锚点**——比如只把「30 日」改成「45 日」，而不是整句删除加整句新增。

### 练习四：看「待我拍板」

有待决定时，侧栏或顶栏会出现「待我拍板」（工作台和改稿没有侧栏，按钮在顶栏）。点进去会到「在办」并只看需要你决定的事。点顶栏「在办」看到的是全部在办。

**理解一件事**：绝大多数动作不会在这里出现。只有外发、真授权、以及需要你判断的事项会进来。

## 25.3 第二天：把工作台用起来

### 建一个真实案件

侧栏「新建案件」。填：

- 案件名
- 客户
- 案由
- 对方当事人
- 案号、法院、审级、诉讼地位（诉讼案件）
- 开庭日

**注意**：只有勾了「利益冲突检查完成」和「委托确认」两项，案件状态才会进入「进行中」；否则是「收案」。这不是形式——它是工作台口径的一部分。

### 灌一份传票

把你手边的传票照片拖进对话，说「记一下」。

**应该看到**：

- 抽出的开庭时间、案号出现在工作台今日。
- 可能有一条「确认这次抽取」的待办（工作台手工入口仍要确认）。

**检查点**：不要出现「举证期限自动挂在开庭后面」这种情况——系统不猜这种依赖。

### 配一个每日计划

工作台里手写几条今天的计划。明天打开时，没做完的会**带过来**（往回看 14 天，最多带 8 条）。

### 看一次记忆

设置 → 记忆库。第一屏只有「待确认」。

**记住这条规则**：没有你的确认，系统不会往你的偏好档案里写东西。觉得某条对就确认，觉得不对就忽略。

## 25.4 第三天：把重复劳动交出去

### 配一个自动办件

设置 → 办案 → 自动办件。建一条，比如「每周一起草给客户的进展」。它准备草稿，不会自己把信发出去。

填写时会遇到**六个确认项**（这是个产品口径：下面这张表是其中需要逐字填的四项，另两项是**标题**与**计划**，各有既有输入框）：

| 项               | 怎么填                                       |
| ---------------- | -------------------------------------------- |
| 期望结果         | 「一页进展说明，包含本周完成事项和下周计划」 |
| 审批边界         | 「涉及金额的结论必须我先确认」               |
| 资料缺失时怎么办 | 默认「出部分结果并报告」                     |
| 什么时候通知我   | 建议「有问题时通知」                         |
| 其他两项         | 按你的习惯                                   |

**为什么认真填**：这四项（加上另外两项）会进任务书，直接影响模型怎么做。而且它防的是「你以为它会干 A，实际它在干 B」。

### 看一眼「在办」

自动跑出来的东西会进「在办」。左栏可以按团队或按队列看。

**一个技巧**：不想现在处理的可以「稍后看」，它会记住。

### 试一次委派

如果你建了两个助手，可以试试「让合同助手先审一遍，你把结论汇总给我」。

**注意**：被派的助手看不到你和它的对话，所以要写清要做什么、不要做什么。

## 25.5 第一周：把口径固定下来

### 校准你的偏好档案

用了一周之后，设置 → 记忆库 里应该攒了一些建议。这时候**批量采纳**低风险的风格项：

- 预览一下会写到哪、diff 多少。
- 确认之后一次落盘。

**只影响风格的建议可以批量**；涉及案件事实的一条条来。

### 配执业口径

设置 → 工作区 → 办案标准。这里可以写：

- 己方纸 / 对方纸的审查口径
- 违约金、管辖这些条款的默许立场

**它只影响之后的任务**，不会回改历史文件。

### 校准风险表述

如果你发现系统总是写得太保守或者太激进，改两个地方：

1. 设置里重开新手引导，改风险口径。
2. 设置 → 工作区 → 办案标准。工作区里的 `playbooks/CLAUSE_PLAYBOOK.md` 是同一份口径的文件，不必为了改一句去找路径。

### 试一次历史扫描（可选）

设置 → 工作区 里可以加「历史材料文件夹」，让系统扫一遍你的旧文件，总结出办案习惯。

**它会提出的建议也要你确认**，而且习惯要出现 **5 次**才会入队（第 6 章）。

## 25.6 常见的第一周困惑

### 「为什么它不问我？」

这是设计。只有外发、改原稿这类真授权才打断，中间步骤不问。

**如果你确实想让它停下来**，可以在指令里明确写「先给我看方案，我确认后再写」。

### 「为什么它改了原稿？」

它不会改原稿。**改稿路径是「拷副本 + 在副本上落修订轨」**，原文件一个字节都不动。

如果你看到原文件变了，那说明走的不是修订轨那条路（比如用了 `render_document`）。

### 「为什么导出要我签批两次？」

两个不同的门：

- **必核清单**：逐项确认（第 12 章）。
- **签批**：最终批准。

必核清单没勾完，不能签批。这是你自己的确认，不是稿子被关键词挡住。

### 「为什么引用它说『待核实』？」

说明这条没检索到来源。系统**不编条号**，查不到就标待核实（第 10 章）。

配了法源之后会好很多。

### 「为什么有些技能不生效？」

技能要么被主推（进提示词正文），要么只在索引里（要 `read_skill` 才读）。第 20 章列了哪些技能不在主推行列。

### 「为什么同一个问题两次答案不一样？」

如果两次都过了验收门，那差别通常在表述而不在事实。想要更稳，可以：

- 把口径写进 `playbooks/CLAUSE_PLAYBOOK.md`。
- 把看过的偏好确认进记忆，让同样交办不飘。法律判断仍交给模型。
- 用「按××口径办」点明立场。

稳定性靠已确认的口径，不靠把模型关进一份禁写清单。

## 25.7 一个效率窍门合集

| 想干什么           | 怎么做                                            |
| ------------------ | ------------------------------------------------- |
| 钉一份文件         | 拖进输入框，或者 `@` 文件名                       |
| 从空对话起一句     | 点「写一份备忘」「审违约责任」或「记下传票」      |
| 粘贴截图           | 直接在输入框粘贴（会钉选）                        |
| 换会话但带上前文   | 用「承前分叉」                                    |
| 不选办件           | 直接说事；系统自己判断                            |
| 强制指定能力       | 写 `$skill contract.review` 或「【办件】能力：…」 |
| 搜历史对话         | `⌘⇧O` 或 `/chats`                                 |
| 对话变长了         | 输入栏会出现「这场对话」，可整理或另开一段        |
| 让某份技能被看到   | 在指令里点名要用它                                |
| 撤销刚才的档案写入 | 对话里说「撤销刚才那次写入」                      |
| 一次跑一件长活     | 用工作流（「先让 A 做…再让 B 做…」）              |
| 复现同一张表       | 审查表的行序按路径排，两次跑结果一致              |

## 25.8 该找谁问

| 问题类型         | 去哪里                                                  |
| ---------------- | ------------------------------------------------------- |
| 界面怎么用       | 设置 → 关于 → 免责声明旁边的帮助；或者本文档第 2、24 章 |
| 报错看不懂       | 附录 D 排障手册；把报错原文搜一下                       |
| 效果不满意       | 先看记忆库和执业口径有没有配；再看是不是缺材料          |

| 要不要开某个开关 | 第 15 章（安全）、第 17 章（自动办件）                  |
| 团队部署         | 第 27 章                                                |

## 25.9 一句话总结

上手只要三件事：**连上模型、第一次交办、看一次体检**。剩下的都是慢慢把口径磨准——而口径主要靠记忆库和工作区里的 playbook，不靠背提示词。
