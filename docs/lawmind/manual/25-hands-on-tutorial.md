# 第 25 章 从零上手实操

这一章是一份分步教程，从装好到用顺，按时间顺序走一遍。

## 25.1 第一天上午：装上、跑通

### 第一步：装

下载对应系统的安装包（`LawMind-<版本>-<系统>-<架构>.<扩展名>`），或者从源码跑：

```bash
git clone https://github.com/sunhl4/LawMind.git
cd LawMind
corepack enable
corepack prepare pnpm@10.23.0 --activate
pnpm install
pnpm lawmind:desktop
```

**判断成功的标准**：桌面窗口打开，能看到侧栏和顶栏。**不要**去浏览器打开 5174（第 2 章）。

### 第二步：连模型

首跑会弹连接向导。三件事：

1. 选一个推荐栈（DeepSeek Flash / 通义千问 / OpenAI 兼容），或者自己填 Base URL 和模型名。
2. 填 API Key。
3. 选工作区（默认在用户数据目录下）。

**如果模型能填完但保存不了**，说明系统密钥链不可用（第 2 章那段文案）。要么启用密钥链，要么手工写 `.env.lawmind`。

### 第三步：走完 30 秒首跑

选项会写进你的偏好档案，所以认真选：

| 选项                                         | 影响                   |
| -------------------------------------------- | ---------------------- |
| 角色（独立执业 / 律所协办 / 合伙人）         | 种子交办的语气和深度   |
| 写作风格（简洁直接 / 详尽论证 / 偏诉讼对抗） | 之后所有草稿的默认文风 |
| 风险取向（偏保守 / 平衡 / 偏进取）           | 风险表述的强度         |
| 客户口吻（正式严谨 / 通俗易懂 / 亲和说明）   | 对外材料的语气         |
| 起始交付物                                   | 建第一个案件时用的类型 |

首跑会**自动建一个演示案件**并生成一条种子交办。这不是摆设——它让你马上能看到一条完整的链路。

### 第四步：看一遍体检

设置 → 系统健康。重点看三行：

| 看什么 | 期望                                   |
| ------ | -------------------------------------- |
| 模型   | 已配置、已连通                         |
| 索引   | 就绪（可能显示「陈旧」，重启后会重建） |
| 法源   | `sample-ready`（只有演示语料，正常）   |

法源显示 `sample-ready` 是**正常**的。要查真法条得配语料或接端点（第 10 章）。

## 25.2 第一天下午：第一次交办

### 练习一：一句话

在对话里说：「查一下民法典关于违约金过高的规定，写个备忘。」

**应该看到**：

- 状态条显示「本轮按检索研究处理」。
- 在「在办」里能看到这件事在跑。
- 最后产出一份备忘，落在工作区。

**如果它问你要不要继续**，那是 bug——中间步骤不该问。

### 练习二：丢一份材料

拖一份合同进输入框，说：「审一下违约责任。」

**应该看到**：

- 输入框上方出现钉选条。
- 产出审查意见（有审查结论、主要风险、修改建议三节）。
- 每条风险都指向具体条款，每条建议都有推荐措辞。

如果风险章节里只有「本合同存在风险」这种泛泛的话，说明**条款锚点检查**会拦下它（`contract.review.clause_anchor`）。

### 练习三：改稿

如果有原合同：

1. 在「改稿」工作面打开这份稿。
2. 看红线面板，逐处决定接受或拒绝。
3. 接受之后签批。
4. 导出 Word，看是不是带修订轨。

**检查点**：导出的修订轨里，改动应该是**最短锚点**——比如只把「30 日」改成「45 日」，而不是整句删除加整句新增。

### 练习四：看「待我拍板」

侧栏那个徽标按钮点进去。它会把你带到「在办」并聚焦到需要你决定的事。

**理解一件事**：绝大多数动作不会在这里出现。只有外发、真授权、以及需要你判断的事项会进来。

## 25.3 第二天：把工作台用起来

### 建一个真实案件

侧栏「新建案件」。填：

- 案件名
- 客户
- 案由
- 对方当事人
- 案号、法院、审级、诉讼地位（诉讼案件）
- 开庭日

**注意**：只有勾了「利益冲突检查完成」和「委托确认」两项，案件状态才会进入「进行中」；否则是「收案」。这不是形式——它是工作台口径的一部分。

### 灌一份传票

把你手边的传票照片拖进对话，说「记一下」。

**应该看到**：

- 抽出的开庭时间、案号出现在工作台今日。
- 可能有一条「确认这次抽取」的待办（工作台手工入口仍要确认）。

**检查点**：不要出现「举证期限自动挂在开庭后面」这种情况——系统不猜这种依赖。

### 配一个每日计划

工作台里手写几条今天的计划。明天打开时，没做完的会**带过来**（往回看 14 天，最多带 8 条）。

### 看一次记忆

设置 → 记忆库。第一屏只有「待确认」。

**记住这条规则**：没有你的确认，系统不会往你的偏好档案里写东西。觉得某条对就确认，觉得不对就忽略。

## 25.4 第三天：把重复劳动交出去

### 配一个自动办件

设置 → 办案 → 自动办件。建一条，比如「每周一给客户发进展」。

填写时会遇到**六个确认项**（这是个产品口径：下面这张表是其中需要逐字填的四项，另两项是**标题**与**计划**，各有既有输入框）：

| 项               | 怎么填                                       |
| ---------------- | -------------------------------------------- |
| 期望结果         | 「一页进展说明，包含本周完成事项和下周计划」 |
| 审批边界         | 「涉及金额的结论必须我先确认」               |
| 资料缺失时怎么办 | 默认「出部分结果并报告」                     |
| 什么时候通知我   | 建议「有问题时通知」                         |
| 其他两项         | 按你的习惯                                   |

**为什么认真填**：这四项（加上另外两项）会进任务书，直接影响模型怎么做。而且它防的是「你以为它会干 A，实际它在干 B」。

### 看一眼「在办」

自动跑出来的东西会进「在办」。左栏可以按团队或按队列看。

**一个技巧**：不想现在处理的可以「稍后看」，它会记住。

### 试一次委派

如果你建了两个助手，可以试试「让合同助手先审一遍，你把结论汇总给我」。

**注意**：被派的助手看不到你和它的对话，所以任务要说清。系统里有 `goal` / `not_goal` 就是为了这个。

## 25.5 第一周：把口径固定下来

### 校准你的偏好档案

用了一周之后，设置 → 记忆库 里应该攒了一些建议。这时候**批量采纳**低风险的风格项：

- 预览一下会写到哪、diff 多少。
- 确认之后一次落盘。

**只影响风格的建议可以批量**；涉及案件事实的一条条来。

### 配执业口径

设置 → 工作区 → 办案标准。这里可以写：

- 己方纸 / 对方纸的审查口径
- 违约金、管辖这些条款的默许立场

**它只影响之后的任务**，不会回改历史文件。

### 校准风险表述

如果你发现系统总是写得太保守或者太激进，改两个地方：

1. 首跑那几个偏好（可以在设置里重开首跑改）。
2. `playbooks/CLAUSE_PLAYBOOK.md`（工作区里的文件，你可以直接编辑）。

### 试一次历史扫描（可选）

设置 → 工作区 里可以加「历史材料文件夹」，让系统扫一遍你的旧文件，总结出办案习惯。

**它会提出的建议也要你确认**，而且习惯要出现 **5 次**才会入队（第 6 章）。

## 25.6 常见的第一周困惑

### 「为什么它不问我？」

这是设计。只有外发、改原稿这类真授权才打断，中间步骤不问。

**如果你确实想让它停下来**，可以在指令里明确写「先给我看方案，我确认后再写」。

### 「为什么它改了原稿？」

它不会改原稿。**改稿路径是「拷副本 + 在副本上落修订轨」**，原文件一个字节都不动。

如果你看到原文件变了，那说明走的不是修订轨那条路（比如用了 `render_document`）。

### 「为什么导出要我签批两次？」

两个不同的门：

- **必核清单**：逐项确认（第 12 章）。
- **签批**：最终批准。

清单没勾完会报 `checklist_incomplete`。

### 「为什么引用它说『待核实』？」

说明这条没检索到来源。系统**不编条号**，查不到就标待核实（第 10 章）。

配了法源之后会好很多。

### 「为什么有些技能不生效？」

技能要么被主推（进提示词正文），要么只在索引里（要 `read_skill` 才读）。第 20 章列了哪些技能不在主推行列。

### 「为什么同一个问题两次答案不一样？」

如果两次都过了验收门，那差别通常在表述而不在事实。想要更稳，可以：

- 把口径写进 `playbooks/CLAUSE_PLAYBOOK.md`。
- 把偏好确认进记忆（减少模型的自由度）。
- 用「按××口径办」这类明确指令。

稳定性主要靠口径固定，不是靠提示词技巧。

## 25.7 一个效率窍门合集

| 想干什么           | 怎么做                                            |
| ------------------ | ------------------------------------------------- |
| 钉一份文件         | 拖进输入框，或者 `@` 文件名                       |
| 粘贴截图           | 直接在输入框粘贴（会钉选）                        |
| 换会话但带上前文   | 用「承前分叉」                                    |
| 不选办件           | 直接说事；系统自己判断                            |
| 强制指定能力       | 写 `$skill contract.review` 或「【办件】能力：…」 |
| 搜历史对话         | `⌘⇧O` 或 `/chats`                                 |
| 看上下文用量       | 输入框工具栏的用量表                              |
| 让某份技能被看到   | 在指令里点名要用它                                |
| 撤销刚才的档案写入 | 对话里说「撤销刚才那次写入」                      |
| 一次跑一件长活     | 用工作流（「先让 A 做…再让 B 做…」）              |
| 复现同一张表       | 审查表的行序按路径排，两次跑结果一致              |

## 25.8 该找谁问

| 问题类型         | 去哪里                                                  |
| ---------------- | ------------------------------------------------------- |
| 界面怎么用       | 设置 → 关于 → 免责声明旁边的帮助；或者本文档第 2、24 章 |
| 报错看不懂       | 附录 D 排障手册；把报错原文搜一下                       |
| 效果不满意       | 先看记忆库和执业口径有没有配；再看是不是缺材料          |
| 数据在哪         | 附录 C 文件布局                                         |
| 要不要开某个开关 | 第 15 章（安全）、第 17 章（自动办件）                  |
| 团队部署         | 第 27 章                                                |

## 25.9 一句话总结

上手只要三件事：**连上模型、第一次交办、看一次体检**。剩下的都是慢慢把口径磨准——而口径主要靠记忆库和工作区里的 playbook，不靠背提示词。
