# 第 33 章 任务速查手册

这一章是「我要做 X，该怎么走」的速查。按任务类型分组，每条给出**步骤**和**注意点**。

## 33.1 怎么用这一章

每条格式：

```text
任务名
  入口：从哪个界面/怎么开口
  步骤：1 → 2 → 3
  注意：容易踩的地方
```

任务是端到端的具体操作，不是功能列表。功能清单在第 23 章（工具）和第 24 章（界面）。

## 33.2 审查类

### 审一份合同

```text
入口：对话，拖入合同
步骤：
  1. 说「审一下这份合同的违约责任和解除条款，我方是买方」
  2. 等在办跑完
  3. 打开「改稿」看正文
  4. 走必核清单
  5. 签批
  6. 导出（要修订轨就说明）
注意：
  - 风险最好指向具体条款，建议最好给推荐措辞（缺了会提醒，不挡导出）
  - 「只出意见不改原稿」要说出来
```

### 审一批合同做成表

```text
入口：对话，拖入文件夹
步骤：
  1. 说「把这些合同的付款条件、责任上限、解除条款整理成一张表，每条要有出处」
  2. 模型自己决定要不要先看目录；没先探查也不会被拦住
  3. 批量抽取（模式优先，扫描件走 OCR 兜底）
  4. 看汇总（多少格有出处、多少格弃答）
  5. 核对关键行，锁住
  6. 导出 xlsx，或推进到 docx
注意：
  - 抽不动会写「无法判断（证据不足）」，这是正常的
  - 锁住的行批量重抽不会覆盖
  - 两次跑出来的表是一样的（行序按路径排）
```

### 独立审稿没过怎么办

```text
症状：签批或导出时提示审稿未过
步骤：
  1. 看审稿结论里的缺口清单
  2. 逐条处理（补引用、改表述、标待核实）
  3. 重新跑（证据变了会自动重跑）
注意：
  - 缺口分两类：机械项（代码判的，必须过）和判断项（可以不同意的）
  - solo 档的修订稿审稿是 advisory（不挡出稿）；律所档是 block
```

## 33.3 改稿类

### 在 Word 里就地改

```text
入口：Word 任务窗格 → 「审这份」
步骤：
  1. 在 Word 里打开合同
  2. 点「审这份」
  3. 桌面端自动跑（不用切回去）
  4. 插件刷新后把修订轨落进 Word
注意：
  - 插件只处理「最短锚点」；整节重写会提示回桌面端
  - 文件在点击后被改过会转 stale，重新点一次
  - Word 或 WPS 连不上时：完全退出对应软件再打开；仍不行就在设置 → 外观点「重新连接」。加载项还是半成品，见 LAWMIND-WORD-ADDIN.md 开头
```

### 批量统一称谓

```text
入口：对话，钉多份文书
步骤：
  1. 说「这五份文书里的『甲方』都改成『买方』，当事人名字也统一」
  2. 如果有歧义，整批会停（零写入）并告诉你哪个锚点有问题
  3. 确认是统一替换就重来一次（模型会声明 occurrences: "all"）
注意：
  - 整批停是保护，不是故障
  - 某份里没有这个锚点不算错，会记进变更清单
```

### 出一份带修订轨的 Word

```text
入口：改稿工作面
步骤：
  1. 确认有原合同基线（有原件走「拷副本」那条路）
  2. 落改（红线面板逐处接受/拒绝）
  3. 检查红线数量不为 0（空修订不许导出）
  4. 导出
注意：
  - 导出后会在产物旁边写一份清单文件，里面有 applied/ambiguous 统计
  - 原文件一个字节都不动
  - 引擎永远不会自动打开 Word
```

## 33.4 材料与档案类

### 把一批材料建案并归位

```text
入口：对话
步骤：
  1. 拖入文件夹，说「整理一下，抽出当事人和案由」
  2. 系统探查目录、批量读、抽事件
  3. 确认抽取结果
  4. 写穿到卷宗与期限
注意：
  - 只提升「真正读到」的值，不猜立场
  - 每次写入都可以撤销（revert_desk_write）
```

### 谈话记录入档

```text
入口：对话
步骤：
  1. 粘贴谈话记录，说「整理一下，把当事人和案由记进案子」
  2. 看整理出的结构化摘要（需求/事实/争点/候选案由/证据缺口）
  3. 确认 → 写穿
注意：
  - 摘要先落一个待确认文件，确认后才进档案
  - 立场不明时只登记当事人与诉讼地位
```

### 收本机文件进本案

```text
入口：对话，或文件拖拽
步骤：
  1. 拖入。已经在工作区或本机文件夹里的，只钉上引用，不复制
  2. 工作区外的文件会收进本案材料（当前有案件时）或上传区
  3. 或说「把这几份收进本案」
注意：
  - 本机文件夹默认只读；要改就在案件材料目录里改
  - 单独文件有 200MB 上限；整目录有文件数/总量上限
```

### 整理乱掉的案件材料

```text
入口：对话
步骤：
  1. 说「本案材料有点乱，提个整理方案给我看看」
  2. 看方案（此时不动文件）
  3. 确认 → 执行
  4. 不满意 → 撤销
注意：
  - 三步是固定的：提计划 → 确认 → 执行
  - 范围限制在材料目录内
```

## 33.5 期限与事件类

### 从传票登记开庭

```text
入口：拖入传票照片 + 「记一下」
步骤：
  1. 抽取（OCR 或视觉兜底）
  2. 看抽取结果
  3. 确认写入
注意：
  - 开庭默认提前 72 小时提醒
  - 不会自动把举证期限串到开庭后面
  - 抽取是启发式，写进工作台前要确认
```

### 手工记一条期限

```text
入口：工作台，或对话
步骤：说「记一下：下个月 15 号之前提交证据」
注意：可以设提前提醒小时数、设前置期限
```

### 导出日历

```text
入口：案件内的期限列表
步骤：导出 .ics，然后导入系统日历
注意：只生成文件，不直接写飞书/Graph 日历
```

## 33.6 检索与引用类

### 查法条并出备忘

```text
入口：对话
步骤：
  1. 说「查一下民法典关于违约金过高的规定，写个备忘」
  2. 系统先试检（写条号前必须先查）
  3. 同一轮写出备忘；栏目按规格保留，无命中标【待核实】
注意：
  - 没查到会保留栏目并标【待核实】，不是删掉
  - 演示语料会打水印
```

### 查类案

```text
入口：对话
步骤：说「找一下类似的买卖合同违约判例」
注意：
  - 本机没接类案库时会诚实说明，且不编案号
  - 接了之后 `GET /api/health` 的 `doctor.scorecardRows` 里会有「类案」行
```

### 看某条引用支撑了什么

```text
入口：改稿面或对话里的来源
步骤：点开来源 → 看预览（含支撑了哪些结论、被哪些章节引用）
注意：这是「引用可回溯」在界面上的样子
```

### 用本所旧案参照

```text
前提：开启 LAWMIND_ALLOW_CROSS_MATTER_SEARCH=1 并重建索引
步骤：说「看看我们所以前类似的案子里怎么写这段」
注意：
  - 默认关（伦理墙姿态）
  - 命中只作写法参照，事实以本案为准
  - 术语不一致时会报出未映射的外来叫法
```

## 33.7 协作类

### 派活给另一个助手

```text
入口：对话
步骤：说「让合同助手先审一遍，把结论给我」
注意：
  - 被派的助手看不到你的对话，任务要说全
  - 结果会自动回传到本会话
  - 有并发上限（5）和深度上限（3）
```

### 开个会讨论

```text
入口：会议室工作面
步骤：
  1. 选范围（临时 / 某案件）
  2. 选参会人、钉材料
  3. 开始讨论
  4. 可以打断 → 暂停 → 继续 → 结束
注意：
  - 纪要开头写明「非对外法律意见」
  - 纪要写在案件目录；参会人选择记在本机，关掉应用还在
```

### 多人协作一个案子

```text
前提：matterReplicaCollab 开着（各版本默认开；可用 matterReplica.enabled 关掉）
步骤：
  1. 主办建名册
  2. 生成邀请码发给同事（14 天有效）
  3. 同事接受邀请
  4. 各自改卷宗、传材料，自动同步
注意：
  - 内容端到端加密，密钥不出本机
  - 同文件冲突会留两份（一份带「（冲突）」后缀）
  - 移除成员会做密钥轮换
```

## 33.8 自动化类

### 建一个定时任务

```text
入口：设置 → 办案 → 自动办件
步骤：
  1. 选预设（或自定义）
  2. 填六个确认项（期望结果 / 审批边界 / 缺资料怎么办 / 何时通知 等）
  3. 设排期
  4. 启用
注意：
  - 六项没填全会拒绝启用
  - 失败和待拍板**永远会通知**（不受通知策略影响）
  - 缺资料默认「出部分结果并报告」
```

### 从一件活变自动化

```text
入口：对话
步骤：干完一件事之后说「以后每周一都这样来一次」
注意：需要案件上下文（否则报 work_missing_matter）
```

### 处理卡住的自动化

```text
步骤：
  1. 看「在办 / 待我拍板」有没有待处置项
  2. 看 GET /api/automations/:id/runs
  3. 看 GET /api/jobs?status=running
注意：门禁停下时应该产生律师可见的待处置项；如果只有对话里一句话，那是缺陷
```

## 33.9 记忆与口径类

### 确认一条记忆

```text
入口：设置 → 记忆库
步骤：看建议 → 确认 或 改写（预览/稍后/忽略在「更多」里）
注意：确认之前不会写入任何东西
```

### 批量采纳风格项

```text
步骤：
  1. 记忆库里的批量入口
  2. 预览（会显示写到哪、diff 多少）
  3. 确认 → 一次落盘
注意：批量只包含低风险的风格类；案件事实一条条来
```

### 配执业口径

```text
入口：设置 → 工作区 → 办案标准（或直接编辑 playbooks/CLAUSE_PLAYBOOK.md）
注意：只影响之后的任务，不回改历史
```

### 撤销一次档案写入

```text
入口：对话
步骤：说「撤销刚才那次写入」
注意：依赖 desk-writes.jsonl 的记录
```

## 33.10 交付与导出类

### 出一份正式 Word

```text
步骤：
  1. 确认交付物类型对不对（影响验收规格）
  2. 走必核清单
  3. 签批
  4. 导出
注意：
  - 占位符没清理会被拦（某些类型要求外发前解决）
  - 只有「已驳回」状态绝对不许渲染
```

### 出 PPT

```text
步骤：说「做成培训课件，12 页」
注意：用案件材料前必须脱敏或声明已脱敏（手机号/身份证是硬拦）
```

### 出审查表 xlsx

```text
步骤：在审查表编辑器里点导出，或用 API
注意：表格本体在侧车文件里，正文只有 markdown 预览
```

## 33.11 排障类

### 查一个报错的来源

```text
步骤：
  1. 复制报错原文
  2. 在仓库里搜（报错文案通常就在代码里，附近有解释为什么的注释）
  3. 对照附录 D
```

### 收集诊断信息

```text
步骤：
  1. pnpm lawmind:doctor --json
  2. 诊断包（GET /api/support/bundle?download=1，脱敏 zip）
  3. 相关审计导出（按 taskId）
```

### 修投影漂移

```text
步骤：
  1. pnpm lawmind:ops matter-consistency 看问题
  2. POST /api/matters/repair-projections
```

### 修会话历史

```text
步骤：pnpm lawmind:doctor --fix
注意：修的是工具调用配对
```

### 重建索引

```text
步骤：
  1. LAWMIND_ALLOW_INDEX_REBUILD=1
  2. POST /api/search/workspace/rebuild
```

## 33.13 一张「先做什么」的判断表

| 你想…            | 先做这个                                     |
| ---------------- | -------------------------------------------- |
| 让它更懂我的习惯 | 用一两周，然后去记忆库确认建议（第 25 章）   |
| 让它少问问题     | 检查是不是材料没给够（意图编译靠材料形态）   |
| 让它更稳         | 把口径写进 playbook，确认记忆；不要改提示词  |
| 让它更省         | 取消不需要的钉选；用量桶只在引擎里排查       |
| 让它更安全       | 配策略文件（出口模式、白名单、沙箱、伦理墙） |
| 让它更自动化     | 配自动办件；但注意「失败永不静默」这条       |
| 出问题找原因     | `pnpm lawmind:doctor` → 诊断包 → 审计        |

## 33.14 已知坑（本章相关）

- **丢文件夹时先看目录是建议，不是硬门禁。** 模型自己决定要不要先探查；没探查也不会被拦住。
- **整批停是保护。** 遇到「整批未写入」先看冲突说明。
- **抽取是启发式。** 写进工作台前确认，不要指望它 100% 准。
- **跨案检索默认关。** 不开就查不到其他案件。工作区查找会写明「未检索其他案件」，不要当成所里没有类似案子。
- **会议记录不是对外意见。** 那句说明不能删。
- **自动化失败一定会通知。** 收不到就说明链路有问题。
- **记忆不确认不写入。** 看到「它怎么知道我偏好这个」时，去看记忆库。
- **`--fix` 和「重建索引」是两件事。** 前者修会话配对，后者重建 FTS。
