# LawMind 团队协作能力说明（律所版）

> 面向律所决策者与 IT 负责人。技术实现见 `LAWMIND-MATTER-REPLICA.md`；
> 与市面产品对照见 `LAWMIND-MATTER-REPLICA-GAP-REVIEW.md`。
>
> **文档状态**：能力与边界均以本仓库自动化验收探针的实测结果为准
> （`pnpm lawmind:matter-replica:probe`，14 条判据）。文中标注「未做」的部分**不要**按已交付理解。

## 一句话

每位律师继续用自己电脑上的 LawMind 办案；**邀请同事进入「这一案」**，
材料、改稿、签出、删除在各自电脑上保持同步，**不需要律所自备服务器或共享盘**。

## 律师怎么用

1. **每人一套 LawMind**，各自打开自己的案件列表与工作台。
2. 主办律师在案件里点**邀请同事**，填同事邮箱、选角色，把邀请码发给对方。
3. 同事在自己机器上粘贴邀请码，**同一件案子**就出现在他的侧栏里。
4. 助理把证据拖进案件材料树 → 主办、协办那边**不必手动同步**，材料自己出现。
5. 要改合同 Word，先点**我来改**（签出）：其他人在此期间看到该文件被占用，不会互相覆盖。
6. 谁在何时邀请、加入、签出、入卷、轮换密钥 —— 全部进入**可导出的审计报表**。

> 关键差别：协作的单位是**案件**，不是「一个共享文件夹」。没有被邀请的案件，
> 在同事的 LawMind 里根本不存在。

## 与网盘 / 在线文档的区别

|                    | 坚果云类网盘          | 腾讯/石墨类在线文档  | **LawMind 协作**                     |
| ------------------ | --------------------- | -------------------- | ------------------------------------ |
| 共享单位           | 任意文件夹            | 单个文档             | **案件（含材料、记录、成员）**       |
| 未授权内容         | 可能仍在盘里被搜到    | 取决于分享设置       | **同事侧根本不存在（伦理墙）**       |
| 改 Word 合同       | 冲突副本，修订轨被毁  | 同屏编辑，修订轨被毁 | **签出保护 + 保留 Word 修订轨**      |
| 证据入卷           | 无编号、无哈希        | 不适用               | **内容寻址（SHA-256），改动可检出**  |
| 谁能看正文         | 平台可读              | 平台可读             | **端到端加密：云端只有密文**         |
| 助手能否用上新材料 | 网盘对 LawMind 不可见 | 不适用               | **材料进了案件，工作台与助手直接用** |

## 安全与合规

| 能力              | 做法                                                                     |
| ----------------- | ------------------------------------------------------------------------ |
| **端到端加密**    | 材料与案件叙事在**律师设备上**加密后上传；云服务端只存密文，**没有密钥** |
| **完整性校验**    | 下载前比对内容哈希，不符即**拒收**并记录事件；上传时服务端亦校验         |
| **密钥轮换**      | 撤销邀请或移出成员后**立即轮换**案件密钥；被撤销者读不了之后的内容       |
| **角色权限**      | 主办 / 共同主办 / 协办 / 助理 / 只读 / 外协，权限在**服务端**强制执行    |
| **审计链**        | 协作动作写入 HMAC-SHA256 链；改动任何一条都会导致链校验失败              |
| **审计报表**      | 按动作 / 律师 / 案件汇总导出（Markdown / JSON），含**链完整性结论**      |
| **租户隔离**      | 不同律所的数据在存储路径层面物理隔离                                     |
| **Solo 不受影响** | 不开启协作时，行为与单机版完全一致（无新增入口、无后台行为）             |

## 部署形态

| 形态                   | 说明                                               | 适用                   |
| ---------------------- | -------------------------------------------------- | ---------------------- |
| **LawMind 云（推荐）** | 律所无需任何服务器；律师装桌面应用、登录、邀请即用 | 绝大多数律所           |
| **私有化**             | 把同一套桌面端指向律所自己的服务端（同一契约）     | 数据不出所、有 IT 能力 |

运行方式（供 IT 参考）：

```bash
pnpm lawmind:matter-cloud -- --setup   # 建租户，打印一次管理员令牌
pnpm lawmind:matter-cloud              # 启动服务端
```

**部署责任（本产品不含）**：TLS 证书与反向代理、访问限流、备份策略、密钥托管（KMS）、
审计日志留存期。生产部署**必须**置于以上措施之后，不得直接暴露明文 HTTP。

## 明确的边界（请按此评估采购）

以下项目**当前未交付**，不应按已有能力理解：

1. **运维面**：对象存储后端（当前为本地磁盘）、令牌过期与自动轮换、限流、备份 —— 需随实际部署补齐。
2. **审计留存策略**：报表支持时间范围筛选，但没有自动归档与保留期管理。
3. **中继来源认证**：内容完整性已由哈希与加密保证，但同步日志条目本身**未签名**。
4. **元数据加密**：材料正文已加密；但邮箱、文件名等**元数据**在同步日志中仍为明文。
5. **外协隔离粒度**：外协（仅上传）角色目前会获得案件密钥；细粒度隔离需按子树加密。
6. **实时同屏编辑 Word**：**刻意不做** —— 它会破坏律师赖以协作的 Word 修订轨。
7. **移动端**：当前产品为桌面端（macOS / Windows）。

## 采购常见问题

**Q：律所需要准备服务器吗？**
不需要。默认走 LawMind 云。只有数据不出所的场景才需要私有化部署。

**Q：平台方能看到客户材料吗？**
看不到正文。材料在律师设备上加密后才上传，密钥不经云端。平台能看到的是
「谁、哪个案件、什么角色」这类**为执行权限所必需**的信息。

**Q：两个人同时改一份合同会互相覆盖吗？**
不会。改前需**签出**；未签出方的同步会跳过该文件而不是覆盖。冲突时保留双方副本，
不会静默丢内容。

**Q：审计能证明「谁在何时动了卷宗」吗？**
能，且**报表可验篡改**：协作事件写入 HMAC-SHA256 链，改动任意一条链校验即失败。
报表会把链完整性结论直接印在文首。

**Q：删掉的材料会传到同事那边吗？**
会。删除同步到同事机器，且不会「自己又回来」（这一点有专门的回归测试）。

**Q：律师会不会因为协作变难用？**
不会。不邀请同事时，产品与单机版完全一致 —— 这是刻意的设计约束，
也是验收探针里的对照判据。

## 验收与可复现证据

本说明中标注为「已交付」的能力，全部由仓库内探针实测，可随时复跑核对：

```bash
pnpm lawmind:matter-replica:probe            # 打印 14 条判据与逐条证据
pnpm lawmind:matter-replica:probe -- --strict # 任一判据不成立即退出码 1
```

探针使用两个**完全独立**的工作区 + 一个真实服务端，只走产品正式入口
（建邀请 / 接受邀请 / 签出 / 同步），不依赖测试桩。判据涵盖：
跨机器邀请、成员回传、签出可见、删除传播、内容完整性、密文防降级、
叙事不明文出网、密钥轮换、无共享盘共案、后台自动同步、云权威邀请、协作审计。
