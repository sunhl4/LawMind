## 0. 问题重述

外部评审的核心论点：

1. 审计/可追溯是内部合规，不是客户价值；北极星应是**无人工干预完成率 / 一次通过率 / 律师审阅时长**。
2. Codex 能「人几乎不参与」是因为代码有**可自动验证的客观信号**（编译、测试、lint）；法律没有这个信号，所以只能靠人审。
3. 「律师审批是终点」应反转为「**默认自动交付 + 例外升级**」。
4. 「每次零检索」应换成**立场库 + 先例库**的确定性沉淀，越用越像这位律师。
5. 「不满足就丢回给律师」应换成**自检 → 自动修订 → 再自检**的有界闭环。
6. 需要**法律任务 benchmark**（黄金答案）量化「达到律师期待水平」。
7. 输出应**决策导向**（顶部三行可拍板），审计细节折叠。

本文件先逐条裁决（§1），再给目标架构（§2）与 500 人天计划（§3–§7）。

### 0.1 已锁定产品决策（历史扫描 · 2026-08-29）

1. **两种材料都要**：按案件整理好的文件夹 **和** 杂烩堆（桌面/下载/未分类）。整理夹建议建案；杂烩只进未分类桶，**不自动建案**。
2. **可添加多个根**：最多 **3** 个扫描根。
3. **重复改法 ≥5 次**进入记忆**待确认**（不静默写入习惯）。同一条款类型冲突时，**以最新修改时间（mtime）为准**。
4. **排期**：Phase 0 先做扫描编目 + 知识入队 + lint 内核；习惯层随 WS4；决策头延后（高感知、低杠杆）。

## 1. 深度 Review：逐条裁决

裁决口径：**接受** = 方向对且按原样排期；**修正** = 方向对但须按仓库现状/执业约束改形；**反对** = 不做或明确延后。

### 1.1 审计降权 —— **接受（降 UI 权重，不降采集）**

评审说得对：律师问的是「敢不敢说能直接用」，不是「审计有多少条」。但审计不是可砍的成本，它是三件事的底座：

- 律师执业责任（法律文书对外责任仍在律师）；
- 所内合规与 Firm 版卖点；
- 本路线图的飞轮本身（lint 逃逸、立场学习、benchmark 影子模式全都从审计/事件流取数）。

**裁决**：UI 与营销口径降权（默认折叠、按需展开、不再当头条卖点）；采集与事件流**加强**——它是 §2 飞轮的燃料。北极星指标按评审重构（§2.4）。

### 1.2 法律正确性信号（法律编译器）—— **接受，最高优先级，但须诚实界定覆盖边界**

评审的核心洞察成立，且仓库现状印证了缺口：

**已有（形状 + 出处 + 改稿卫生的编译器）**：

- 验收 spec / 占位符 / 骨架密度（`src/lawmind/deliverables/validator.ts`、`scaffold-status.ts`）
- 必核清单人工勾选硬闸（`verification-checklist.ts` → `assertChecklistCompleteForApprove`）
- 引用**出处**完整性（`drafts/citation-integrity.ts`：citation ID ∈ research bundle）
- IRAC 结构计数（`reasoning-validator.ts`：minIssues / 争点有据）
- 外科改稿幅度与空红线硬闸（`surgical-span-gate.ts`、`tracked-render-hunk-gate.ts`）
- 分族审查要点（`platform/word-revision-packs.ts`）——但只是**提示**，不执行核对

**没有（法律实体正确性的编译器）**：

- 法条**有效性**核对（引用条文是否现行有效、条文号是否映射正确；`npc-flk.ts` 的 `sxx` 元数据只用于展示，未升级为 gate）
- 可执行规则引擎（「民间借贷利率 ≤ 4×LPR」「定金 ≤ 20%」「或裁或诉无效」对草案数字/条款自动核对）
- 文书一致性（大小写金额、定义词、交叉引用、日期逻辑、签章栏）
- `calculate` 工具会算 LPR/时效，但**从不主动对草案跑**

**诚实边界（重申）**：Phase 0–1 的「编译器」约 70% 是**文书一致性**（金额、定义词、交叉引用、编号、日期、要式），不是完整法律 gcc，也没有法宝/Lexis 联调。lint 通过 =「N 项机械核对，已知缺陷未漏网」，**不是**「法律正确」。

**裁决**：接受为 WS1（120 人天；族规则包后置，先买卖+借款）。三条设计约束：

1. **诚实边界**：lint 通过 ≠ 法律正确，=「本次机械核对 N 项，已知机械缺陷零漏网」。报告必须带覆盖率自述，否则比没有 lint 更伤信任。
2. **规则分三类**：可枚举客观规则（法条有效性、法定上限、时效、要式、管辖/仲裁形式）→ 编译；半客观一致性（金额、定义词、交叉引用、日期）→ 编译；主观裁量（赔偿上限接不接受、商业条款取舍）→ **永远不编译**，只升级。
3. **法条参数库是资产也是负债**：LPR 历史值、时效期间、上限比例须版本化 + 生效日 + 来源引用；错规则比没规则更糟，规则包验收须法律顾问参与（§8 人员）。

### 1.3 默认自动交付 + 例外升级 —— **修正接受**

评审假设「现在律师是必经闸门」，但仓库现状已经走了一半：

- 内部起草/审阅/渲染**默认直接出结果**（`requireSignoffReview` 默认关，草稿不进「待我拍板」）；
- 全产品**只有 `send_email` 硬暂停**（`platform/lawyer-outbound-decision.ts`：风险上限只拦真正发信）；
- 交付物已带风险分级（`DeliverableSpec.defaultRiskLevel`）、意图已带 `audience`——但都**没有绑定到交付策略**。

真正缺的不是「反转闸门」，而是四件具体的事：

1. **风险分级策略显式化**：`(风险级 × 受众 × 是否外发) → 自动交付 / 一键签批 / 完整审阅`，写进 `lawmind.policy.json`；
2. **渐进自主**：按「交付类 × 律师」解锁自动交付——必须同时满足 **一次通过率阈值 + lint 逃逸低于阈值 + 样本 ≥N**。只靠橡皮图章一次通过**不得**解锁。
3. **升级卡带推荐**：`LawMindRequiresAction` 今天只有问题（title/summary/args），没有**推荐结论 + 理由 + 一键采纳**；
4. **决策头延后**：顶部三行「改了什么 / 为什么 / 风险 / 可直接用」感知强、杠杆低，不占 Phase 0。

**边界（不接受的部分）**：对外发送（邮件、提交法院/客户的文书）**永远保留一键签批**。这不是技术保守，是执业责任——目标是把签批压缩到 30 秒（决策头 + 预检全绿），不是去掉签批。

### 1.4 立场库 / 先例库 —— **接受，捕获点已存在但没接线**

仓库现状是「多 sink 自由文本」：

- `LAWYER_PROFILE.md` §八 学习条目、`lawyer-preferences.json`（≤40 条可执行偏好，已注入系统提示）
- 条款 playbook 追加行（`playbook-learning.ts`，**不自动注入**，靠钉选/检索）
- 黄金范例整稿（`evaluation/golden.ts` → 召回注入）
- 合同修订包（`learning/contract-revision-pack.ts`，approve 时自动捕获 initial/final + KEY_MODIFICATIONS）
- 采纳队列已有 firm/lawyer scope（`memory/adoption-service.ts`），但 `firm.preference` **没有落盘 writer**

**关键发现**：最便宜的两个捕获点已经存在但没接学习——红线 accept/reject（`drafts/<taskId>.redline.json` 已有 before/after/rationale/status）和 review 标签（已接 profile，但未结构化为主题 × 立场 × 改法）。DOCX 修订回读（律师在 Word 里改完回流）价值最高但成本最高，延到 P3 后评估。

**冷启动**：只从 LawMind 内红线学习，Day-1 立场库是空的。**历史扫描是立场库与影子 benchmark 的冷启动**（WS0）：编目 + 知识入队在 Phase 0；≥5 次改法入待确认随 WS4 习惯层。

**裁决**：接受为 WS4（60 人天）。核心是**一个**结构化、带版本链、带采纳/驳回置信度、分 lawyer/firm 的立场存储；扫描习惯与红线 accept 共用同一队列，不静默写 profile。

### 1.5 自主迭代闭环 —— **接受**

现状印证：gate 大多「停下来问」而不是「修了再试」——craft signals 是软教练但不自动重跑；lint 类发现（如引用出处缺失）直接 block 导出；模型收到 coach 文案后是否真的修了，没有闭环验证。

**裁决**：接受为 WS2（50 人天）。设计要点：

- **有界**：默认 ≤3 轮自修订，继承工具预算检查点（W3 已落地的软预算续跑），每轮落审计；
- **残留分类**：机械缺陷自动修；主观裁量项**不碰**，聚合成一张「需你定夺」清单带推荐（接 WS3 的升级卡）；
- **诚实呈现**：UI 显示「已自检 2 轮，修掉 3 处机械问题」，不隐藏迭代过程。

### 1.6 法律 benchmark —— **接受，但黄金答案的第一来源是影子模式**

现状：benchmark 是 5 任务路由/关键词对齐（mock 模式 CI 绿）；质量快照是同源自洽启发式（citation ID ∈ 同轮 sources）；skills-golden 只测结构；12 个 replay fixture 是合成结构检查。**没有黄金答案、没有缺陷召回、没有 LLM 评审、没有人类校准**。

**裁决**：接受为 WS5（55 人天）。黄金语料第一来源是**已结案件影子重跑**；历史扫描编目为影子语料提供候选。合成植入缺陷用于评 WS1 召回。外部真实语料放最后。

### 1.7 决策导向输出 —— **接受方向，延后（高感知、低杠杆）**

`assessDeliverableReadiness` 已有 `summaryZh`，SelfCheck 已挂机械核对一行。决策头仍要做，但不占 Phase 0 人天——先把 lint 内核与历史扫描冷启动做实。

### 1.8 补充一条评审没说的：**飞轮闭环**

上述六点串起来的工程化机制是 **lint 逃逸率**：律师在交付后每改一处 = 一次 lint 逃逸 = 同时是 (a) 新 lint 规则候选 (b) benchmark 新案例 (c) 立场库新条目。这一个指标把「越用越像这位律师」从口号变成可度量的收敛过程。落入 WS6。

## 2. 目标架构与北极星

### 2.1 目标架构

```text
材料/指令
   │
   ▼
起草/改稿（现有管线，不动 execute）
   │
   ▼
法律编译器（WS1）──机械缺陷──► 自修订闭环（WS2，≤3 轮）──► 再编译
   │                                │
   │ 通过                            │ 残留=主观裁量
   ▼                                ▼
交付摘要（现有 SelfCheck + lint）   例外升级卡（WS3.3：推荐+理由+一键采纳；决策头后置）
   │
   ▼
分级交付（WS3.1/3.2）：内部低风险自动交付 · 外发一键签批 · 高风险完整审阅
   │
   ▼
律师动作（直接用 / 改一处 / 驳回）──► 立场库（WS4）+ lint 逃逸（WS6.2）+ benchmark 语料（WS5）
```

### 2.2 与既有硬约束的关系（不变）

- 硬门禁白名单不动：空交付、未签批外发、危险工具、网络/密钥/不可信围栏（见 CRAFT-REVIEW §3）。
- 第四铁律不动：判断类用 Skill/量规/软教练；本路线图的 lint 属**安全级客观规则**，与「关键词冒充质量」无关。
- 本地优先、审计采集、案件隔离不变。
- 核心工具 ≤12 不变；lint 经 `list_more_tools` 披露或走中间件自动触发。

### 2.3 规则三分类（WS1 的边界宪法）

| 类         | 例子                                                        | 处置                         |
| ---------- | ----------------------------------------------------------- | ---------------------------- |
| 客观可枚举 | 法条现行有效、4×LPR、定金 20%、或裁或诉、时效、要式、签章栏 | 编译；发现即报，可自动修     |
| 半客观一致 | 大小写金额、定义词、交叉引用、日期顺序、附件引用            | 编译；发现即报，多数可自动修 |
| 主观裁量   | 赔偿上限接不接受、管辖选哪边、商业让步                      | 永不编译；升级卡带推荐       |

## 6. 明确不做（防做歪）

- 不做云端 SaaS 化 / 客户卷宗上云；
- 不做外发全自动（`send_email` 与对外文书永远要人）；
- 不做主观裁量自动化（赔偿上限接不接受、商业条款取舍——只推荐，不决定）；
- 不做真源法宝/Lexis 联调（等凭证，既有阻塞项）；
- 不做通用法律问答扩面；
- 本轮不做 DOCX 修订回读（律师 Word 改单回流）；P3 后凭 WS4 数据再评估；
- 不动既有硬门禁白名单与核心工具 ≤12；
- 不为凑指标降低 benchmark 门槛。

## 7. 与既有债表的缝合

- 律师工作 OS 的 W4 长尾文书（客户更新、特权清单等）复用 WS1 规则包与 WS3 分级策略，不另起炉灶。

## 8. 人员、节奏与开工方式

- **配置**：2 名全职工程师 + 0.5 名法律顾问（规则包与黄金语料验收）≈ 12 个月；或 3 名工程师 ≈ 8–9 个月。法律顾问参与不是可选项——规则错了比没有规则更糟。
- **节奏**：每 Phase 末按 M 出口验收；每个 WS 收尾跑 `pnpm test` + `pnpm --filter lawmind-desktop typecheck` + 黄金路径 e2e；M2/M3 末各跑一次 `lawmind:desktop:e2e:pr` 全量。
- **开工**：已按重校准顺序开工（扫描编目 + lint 内核 + 参数库骨架 + 北极星）。后续 sprint：增量扫描 → 自修订闭环 → 买卖+借款族包 → 立场存储 → 影子 benchmark。勾选见 GOALS.md 第十四期。
- **口径**：本文件数字为规划估值，允许 ±20% 漂移；漂移超过时更新本文件并记一笔原因，不静默滑期。
