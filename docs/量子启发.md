# 量子启发：长稿为什么不会越写越错

这份说明给律师看。不讲线路、不讲比特。名字里的「量子」只是借用了一套记账办法：稿子里的关键事实单独记账，不靠模型自己记住自己刚写过的句子。

## 它解决的是哪一种错

模型写长文，是一句接一句往下写的。前面一句写错了，后面就会拿这句错的当前提，越写越圆，越圆越像真的。

常见的不是「法律观点写偏了」，而是这几件机械的事：

- 计算器算出来是 8.8 万元，稿子后半段写成了 9.9 万元，还据此往下算。
- 检索到的是演示材料，稿子却写成「现行有效」。
- 合同里定义的是「发包人」，后文冒出「承包人」，两套称谓并存。
- 修订没有真正写进 Word 的修订轨迹，系统却说「已经改好」。

观点、争点、结构，仍由模型写。上面这几类，由引擎记账，不让错句变成下一句的前提。

## 用一份劳动争议稿看它怎么做

律师说：被辞退员工月工资 1.5 万元，工作满 4 年，请算经济补偿，并写一份意见。

### 1. 先把能核对的事实记进一本小账

这本账不给律师看，也不靠对话历史保存。每一条只记一个「槽」和它的读法。

这一轮账上会有：

| 槽                     | 记下来的内容                    | 算不算已核实                         |
| ---------------------- | ------------------------------- | ------------------------------------ |
| 经济补偿               | 计算器算出 88000 元             | 已核实。工具算出来的                 |
| 月工资                 | 材料原句里的「1.5 万元」        | 已核实。律师自己写的，连原句一起留下 |
| 《劳动合同法》第 47 条 | 检索命中，并抄下一小段原文      | 已核实。原文对得上这条               |
| 当事人称谓             | 合同里写的是「发包人 / 承包人」 | 已核实。从合同定义里抽出             |

模型自己写的句子，默认**不算**已核实。写得再顺，也只是「提议」。

### 2. 模型照常写意见，引擎只对账，不改它的判断

模型写出：

> 建议主张违法解除，并要求继续履行。经济补偿金为 99999 元。根据《劳动合同法》第四十七条（权威来源、现行有效）……承包人应当……

律师关心的判断句——「建议主张违法解除」「要求继续履行」——整句留下。

引擎同时做四件核对，都是字符串比对，不再叫一次模型：

1. **金额。** 「经济补偿」这句里出现 99999，和账上的 88000 对不上。账上仍是 88000，99999 另记一笔「稿里写成了这个数」。不取平均，也不选看起来更顺的那个。
2. **引用。** 若这条法条来自演示语料，稿子却写成「权威来源 / 现行有效」，就记成冲突。法条名字可以留，假的「现行有效」不能当证据。
3. **称谓。** 合同没有定义「承包人」这个角色，稿子却当成确定当事人来写，记成未核实。
4. **修订轨迹。** 若导出报告说轨迹是空的，不能把「已改好」当成完成。

对不上的，稿子底下补一块给律师看的附注，判断句不动：

> 【机械核定】下面几项以引擎为准，上文判断仍保留。
>
> - 经济补偿：材料 / 计算器是 88000 元。稿里写成了 99999 元，仍以 88000 为准。
> - 引用：这条是演示语料，不能写成现行有效。
> - 称谓：承包人在本合同里没有定义，待核实。

### 3. 下一句不能再拿错数当前提

律师在界面里仍能看到原来那段话。但模型**下一轮真正读到的历史**会被改过：

- 「经济补偿」那一句里的 99999，换成 88000。别的句子里如果碰巧也有 99999，不动。
- 「权威来源 / 现行有效」从这条演示引用上拿掉。
- 每次开口前，末尾再附一段现算的清单：「经济补偿以 88000 为准；这条引用是演示语料；承包人待核实。」这段清单不进历史存档，压缩对话也不会把它弄丢，因为下一轮会重新画一遍。

所以模型不会接着写：「按 99999 元计算，再加利息应为……」。错数进得了律师看见的稿，进不了下一轮的前提。

### 4. 律师说「不对」，只撤回相关的那一处

律师打：「补偿金额不对」。

系统不是把整篇意见推倒重写。它只做三件小事：

1. 找到这句话点到的槽：经济补偿。
2. 连同和它直接绑在一起的槽（例如同一条里的月工资），组成一个小范围。范围外的，比如管辖、违约金，不动。
3. 如果这些字已经写进 Word，就按当时记下的反向替换改回去。当时是把「88000」改成「99999」，撤回就是把「99999」改回「88000」。同一词在文中出现多次、次数对不上，就不动，避免改到别处。

撤回最多试两次。仍对不齐，就只在这一处标「待核实」，其余保持，回合照常结束。不问律师要不要进入某种模式。

## 律师能感知到的，只有这几句话

| 你看到的         | 意思                                                   |
| ---------------- | ------------------------------------------------------ |
| 意见正文         | 模型写的判断，不因金额或引用冲突被整篇删掉             |
| 【机械核定】     | 金额、引用、称谓、修订轨迹以引擎为准，附在正文下面     |
| 【待核实】       | 有两种读法，或没有独立出处。不是禁写，是不要写成确定句 |
| 你说「不对」之后 | 相关那一处回到改之前；别的段落还在                     |

你不会在界面里看到「量子」「稳定子」「纯度」。那些词只留在内部设计说明里。

## 它查的只有这几类

| 查什么           | 怎么算对得上                                           | 对不上时                                                         |
| ---------------- | ------------------------------------------------------ | ---------------------------------------------------------------- |
| 金额             | 和计算器结果一致，或和律师材料里的原句一致             | 稿中的数留下，但标明以账上的数为准；下一轮模型看不到那个错数     |
| 引用             | 这条法条或案例确实在刚才的检索结果里，原文也对得上条号 | 不在来源里的，标待核实；演示材料写成「现行有效」的，拿掉这个说法 |
| 称谓和定义       | 用的角色词，合同里定义过，或是已有别名                 | 冒出来的角色词标待核实，不替你选「发包人」还是「承包人」         |
| 修订是否真的写上 | 导出检查说修订轨迹里有改动                             | 轨迹是空的，不能当成已经改完                                     |

定义互相打架时（同一圈称谓，定义原文不一致），只列出两侧，不选边。

## 它故意不查的

- 解除是否成立、管辖是否有利、论证是否有力。这些仍是模型的判断，可以改、可以删。
- 同一种意思的两种写法。只要指的是同一个已核实结果，不记成冲突。
- 还没检索之前，模型自己先拟的法条名称。那时不把「模型提到了一部法律」收成错误。

长稿后半段会漂，往往是因为从空白自由写。引擎会先收下已有标题或母版栏目，当作可改的提纲起点，一次只往上绑有限的新事实。提纲可以增删，不锁句子。

## 为什么叫量子启发

量子纠错里有一类辅助位：不存正文，只用来回答「这一组事实还一不一致」。读这个答案，不改写正文本身。

LawMind 用的就是这件事的普通计算机版本：

- 正文是模型写的。
- 账本是引擎的。关键事实以工具结果和律师材料为准。
- 每次写完做一次核对。全对，就继续写。有一处不对，只标这一处，并让下一轮看不见这个错前提。
- 交给律师之前，写进稿子的修改可以撤回。真正发出去、导出终稿、删除案件，才不能撤回。

没有量子计算机，也不在写稿过程中做量子计算。自回归生成还在：模型仍是从左往右写。变的是错句不再自动变成下一句的事实。

## 和「再提示它小心一点」的差别

在错的上文后面加一句「请注意金额」，模型仍站在错的上文上改。这套办法是在上文外面放一本模型改不动的账：下一轮开口前，错的机械事实已经从它的阅读材料里换掉，账上的数重新附在末尾。

判断怎么写，仍是它的事。数、法条出处、称谓、修订有没有真的落上，以账为准。

# 给设计者的下一页：现状复盘、下一层方向、测试取舍与同行对照

> 2026-10-19 写入。本页写给设计者与工程师，不是律师说明，前面正文的律师口吻不变。
> 2026-10-27 续：控制平面 v2 的现状审计、2025–2026 调研、来源根 / 译码器 / 弱测量方案见 [`LAWMIND-QUANTUM-CONTROL-PLANE.md`](./LAWMIND-QUANTUM-CONTROL-PLANE.md)。
> 科学边界仍以 [`LAWMIND-FORWARD-AGENT.md`](./LAWMIND-FORWARD-AGENT.md) §9 为准：不存相位、不跑线路、不声称加速。

## 一、复盘：这套「账本」现在什么已经是真的，什么还偏玩具

先对齐三个词，下文统一这么用：**锚**＝账上的一条关键事实（一个金额、一条法条、一个称谓）；**红灯**＝账上某项核对不通过；**稳定子**＝一组固定格式的核对项的内部名。

已经立住、要守住的：

- 不确定不写成确定。一个读数要证据足够集中（内部叫纯度 \(\gamma\ge0.75\)）才写成确定句，确认决定还要再叠一道保险（conformal 校准：保险出错率是事先在新案例上量出来的，不是拍脑袋定的），模型自己嘴硬也不升级结论。实现见 `src/lawmind/agent/factor-state.ts` 的 `projectReading` / `projectReadingGated`。这条是整栋楼的地基。
- 引擎账本和律师稿是两本测量。撤回是真可逆补丁（带反向替换），不是道歉式提示。
- `retrieval-amplify.ts` 诚实标注乘性权重「不是量子搜索、无平方加速」。

仍偏玩具、要替换的：

- 锚的提取大部分靠正则与硬编码关键词映射（`slotHint` 里 op 名到中文关键词的写死表）。工具换一种口径，表先碎。这正是「硬设置几个关键词」的残留。
- 因子图的边几乎没有自动建边通路。没有边，「1-hop 约化」等于全量转发，长程纠错名存实亡。
- 只有检测器，没有译码器：稳定子翻转后按 kind 走正则替换修复，丢掉了「该错误是否同时触发多条稳定子」这条最值钱的信息。

## 二、下一层的七个方向（全部落在对角态上，不破坏 §9）

1. **译码器：红灯亮了，先找「最少的笔误」。** 现在账上核对项（内部叫稳定子）翻红灯之后，是按出错类别套替换规则。要改成先回答「这组红灯最少是哪几处笔误造成的」，只重写这几处。这是量子纠错里译码（decoder）的一步，可借用并查集这类秒级算法。验收：两处核对项同时变红时，下一轮只修归因出来的那一处，不是按类别套两条规则。
2. **小声测很多次，凑成一次大声测（弱测量）。** 模型每轮写已核槽时，对「会写成什么数」的内在倾向（logits，或让它口头报把握度）本身就是一串微弱读数；同一个倾向连续几轮，才升级成一次红灯。单句措辞不再造成误报。口头报的把握度要先单独量过准头（再做一次保险校准）才准收。
3. **记性抽查（witness）。** 每次压缩或工具轮之后，用三五个固定小问题抽查模型还记不记得账上的读数。这一轮抽查掉线，就主动把账重注进上下文，不等下一次真的写错。今天的做法是出错之后靠验断顶住，这条把它变成量化的日常体检。已有论文证明这类抽查能提前预测「这回压缩会不会伤人」（见第六节 TRACE）。
4. **分支表决暂停进入产品。** 2026-10-19 决定：不以并行生成多稿、反复抽样择优作为默认纠错办法。多稿增加 token 和等待时间，同一模型还可能重复犯同一种错。此方向只保留为离线研究对照；须在相同总 token 预算下胜过单稿方案，且经单独批准，才重新讨论产品接入。
5. **律师修正史当校准数据。** 把记忆内核（`src/lawmind/memory/kernel/`、`lawyer-profile-learning.ts`）里记录的律师修正习惯，拿来校准三类账本参数：每类锚的起手把握度、每类错误的修复重试次数、按律师分层定保险门槛。是统计先验，不是关键词表。
6. **审稿模型改探针，不改裁判。** `reviewModel`（`src/lawmind/agent/turn-orchestrator.ts:393`）已接上，这一次改的是协议：审稿意见每条必须附原文片段并指向一个锚，走账本同一条入账通道；最终确认权仍在证据集中度加保险里。审稿模型的价值在抓正则抓不到的语义（比如合同定义的是「前置义务」这类角色关系），不在拍板。
7. **定义环守恒（最深的一条）。** 已有的定义环检查（`refreshDefinitionCycles`）升级成正式的账目守恒：环上别名关系逐边核对，算出来是奇数就翻红灯，多个环的重叠还指得出共用的错误。学术对应物是 LDPC 码的校验矩阵。它最依赖第 3 条和第 6 条攒下的红灯日志，所以放最后。

## 三、先选一个还是先测几个：三批测试计划

**结论：不单选。第一批测「只观测、不插手」的两个（方向 3 记性抽查 + 方向 6 审稿探针），它们只读不写，不接触生成，本身就是防退化最安全的起点。** 第二批是方向 5（记忆校准，吃第一批产出的数据）。译码器（1）与定义环守恒（7）是第三批：没有实测的红灯日志就做译码器，等于给译码器出一道没有训练集的题。

每批的测试设计固定为同一组消融臂（消融臂＝同一份任务、同一个模型，把机制一层层轮流关掉，看每层各自值多少分）：

- 臂 A：裸模型 + 最简循环，不接 LawMind 账本。这是防退化基线，永远保留。
- 臂 B：现状账本（S1–S4）。
- 臂 C/D：B 加当批新机制。
- 臂 E：全组合。

任务集用同一份：长稿任务若干 + 真客户稿（无夹具则诚实跳过）。指标固定四个：错数/错引用存活率（错前提进入下一轮的比例）、grounded 锚二次修正率、长稿后半段漂移率、律师可见【待核实】的误报密度（**无依据的警告不得增加**；真实缺源必须如实提示，不能靠隐瞒风险压低标注数量）。

## 四、防退化条款：模型越来越强时的边界

- **直通保证。** 任何机制关闭开关后必须回到臂 A 的形态；新机制上线前先跑消融证明「比 B 不差、比 A 不差，其中『比 A 不差』单独立项验收」。
- **自适应放宽。** 证据集中度门槛、保险门槛、抽查阈值、修复配额都从该模型在当前校准集上的错误率算出，不写死常数。模型变强 → 错误率下降 → 红灯触发频率与检查频次自动跟着降，引擎成本自动降。机制只应该按需存在，不该按惯性存在。
- **模型只提出，引擎处置。** 第五节提到的社区口号「the LLM proposes, deterministic guards dispose」收为这里的一句拍板：模型的信号（概率、口头把握度、审稿意见）一律作为读数进入账本通道，处置决策全部在确定性引擎侧。这保证换更强模型时只改善采样质量，不会反过来让账本压过模型——账本的每个读数都标成本，超过就把对应机制降级到只读。
- **替换硬编码。** `slotHint` 这类写死的 op→关键词映射由方向 5 的统计先验与方向 2 的弱测量替换，不再作为第一道防线。

## 五、DeepSeek Harness 和 Codex 是怎么解决同一批问题的

**Codex（GPT-5.1-Codex-Max，2025-11 起）。** 主打一个动作：压缩（compaction）。上下文将满时，把旧行为总结成高保真摘要继续干，模型**原生训练过压缩后作业**，可连续数小时、跨多次压缩完成长任务，SWE-bench 提升明显。它把一致性押在「模型权重被厂商训过」上：harness 少管状态，赌模型自己抗漂移。对我们的含义：这条路线随官方模型变强自动变好，但换模型即失效；LawMind 押的是「态在引擎」，模型无关，任何模型可接。两者不冲突——模型越强，红灯触发越少，引擎的开销自动让位，这就是第四节「自适应放宽」的又一层含义。

**DeepSeek Harness（开源 `deepseek-ai/deepseek-harness`，MIT，2026-08 起）。** 一切皆插件，底层是 Cordis 元框架，配套论文《A Programming Paradigm for Spatiotemporal Composability》（arXiv:2608.25512）。与本仓库设计逐条对得上的暗合：

| 他们                                                         | LawMind 对应物                                        |
| ------------------------------------------------------------ | ----------------------------------------------------- |
| 可逆效应：每个上下文变换自带逆变换，卸载即回卷               | 可逆直到测量；光锥撤销、`inverseEdits`                |
| 会话日志 append-only，「model-visible means logged」         | 「模型可见 ≠ 态本身」：账本是日志的投影，不是历史本身 |
| 投影刻面（session projection，`stateOf()` 增量折叠）         | factor-state 就是回合投影的解释：同一思想，更少的层   |
| 子代理单接口（`ctx.subagents`）                              | 约化子工：子工只带本任务的边际                        |
| 审批刻面 fail-closed（`ctx.approval`）                       | 外发即测量；一次性放行默认拒绝                        |
| 社区插件 `dsh-argp`：LLM 提出、确定性守门处置 + 台账逐字回放 | 方向 3/5 的同族做法：压缩前抓逐字胶囊、压缩后注回     |

另记：Claude Code 一系把长期记忆放在文件系统（项目记忆文件 + 子代理），状态在文件不在上下文——与「1-hop 约化」同族但更粗。

**同行没有做的三件事，就是本仓库的先发空间**：账本红灯谱系的记录、红灯译码器、小声测量累积。Codex 押模型权重，DeepSeek Harness 押插件可逆性，两家都没有把「错误校正」做成一个**被测量、被校准、可消融**的第一等对象。第三节的三批测试，就是把这个空间变成可验收的实验，而不是再加几个量子名词。

## 六、最新论文与研究方法的方法采位（信息口径：2026-10-19 检索）

> 本节是第三节三批测试和后续工程选型的采位表。每条只写三件事：他们怎么做的（大白话）、LawMind 取用哪一块、归入哪一批测试。

### 压缩这条线

- **CompactionRL（arXiv:2607.05378，2026-07）**。把「压缩后接着干活」直接训进模型：任务执行和写摘要一起上强化学习，压缩线本身成为训练对象，已并入开源 GLM-5.2 的训练管线。取用点：模型厂商在把摘要质量当成被优化的对象，引擎侧不必重复训练，要跟上的是第四节的自适应放宽；GLM 系恰是本机常接的模型。→ 服务第四节的参数自算。
- **Prune the Summary, Not the History（2026-10）**。压缩伤人的主因是动了历史、只留总结；主张按出处裁剪总结，原文永远作为可回源的档案保留。我们的压缩层「可回源归档 + 任务重注」正走在这条上。→ 给它配测量端的是方向 3（第一批）。
- **ACON（ICML 2026）**。训一个「这笔留还是丢」的小决策器，按下游需要选择性压缩。取用点：丢不丢不由固定比例决定，由「下游还要不要用」决定——约化子工就是同样的按需留取。→ 复用现有约化，不新增机制。
- **Pack Light, Carry On（2026-08）**。把上下文组织成一个个自带动作说明的对象包（这份材料是什么、还能对它做什么），不是流水账。→ 与账本「每个读数带锚、带动作」同形，作为账本渲染格式的参照。
- **CCP Lab（Context Compaction Provenance，SSRN）**。把压缩当成一条信任边界来量：统计「不可信文本经压缩混进可信状态」的比例，并证明带确定性防火墙的压缩可把该指标测到零。取用点：账本的 sampling 投影（错句不进下一轮前提）同属信任边界。→ 新增为消融臂的第五个验收指标（第一批就可以量）。
- **TRACE 配对回放（2026-09）**。用会话历史预判「这回压缩会不会伤」。→ 方向 3 记性抽查的先导形态：先预测、再重注，不等出错。

### 校验这条线

- **Verification Independence（SSRN，2026）**。核心一句：多一个评审员不等于多一个独立的判断依据。它把独立性拆成四个维度（框定、证据、机制、权限），要求生产者、挑战者、证据核查、放行者四个角色分离。取用点：直接约束方向 6——审稿探针必须在**机制**上独立（必须带原文证据、独立执行、无权放行），只换个模型的「独立」不算独立；同时正面支持「模型只提出，引擎处置」。→ 第一批。

### 记忆这条线

- **Persistent Memory … Grows by Duplication（SSRN，所谓「二次压缩」）**。长期记忆文件因重复追加而膨胀，整篇注回挤占窗口，反噬压缩本身——第一类丢失的解药造成第二类丢失。取用点：对律师习惯记忆库的硬约束——必须配去重与撤回（memory/kernel 的 `consolidate` 与 `retract-projection` 正是这两味药），并新增「记忆重复率」指标。→ 第二批。
- **Does Memory Credit Travel?（SSRN）**。给记忆功效记账，发现绝大多数「记忆帮上忙」是搭便车——碰巧命中而已，不是边际贡献。取用点：方向 5 的记忆校准评测必须用边际贡献口径（同一任务开/关记忆对照），不能按命中次数记功。→ 第二批。
- **From Storage to Experience（综述）与 MemoryArena 一类基准**。记忆评测的风向从「存了什么」转向「用过之后变好没有」，并出现逐经验再巩固（reconsolidation）路线。取用点：memory/kernel 的 adoption 流程方向一致，缺的是效果测量，与上一条合并成同一份评测集。→ 第二批。

### 框架与工程生态

- DeepSeek Harness 的社区插件（`dsh-argp` 守门压缩、`dsh-ledger-memory` 台账注回）已经把方向 3/5 的同族做法商品化，说明这条路不缺先例，缺的是校准与评测——先发空间仍在第五节结尾那三件事上。
- Codex 之外，主流 agent 的记忆现状（如 Claude Code 的文件式记忆）仍是「存了就整篇注回」，没有第四节的自适应放宽机制。

**这批研究共同背书、而第三、四节已经写死的一句话**：压缩和记忆都应当被测量，而不是被信任；校验要靠机制独立，而不是靠评审员多。以后每次选型和改工程，先对着第六节这张表过一遍，再进第三节的三批测试。

## 八、2026-10-19 补充：先修证据传递，不靠多写稿提高分数

本次实现范围是检索状态与评测可信性，尚未证明法律答题质量提高。

- **区分状态。** 配好了法宝、HTTP 连通、有内容返回、正常无命中、积分不足、限流与其他异常分别记录。普通查询零命中不等于欠费；旧日志只记 `livePkulaw` 或 `ok/error` 的，不能事后认定全部健康或全部欠费，也不能仅凭 `rev3` 分数较高认定它是干净基准。
- **状态传到模型。** `projectToolResultForSampling` 会删掉重复检索数组。本次确保它和历史截断都保留服务状态字段，防止程序知道失败而模型只看见空结果；这不需要增加一次模型调用。
- **评测和产品分开。** 评测前实际查询法条与案例两个接口；控制查询没有可用命中时暂停，原因记“未验证”而不是猜测欠费。中途服务异常排除该题并停止后续跑批；普通空结果不直接算故障，全部为空时再做控制查询。原稿、评分原文、逐调用状态各轮独立保存。产品仍允许分析、整理和起草，只如实说明缺少核实来源的引用，不以检索故障禁止交件。

后续低消耗方案先做实验，不在本次接入：

1. 先用已核实的请求体、来源片段和稿件定位信息在哪一步丢失。检索没拿到、拿到但被截断、送到了却没使用，是三种不同问题，不能统称模型不够认真。
2. 优先复用已有争点和证据记录，把下一步需要的原文与未解决事项送入正常的下一次调用；不另开一轮问答抽查，不全篇重注，也不把查到次数当作证据充分程度。金额和明确条文的机械错误可以确定性核对；论证完整性仍须语义评测，不能用关键词检查宣称已解决。
3. 这 39 题只用于查错，不充当唯一验收集。保留未参与设计的不同业务、短问答和真实长稿任务，分层比较正确性、误报、拒答、律师修改量、总 token 与耗时。相同预算比较，失败和零分都保留；未有完整稿件及服务记录的历史轮不用于因果结论。

律师可见的无依据警告应减少，真实风险提示必须保留；不能为了让“待核实”更少而隐瞒缺源。新机制的好用程度需要盲评和实际修改量验证，不能仅凭警告数量或这一小批题的平均分承诺。
